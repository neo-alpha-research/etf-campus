## 2. 2-4 제안은 채택하지 않습니다

동적 fetch 방식(`Contents: Read` 권한 추가)을 권장하셨으나 반대합니다. 이유는 두 가지입니다.

**첫째, 런타임 의존을 다시 만듭니다.** 이 Worker를 만든 이유는 GitHub Actions가 한도 초과로 멈추자 감시 장치까지 함께 죽었기 때문입니다. 판정의 핵심 근거인 휴장일 목록을 GitHub API 실시간 호출로 가져오면, GitHub 쪽 장애나 토큰 만료 시 감시 장치가 판정 자체를 못 하게 됩니다. 제거하려던 결합을 다른 형태로 되살리는 것입니다.

현재 Worker는 GitHub API를 **알림 전달**에만 씁니다. 판정은 로컬 데이터로 합니다. 이 분리를 유지해야 GitHub이 죽어도 최소한 로그에는 문제가 기록됩니다.

**둘째, 권한이 과합니다.** private 저장소에 `Contents: Read`를 부여하면 Issue 생성만 하면 되는 토큰이 저장소 전체를 읽을 수 있게 됩니다. 토큰이 유출되면 피해 범위가 완전히 달라집니다. 최소 권한 원칙에 어긋납니다.

## 3. 확정 방식: 공개 사본 게시와 정합 검사 분리

저장소를 확인한 결과 **`public/` 디렉터리가 있고 그 아래 `public/data/`도 이미 존재합니다.** Next.js가 `public/`을 정적 자산으로 서빙하므로 인증 없이 접근 가능한 경로를 만들 수 있습니다.

아래 구조로 구현하십시오.

### 3-1. 휴장일 파일을 공개 경로에 게시하십시오

빌드 시점에 `data/market_holidays.txt`를 `public/data/market_holidays.txt`로 복사하는 단계를 `package.json`의 빌드 스크립트에 추가하십시오.

이렇게 하면 `https://etf-campus.pages.dev/data/market_holidays.txt`로 인증 없이 최신 목록에 접근할 수 있습니다. Cloudflare Pages가 저장소를 감시하므로 원본이 갱신되면 다음 빌드에서 자동으로 반영됩니다. 데이터 커밋이 매 거래일 발생하므로 갱신 지연은 사실상 없습니다.

### 3-2. 판정은 계속 번들 사본으로 하십시오

Worker의 휴장일 판정은 지금처럼 `src/market_holidays.txt` 번들 사본을 사용하십시오. **판정 근거를 네트워크에 의존시키지 마십시오.**

### 3-3. 공개 사본은 정합 검사에만 쓰십시오

Worker가 실행될 때 공개 경로의 파일을 가져와 번들 사본과 내용을 비교하십시오.

다르면 **휴장일 목록 불일치를 알리는 Issue를 생성하십시오.** 제목과 라벨은 기존 감시 Issue와 구분되게 두십시오. 예를 들어 `휴장일 목록 동기화 필요`와 `market-daily-monitor` 라벨입니다.

가져오기에 실패하면 로그에 남기되 판정은 계속 진행하십시오. 정합 검사 실패가 감시 기능 자체를 멈추게 해서는 안 됩니다.

**이 구조의 이점은 명확합니다.** 판정은 네트워크와 무관하게 항상 동작하고, 사본이 어긋나면 조용히 방치되지 않고 Issue로 드러나며, 토큰 권한은 `Issues: Read and write` 그대로입니다.

### 3-4. 부수 효과 확인

`public/data/`에 파일을 추가하면 정적 사이트에 새 경로가 생깁니다. 다음을 확인해 보고하십시오.

`public/_routes.json`이 존재하는데, 새 경로가 이 설정에 영향을 받는지 확인하십시오.

빌드 산출물 크기나 배포에 문제가 없는지 확인하십시오. 휴장일 파일은 작으므로 문제될 가능성은 낮습니다.

기존 `public/data/returns/` 디렉터리의 용도를 확인하고, 같은 위치에 파일을 두는 것이 적절한지 판단하십시오. 부적절하면 다른 경로를 제안하십시오.

## 4. README 경고문 유지

이미 추가하신 경고문은 그대로 두십시오. 3번 구조가 적용되어도 재배포가 필요한 상황은 남습니다. 다만 문구를 다음 취지로 보완하십시오.

번들 사본은 판정에 쓰이며 원본이 바뀌면 재배포가 필요하고, 재배포를 잊으면 Worker가 자동으로 불일치 Issue를 생성한다는 내용입니다. 운영자가 경고를 봤을 때 무엇이 자동이고 무엇이 수동인지 알 수 있어야 합니다.
