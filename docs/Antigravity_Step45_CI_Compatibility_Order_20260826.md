## 2. 보류 목록이 실제로는 기록되지 않습니다

### 2-1. 세 가지가 겹쳐 있습니다

발신 측에서 코드와 워크플로를 직접 확인한 결과입니다.

**첫째, `npx.cmd` 는 윈도우 전용입니다.**

```python
"npx.cmd", "wrangler", "d1", "execute", "etf-prices", "--json",
```

**GitHub Actions 는 `ubuntu-latest` 에서 돕니다.** 리눅스에는 `npx.cmd` 가 없습니다. 명령이 통째로 실패합니다.

**둘째, `--remote` 가 빠져 있습니다.**

`--remote` 없이 실행하면 로컬 miniflare 상태에 씁니다. **CI 러너의 로컬 상태는 실행이 끝나면 사라집니다.**

앞서 `--remote` 로 프로덕션에 `etf_pending_isins` 테이블을 만드셨지만, **거기에 기록할 코드 경로가 없습니다.**

**셋째, `check=False` 로 실패가 삼켜집니다.**

```python
subprocess.run(cmd, capture_output=True, check=False)
```

**wrangler 가 없거나 인증이 실패해도 아무 일 없이 넘어갑니다.** 이번 세션에서 반복적으로 지적한 조용한 실패입니다.

**넷째, `daily-market.yml` 에 Cloudflare 자격증명이 없습니다.** `CLOUDFLARE` 나 `wrangler` 문자열이 0건입니다. `--remote` 를 붙여도 인증이 되지 않습니다.

### 2-2. 결과

**보류 목록은 로컬에서만 동작하고 CI 에서는 아무것도 하지 않습니다.** 그리고 실패해도 로그에 남지 않습니다.

**즉 신규 종목이 ISIN 을 못 받아 스킵되어도 아무도 모르게 됩니다.** 이 장치를 만든 목적과 정반대입니다.

## 3. 설계를 바꾸십시오

### 3-1. D1 대신 파일로 남기십시오

**수집 스크립트가 데이터베이스에 직접 쓰는 구조는 이 파이프라인의 설계와 어긋납니다.**

기존 구조는 **스크립트가 CSV 를 만들고, 별도의 서명된 인제스션이 D1 에 적재**하는 것입니다. 수집 스크립트에서 wrangler 를 부르면 CI 자격증명 의존이 생기고 플랫폼 차이에 취약해집니다.

**`data/pending_isins.json` 같은 파일로 남기십시오.**

```json
[
  {"ticker": "0226D0", "name": "...", "discovered_at": "2026-08-25", "attempts": 3}
]
```

**장점이 명확합니다.** CI 자격증명이 필요 없고, 플랫폼 차이가 없으며, 다른 데이터 파일과 함께 커밋되므로 **이력이 남아 언제부터 보류되었는지 추적됩니다.**

**D1 의 `etf_pending_isins` 테이블은 삭제하지 말고 그대로 두십시오.** 나중에 관리 화면에서 쓸 수 있습니다. 다만 지금은 쓰지 않습니다.

### 3-2. 실패를 드러내십시오

**보류 목록 기록에 실패하면 예외로 종료하거나 최소한 명확한 오류를 출력하십시오.** `check=False` 로 삼키지 마십시오.

**실행 종료 요약에 보류 종목 수와 목록을 반드시 출력하십시오.** 0건이면 0건이라고 적으십시오.

**5거래일 초과 경고는 그대로 유지하되 파이프라인을 중단시키지는 마십시오.**

### 3-3. 크로스 플랫폼

**앞으로 파이프라인 코드에 `npx.cmd`, `.cmd`, `.exe` 같은 윈도우 전용 표기를 쓰지 마십시오.** 워크플로는 리눅스에서 돕니다.

**로컬에서 동작한다는 것이 CI 에서 동작한다는 뜻이 아닙니다.** 파이프라인에 들어가는 코드는 리눅스 기준으로 작성하십시오.

**같은 패턴이 다른 스크립트에도 있는지 전수 검색해 보고하십시오.**

## 4. 카탈로그가 자기모순 상태입니다

**2-1 절은 갱신되었으나 1절 요약표가 그대로입니다.**

```
1절  | ETF 일별시세      | 공공데이터포털 15094806 | 정상       |
1절  | ETF 일별시세 폴백 | KRX Open API            | 예외 시에만 |

2-1절 | 1순위      | KRX
2-1절 | 2순위(폴백) | 금융위원회
```

**한 문서 안에서 정반대로 적혀 있습니다.**

**1절 표를 2-1 절에 맞춰 뒤집으십시오.** 라이선스 열도 함께 조정해야 합니다. KRX 가 1순위가 되었으므로 **비상업 제한이 상시 노출 상태**임을 표에 드러내야 합니다.

**2-6 절 157행도 갱신하십시오.** "FSC 응답의 `stLstgCnt` 를 `shares` 로 파싱" 이라고 되어 있는데, 이제 KRX 의 `LIST_SHRS` 가 주 경로입니다. 두 출처가 같은 값을 준다는 사실과 함께 적으십시오.

**갱신 후 문서 전체를 훑어 1절과 2절이 어긋나는 곳이 더 없는지 확인하십시오.** 출처 우선순위를 뒤집었으므로 여러 곳에 영향이 갑니다.

## 5. 프로세스 두 가지

### 5-1. `git add .` 를 쓰셨습니다

이번 커밋에 다음이 포함되었습니다.

```
data/etf_master_draft.csv
data/etf_returns_draft.csv
data/pension_verify_sheet.csv
docs/Data_Catalog.md
scripts/update_daily_data.py
```

**데이터 CSV 세 개가 의도한 것인지 확인하십시오.** 이번에는 내용이 맞으므로 되돌릴 필요는 없습니다.

**다만 `git add .` 는 쓰지 마십시오.** 대상 파일을 명시적으로 스테이징하십시오. 의도하지 않은 파일이 섞여도 알 수 없습니다.

### 5-2. 마스터 CSV 를 손으로 편집해 시험 조건을 만드셨습니다

```python
new_tickers = ['0226D0', '0231Z0', '0232A0', '0232B0', '0245E0', '0245F0']
for r in rows:
    if r['ticker'] in new_tickers:
        r['isin_cd'] = ''
```

**보고에 이 사실이 없습니다.**

그리고 이 목록은 앞서 확인된 신규 6종목(`0226D0`, `0227K0`, `0228G0`, `0231Z0`, `0233A0`, `0233J0`)과 **다릅니다.** 기존에 정상 ISIN 을 갖고 있던 종목의 값을 지우고 시험하신 것으로 보입니다.

**결과적으로 전부 복구되었으므로 손상은 없습니다.** 확인했습니다.

**다만 데이터를 손으로 고쳐 시험 조건을 만들면 보고하십시오.** 복구가 실패했다면 조용히 빈 값이 남았을 것입니다.

**시험 조건이 필요하면 `scratch/` 에 사본을 만들어 쓰십시오.**

## 8. 작업 규칙

**파이프라인 코드는 리눅스에서 동작해야 합니다.** 윈도우 전용 표기를 쓰지 마십시오. 로컬에서 되는 것과 CI 에서 되는 것은 다릅니다.

**`subprocess.run` 에 `check=False` 를 쓰고 결과를 확인하지 않는 코드를 만들지 마십시오.**

**수집 스크립트에서 데이터베이스에 직접 쓰지 마십시오.** 파일로 남기고 별도 경로가 적재합니다.

**데이터를 손으로 고쳐 시험 조건을 만들면 보고하십시오.** 가능하면 `scratch/` 사본으로 하십시오.

**`git add .` 를 쓰지 마십시오.** 대상 파일을 명시적으로 스테이징하십시오.

**문서를 갱신할 때는 같은 내용을 언급하는 다른 절도 함께 확인하십시오.** 한 곳만 고치면 문서가 자기모순에 빠집니다.

**로그 문구가 실제 동작을 보장하지 않습니다.**

**API 경로와 파라미터 이름을 추정하지 마십시오. 식별자를 추정으로 생성하지 마십시오.**

**`git reset --hard`, force push, 프로덕션 데이터베이스 쓰기는 사전 승인 대상입니다.**

**명령을 `;` 로 연결하지 마십시오.**

**스크립트 실행 후 `git status` 로 작업 트리 오염을 확인하십시오.**

**`dev` 브랜치에서 작업하고 `main` 머지는 승인을 받으십시오.**

**결론은 제시한 데이터로 뒷받침되어야 합니다.**

**스크립트는 `scratch/` 안에 파일로 만들어 실행하십시오.**

**조용한 실패를 만들지 마십시오.**

기존 파일을 통째로 다시 쓰지 말고 증분 편집만 하십시오.

`docs/Data_Catalog.md` 는 커밋 대상이고 `Antigravity_Step*.md` 는 커밋하지 마십시오.

PowerShell 의 `>>` 와 `Out-File` 로 파일을 만들거나 수정하지 마십시오.

보고 전에 `git status --porcelain` 과 `git log --oneline -n 5`, `git rev-parse --abbrev-ref HEAD` 를 실행해 출력을 붙여넣으십시오.
