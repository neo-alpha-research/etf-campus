## 0. 이번 라운드의 목적

**마켓 브리핑 STEP 1~6 이 매일 자동으로 채워지는 상태를 만드는 것이 유일한 목표입니다.**

저장소가 현재 Public 이라 Actions 제한이 없습니다. **이 창이 열려 있는 동안 끝내야 합니다.** 끝나면 운영자가 Private 로 되돌립니다.

**이번 라운드는 조사가 아니라 실행입니다.** 아래 순서대로 진행하고, 막히는 지점에서만 멈추십시오.

**범위 밖 작업을 하지 마십시오.** 라이선스 정리, 시간대별 측정, 지수 출처 전환, 펀드상품기본정보는 전부 보류합니다. 유료화 이전 과제로 미뤘습니다.

## 1. 작업 A: 보류 목록 CI 호환 수정 (짧게)

직전 지시의 미완 항목입니다. **간단히 끝내고 넘어가십시오.**

`update_daily_data.py` 의 보류 목록 기록을 **`data/pending_isins.json` 파일 기반으로 바꾸십시오.**

```json
[{"ticker": "0226D0", "name": "...", "discovered_at": "2026-08-25", "attempts": 3}]
```

**`npx.cmd`, `subprocess`, `wrangler` 호출을 전부 제거하십시오.** 리눅스에서 동작하지 않고 CI 자격증명도 없습니다.

**실행 종료 요약에 보류 종목 수를 출력하십시오.** 0건이면 "보류 0건"이라고 적으십시오.

**5거래일 초과 시 경고만 출력하고 파이프라인을 중단시키지 마십시오.**

파이프라인 코드 전체에서 `npx.cmd`, `.cmd`, `.exe` 표기를 검색해 남은 것이 있으면 함께 제거하십시오.

## 2. 작업 B: 카탈로그 정합 (짧게)

`docs/Data_Catalog.md` 1절 요약표가 2-1 절과 정반대입니다.

**1절 표의 ETF 일별시세 두 행을 뒤집으십시오.** KRX 가 1순위, 공공데이터포털이 폴백입니다. **라이선스 열에 KRX 의 비상업 제한이 상시 노출 상태임이 드러나야 합니다.**

2-6 절 157행의 "FSC 응답의 `stLstgCnt` 를 `shares` 로 파싱" 서술도 갱신하십시오. 이제 KRX 의 `LIST_SHRS` 가 주 경로이며 두 출처가 같은 값을 줍니다.

**긴 설명을 쓰지 마십시오. 사실만 고치고 넘어가십시오.**

## 4. 작업 D: 8월 24일 재수집

**STEP 4·5 자금 순유입이 나오려면 연속된 두 거래일에 NAV 가 있어야 합니다.**

현재 상태입니다.

```
2026-08-21  NAV 있음 (다만 50건이 출처 불명 값으로 덮여 있음)
2026-08-24  NAV 없음
2026-08-25  NAV 있음 (이번에 채움)
```

**8월 25일의 직전 거래일은 8월 24일입니다.** 24일에 NAV 가 없으므로 순유입이 계산되지 않습니다.

**`daily-market.yml` 을 `target=20260824` 로 수동 실행하십시오.**

```
gh workflow run daily-market.yml -f target=20260824
gh run watch
```

실행 후 확인할 것입니다.

**수집 출처**가 `KRX Open API` 인지입니다.

**건수**가 1,161건 안팎인지입니다.

**D1 의 NAV 채워짐**입니다.

```
SELECT as_of_date, COUNT(*), COUNT(nav_value) FROM briefing_etf_daily
WHERE as_of_date IN ('2026-08-21','2026-08-24','2026-08-25')
GROUP BY as_of_date ORDER BY as_of_date;
```

**세 날짜 모두 `nav_value` 가 전체 건수와 같아야 합니다.**

**주의**: 이 실행은 워크플로가 마스터 CSV 를 8월 24일 상태로 커밋할 수 있습니다. **커밋 후 `bas_dt` 분포를 확인하고, 8월 24일로 되돌아갔으면 즉시 보고하십시오.** 그 경우 8월 25일로 다시 수집해 복구해야 합니다.
