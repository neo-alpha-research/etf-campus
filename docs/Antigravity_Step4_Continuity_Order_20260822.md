## 1. 검증 결과: 보고와 저장소 상태가 다릅니다

### 1-1. 크론 분산 수정이 커밋되지 않았습니다

저장소 확인 결과 `daily-market.yml`과 `daily-distribution.yml`이 여전히 커밋되지 않은 수정 상태(`M`)로 작업 트리에만 존재합니다.

지난 라운드에 `git diff --stat` 출력을 근거로 "조치 완료"를 보고하셨습니다. 그러나 `git diff --stat`은 **커밋되지 않은 작업 트리 변경도 그대로 출력합니다.** 완료의 증거가 되지 못합니다.

**취소 문제 수정은 아직 반영되지 않은 상태입니다.** 즉시 커밋하고 푸시하십시오.

앞으로 완료 보고에는 `git diff --stat`이 아니라 **`git log --oneline -n N`과 `git status --porcelain` 출력을 함께** 넣으십시오. 커밋되었는지와 작업 트리가 깨끗한지를 동시에 보여야 합니다.

### 1-2. 잔재 파일이 또 남았습니다

`jobs.json`이 작업 트리에 남아 있습니다. `runs.json`, `test.json`, `fails.txt`는 정리하셨는데 이것만 빠졌습니다. `temp.json`, `latest.js.tmp`, `scratch/*.cjs`에 이어 네 번째입니다.

`.gitignore`에 `scratch/`를 추가한 것은 좋은 조치였습니다. 같은 방식으로 `*.json` 분석 산출물이 루트에 생기지 않도록, 앞으로 모든 임시 산출물을 `scratch/` 안에서만 만드십시오. 루트에 직접 파일을 쓰지 마십시오.

### 1-3. 채택하는 부분

`ci-fast.yml`과 `ci-full.yml` 두 파일은 확인했습니다. BOM 없이 UTF-8로 저장되었고, 계층 분리와 `cancel-in-progress` 설정, 배포 토큰 미주입, `contents: read` 권한 한정 모두 지시대로입니다. `.gitignore`의 `scratch/` 추가도 확인했습니다.

인코딩 문제를 인지하고 base64 경유로 파일을 생성한 처리도 적절했습니다.

## 2. 우선순위 변경: 데이터 수집 복구가 먼저입니다

보고에서 확인된 다음 사실이 나머지보다 중요합니다.

> 현재 사용자 계정의 무료 한도 2,000분이 완전히 고갈되어 락이 걸린 상태입니다.

이는 CI를 테스트할 수 없다는 의미에 그치지 않습니다. **일일 데이터 수집 워크플로도 함께 멈췄다는 뜻입니다.** 다음 결제 주기까지 약 10일간 ETF 시세와 브리핑 데이터가 갱신되지 않습니다. 개발 불편이 아니라 서비스 중단입니다.

D1 잠금 작업으로 넘어가기 전에 이것부터 해결합니다.

### 2-1. 즉시 조사할 것 (읽기 전용, 최우선)

**첫째, Cloudflare Pages의 Git 연동 여부를 확인하십시오.**

현재 `market-briefing-production.yml`이 `wrangler pages deploy out`으로 사이트를 배포합니다. 이는 Pages가 GitHub 저장소와 직접 연동되어 있지 않을 가능성을 시사합니다.

Cloudflare 대시보드 또는 API로 `etf-campus` Pages 프로젝트의 소스 설정을 확인하고, Git 연동이 되어 있는지, 되어 있다면 어느 브랜치를 감시하는지 보고하십시오.

**이것이 중요한 이유는, Git 연동이 되어 있으면 사이트 갱신에 Actions가 전혀 필요 없기 때문입니다.** 데이터 수집만 다른 경로로 돌리면 Actions 없이도 서비스가 정상 동작합니다.

**둘째, 한도 초기화 시점을 확인하십시오.** GitHub 결제 화면에서 다음 주기 시작일이 언제인지 확인해 보고하십시오.

**셋째, 초과 사용 단가와 지출 한도 설정 가능 여부를 확인하십시오.** GitHub Free 개인 계정에서 지출 한도를 0이 아닌 값으로 설정하면 즉시 Actions가 다시 동작합니다. Linux 러너의 분당 단가와 설정 경로를 확인해 보고하십시오. 설정 자체는 운영자가 직접 수행할 사안이므로 당신은 조건만 확인하십시오.

### 2-2. 데이터 수집 임시 이전 준비

조사와 병행해 **정부 지원 서버에서 일일 수집을 돌릴 수 있도록 준비하십시오.**

이 작업은 원래 서버 이용 기간 연장 확인 후로 미뤄 두었으나, Actions가 잠긴 지금은 상황이 다릅니다. 수집은 상태를 갖지 않는 배치 작업이고, 서버가 회수되어도 Actions가 되살아나면 그대로 복귀할 수 있습니다. 서버를 쓰기에 가장 적합한 사례입니다.

준비할 것은 다음과 같습니다.

`daily-market.yml`이 수행하는 절차 중 **외부 API 수집과 CSV 갱신, Git 커밋까지**를 셸 스크립트 하나로 재현할 수 있는지 검토하고, 필요한 환경변수와 시크릿 목록을 정리하십시오. 빌드와 배포는 포함하지 마십시오.

이 스크립트는 GitHub Actions 워크플로를 대체하는 것이 아니라 **동일한 결과를 내는 두 번째 경로**입니다. 워크플로 파일은 그대로 두십시오.

실제 서버 설치와 실행은 별도 지시로 진행합니다. 이번에는 스크립트 초안과 필요 시크릿 목록까지만 준비해 보고하십시오.

## 3. 다음 작업: D1 잠금 해결

위 조사와 준비를 마친 뒤 진행합니다. 이 작업은 코드 수정과 마이그레이션이며 `wrangler`를 로컬에서 실행할 수 있으므로 **Actions 잠금과 무관하게 진행 가능합니다.**

`market_data_readiness`와 `market_source_consumer_runs`에 남는 `processing` 및 `skipped_duplicate` 잠금이 다음 파이프라인을 영구히 무시하게 만드는 문제입니다. Backfill 워크플로가 이번 달 34회 실행된 원인이기도 합니다.

D1 마이그레이션 `0009`로 아래를 구현하십시오.

**첫째, 임대 시간을 부여하십시오.** 상태 레코드에 `locked_at` 컬럼을 추가하고 `processing` 진입 시각을 기록합니다. 조회 시 현재 시각과의 차이가 30분을 넘으면 잠금이 만료된 것으로 간주해 자동 회수하고 재처리 가능 상태로 되돌립니다. 임계치는 환경변수로 조정 가능하게 두십시오.

**둘째, 멱등 재처리를 보장하십시오.** `skipped_duplicate`가 남은 상태에서 같은 기준일을 다시 처리할 때 안전하게 통과하거나 명시적으로 실패해야 합니다. 조용히 무시되어서는 안 됩니다. 재처리 시도와 결과를 로그로 남기십시오.

**셋째, 노후 잠금 알림을 추가하십시오.** `monitor-market-daily-pipeline.yml`에 임계치를 넘긴 `processing` 레코드 존재 여부 검사를 추가하고, 존재하면 워크플로를 실패시키고 이슈를 생성하십시오.

**넷째, 인덱스를 만드십시오.** `0008` 마이그레이션에 인덱스가 하나도 없었던 문제를 반복하지 마십시오. 상태와 시각으로 조회하므로 `(status, locked_at)` 복합 인덱스가 필요합니다.

**완료 판정.** 인위적으로 `processing` 상태를 30분 이상 남긴 뒤 다음 파이프라인이 잠금을 회수하고 진행하는 것을 테스트로 확인하십시오. 경계 조건(29분, 31분) 테스트를 포함하십시오. 노후 잠금이 있을 때 모니터 워크플로가 실패하는 것도 확인하십시오.

## 4. 보류 상태로 두는 것

배포 워크플로 경량화(빌드 중복 제거, job 통합, wrangler 고정)는 프로덕션 배포 경로를 건드리는 작업입니다. Actions가 잠겨 검증이 불가능한 지금은 착수하지 마십시오. 한도가 복구된 뒤 진행합니다.

CI 워크플로의 실행 시간과 `cancel-in-progress` 동작 검증도 한도 복구 후로 미룹니다. 두 워크플로는 완료가 아니라 **미검증 상태**로 기록하십시오.

## 5. 작업 규칙

기존 파일을 통째로 다시 쓰지 말고 증분 편집만 하십시오.

완료 보고에는 `git log --oneline -n 5`와 `git status --porcelain`을 함께 넣으십시오. `git diff --stat`만으로는 커밋 여부를 알 수 없습니다.

작업 후 추적되지 않는 파일이 남아 있지 않아야 합니다. 임시 산출물은 반드시 `scratch/` 안에서만 만드십시오.

모든 파일은 UTF-8로 저장하고 BOM이 없는지 검증하십시오.

확인한 사실과 추론한 내용을 구분해 표기하고, 검증하지 못한 항목은 완료가 아니라 미검증으로 표기하십시오.
