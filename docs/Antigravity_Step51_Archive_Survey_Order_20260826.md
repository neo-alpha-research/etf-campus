## 1. 작업 A: 사전 조사 (읽기 전용)

**아래 여섯 항목을 코드와 파일을 읽어 답하십시오. 한 번에 보고하고 멈추십시오.**

### A-1. 학습용 예시 브리핑 현황

`lib/content/briefings` 를 읽고 다음을 보고하십시오.

**브리핑 원본 파일이 어디에 몇 개 있는지**입니다. 경로와 개수, 날짜 목록입니다.

**파일 형식**입니다. 마크다운인지 다른 형식인지, 프론트매터 필드가 무엇인지입니다.

**`isLearningExample` 플래그가 어떻게 정해지는지**입니다. 전부 예시인지 일부만인지입니다.

**`loadBriefings()` 와 `findBriefing()` 의 구현**입니다. 짧으면 그대로 인용하십시오.

### A-2. 마켓 브리핑 화면의 데이터 흐름

`app/briefing/page.tsx` 와 `components/market-briefing/market-briefing.tsx` 를 읽고 보고하십시오.

**데이터를 어디서 받는지**입니다. `lib/hooks/use-market-briefing.ts` 를 쓰는지, 서버에서 받는지, 클라이언트 fetch 인지입니다.

**최상위 컴포넌트가 받는 props 의 타입**입니다. 타입 정의 위치와 필드 목록입니다.

**API 응답 객체를 그대로 넘기면 컴포넌트가 그려지는 구조인지**입니다. 중간 변환이 있으면 어디인지입니다.

**이것이 JSON 파일로 대체 가능한지 판단하는 근거입니다.**

### A-3. 삭제 대상 테이블과 연쇄

`market_briefings` 행을 지울 때 함께 지워야 할 테이블을 확인하십시오.

**마이그레이션에서 외래키와 `ON DELETE CASCADE` 여부**를 확인하십시오.

**CASCADE 가 없으면 삭제 순서**를 제시하십시오.

**현재 `market_briefings` 에 있는 날짜 목록**을 조회해 보고하십시오. 이것은 `SELECT` 이므로 실행해도 됩니다.

### A-4. 사이트맵 현황

**사이트맵을 생성하는 코드가 있는지** 확인하십시오. `app/sitemap.ts`, `public/sitemap.xml`, 빌드 스크립트 어디든입니다.

**있으면 어떤 경로를 포함하는지**, 없으면 없다고 보고하십시오.

**`robots.txt` 가 있는지**도 확인하십시오.

### A-5. 목록 컴포넌트

`components/market-briefing/market-briefing-history.tsx` 를 읽고 보고하십시오.

**`history.js` API 를 어떻게 호출하는지**, `limit` 파라미터를 넘기는지입니다.

**목록 항목을 클릭하면 어떻게 되는지**입니다. 링크가 있는지 없는지입니다.

### A-6. 빌드 시점 데이터 접근

**`generateStaticParams` 와 페이지 렌더링이 빌드 시점에 파일을 읽는 방식**을 `[date]/page.tsx` 기준으로 확인하십시오.

**Cloudflare Pages 빌드 환경에서 `content/` 같은 디렉터리를 읽을 수 있는지** 판단하십시오. 현재 학습용 예시가 그렇게 동작한다면 가능한 것입니다.

**A-1 부터 A-6 까지 한 번에 보고하고 멈추십시오.**

## 2. 작업 B: 브리핑 데이터 정리

**작업 A 와 병행 가능합니다. 다만 워크플로 실행은 최대 2회입니다.**

### B-1. 삭제 대상

```
2026-08-19   삭제  (더미)
2026-08-20   삭제  (더미)
2026-08-24   삭제 후 재발행  (지수 값이 8월 21일 것으로 잘못 들어감)
```

**남길 것은 2026-08-21, 2026-08-24(재발행), 2026-08-25 세 건입니다.**

### B-2. 삭제 절차

**A-3 에서 확인한 연쇄 관계에 따라 순서대로 지우십시오.**

**삭제 전에 대상 행을 조회해 출력하십시오.** 무엇을 지우는지 기록에 남겨야 합니다.

**삭제 후 남은 날짜 목록을 조회해 보고하십시오.**

**이 삭제는 승인된 작업입니다.** 다만 세 날짜 외의 행을 지우지 마십시오.

### B-3. 8월 24일 재발행

삭제 후 워크플로를 실행하십시오.

```
gh workflow run daily-market.yml -f target=20260824
```

**실행 후 확인할 것입니다.**

`market_briefings` 에 2026-08-24 행이 새로 생겼는지입니다.

**지수 값이 정정되었는지**입니다. 코스피 6696.96(-3.12%), 코스닥 813.33(+1.42%) 이 되어야 합니다. 기존 값은 6912.95(+0.88%), 801.94(-4.63%) 였습니다.

`nav_value` 와 `asset_detail` 이 채워졌는지입니다.

### B-4. 마스터 CSV 복구

8월 24일 실행이 마스터 CSV 를 되돌렸으면 **8월 25일로 한 번 더 실행해 복구하십시오.**

**이것이 두 번째이자 마지막 실행입니다.**

**`bas_dt` 분포가 `20260825` 단일값인지 확인해 보고하십시오.**

### B-5. 실패 시

**재실행을 반복하지 마십시오.** 로그를 확보하고 보고하십시오.

## 4. 확정된 설계 (참고용, 이번에 구현하지 마십시오)

**작업 A 조사를 제대로 하시려면 최종 목표를 알아야 하므로 미리 알립니다.**

### 4-1. URL 구조

```
/briefing/                     최신 마켓 브리핑 (현행 유지)
/briefing/2026-08-25           개별 마켓 브리핑 (신규)
/learn/briefing/2026-08-25     학습용 예시 (이전)
```

**학습용 예시를 `/learn/briefing/` 으로 옮기고 `/briefing/{날짜}` 를 마켓 브리핑에 넘깁니다.**

**이미 검색에 잡힌 주소가 있으면 리다이렉트가 필요합니다. A-1 조사에서 개수를 파악하는 이유입니다.**

### 4-2. 데이터 형식

**JSON 입니다.** 현재 화면과 컴포넌트를 그대로 쓰기 위해서입니다.

일간 워크플로가 발행 성공 후 브리핑 데이터를 파일로 커밋하고, 빌드가 그 파일을 읽어 정적 페이지를 만듭니다.

**파일 경로는 조사 결과를 보고 확정합니다.**

### 4-3. 왜 파일인가

**정적 export 이므로 내용이 빌드 시점에 HTML 에 들어가야 검색엔진이 읽습니다.** 클라이언트에서 API 를 호출해 채우면 빈 페이지로 인식됩니다.

**빌드 중 외부 API 를 호출하는 방식은 쓰지 않습니다.** API 장애가 빌드 실패로 이어집니다.

### 4-4. 서술 확장은 하지 않습니다

**브리핑에 해석이나 전망 문장을 추가하지 마십시오.**

현재 헤드라인은 사실 서술이라 안전합니다. 해석을 얹으면 자본시장법 제101조 유사투자자문업 경계에 닿습니다. **매일 자동 생성되는 구조에서는 특히 그렇습니다.**
