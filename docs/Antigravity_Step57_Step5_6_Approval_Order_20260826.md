## 2. 두 방법이 부호까지 어긋납니다

### 2-1. 실측 좌수와 역산 좌수의 불일치

`data/etf_master_draft.csv` (2026-08-25 기준, 1,164행) 를 발신 측에서 직접 검산했습니다.

`shares` 와 `aum / nav` 가 같은 값이어야 합니다. 정의상 순자산총액은 좌수 곱하기 NAV 이기 때문입니다.

```
상대오차 1e-6 초과   335 종목
상대오차 0.01% 초과   326 종목
상대오차 0.1% 초과    302 종목
상대오차 1% 초과      120 종목
최대 상대오차        22.73%  (428510 KODEX 차이나AI테크액티브)
```

**1,164종목 중 326종목, 28퍼센트가 어긋납니다.**

어긋나는 폭이 5만 좌, 10만 좌 단위로 딱 떨어집니다. 설정 환매 단위입니다. **반올림 오차가 아니라 서로 다른 시점의 값입니다.**

### 2-2. 순유입 금액이 2.6배 벌어집니다

2026-08-25 대비 2026-08-24 로 두 방법을 각각 계산했습니다.

```
방법 1  (shares(T) - shares(T-1)) * NAV(T)          합계  -4,955억원
방법 2  (AUM(T)/NAV(T) - AUM(T-1)/NAV(T-1)) * NAV(T) 합계  -1,898억원
                                                     차이  -3,057억원
```

**개별 종목에서는 부호가 뒤집힙니다.**

```
122630  KODEX 레버리지          실측  +528억 유입    역산  -2,744억 유출
233740  KODEX 코스닥150레버리지   실측  -362억 유출    역산  +1,870억 유입
069500  KODEX 200              실측 -3,199억 유출   역산    -640억 유출
102110  TIGER 200              실측 -1,817억 유출   역산    -802억 유출
```

**종목별 차이가 10억원을 넘는 것이 259종목입니다.**

**어느 쪽을 고르느냐에 따라 "오늘 자금이 들어왔는가 나갔는가" 의 답이 달라집니다.** 이 상태로 발행하면 안 됩니다.

### 2-3. 발신 측 가설

세 거래일 표본으로 세 가지 가설을 검정했습니다.

```
가설 A   AUM/NAV(T) == shares(T-1)    17 / 326   AUM 이 하루 지연
가설 B   shares(T)  == shares(T-1)   123 / 326   shares 갱신 누락
가설 C   shares(T)  == AUM/NAV(T-1)  234 / 326   shares 가 하루 지연
```

**가설 C 가 세 거래일 연속 재현됩니다.**

```
2026-08-25 대비 08-24    불일치 326 종목 중 234 성립   72%
2026-08-24 대비 08-21    불일치 346 종목 중 248 성립   72%
2026-08-21 대비 08-20    불일치 323 종목 중 230 성립   71%
```

**즉 `shares` 는 T 시점이 아니라 T-1 시점 좌수일 가능성이 높습니다.** 그렇다면 실측 좌수로 계산한 순유입은 하루 밀린 자금 흐름을 오늘 것으로 기록하게 됩니다.

**다만 72퍼센트이지 100퍼센트가 아닙니다. 나머지 28퍼센트가 설명되지 않습니다. 발신 측도 확정하지 못했습니다.**

## 3. 작업 A: 좌수 시점 규명 (5번의 전제)

**추정으로 넘어가지 마십시오. 다음을 확인해 보고하십시오.**

### 3-1. 수집 단에서 시점을 확인하십시오

```
scripts/update_daily_data.py L728
api_shares = snapshot_value(api, "stLstgCnt", existing.get("shares", ""))
```

**API 가 값을 주지 않으면 기존값을 그대로 씁니다.** 이 캐리포워드가 가설 B 의 123종목을 설명하는지 확인하십시오.

**KRX `LIST_SHRS` 와 FSC `stLstgCnt` 의 기준일이 응답 본문에 명시되는지 확인하십시오.** `BAS_DD` 와 같은 날인지, 별도 필드가 있는지입니다. **응답 원문을 붙여 보고하십시오.**

### 3-2. 외부 기준점과 대조하십시오

**대표 종목 3종목을 골라 상장좌수를 외부 공시와 대조하십시오.** 069500 KODEX 200, 102110 TIGER 200, 그리고 불일치 폭이 컸던 428510 입니다.

**세 종목의 특정 거래일 좌수가 `shares` 와 맞는지 `aum / nav` 와 맞는지가 이 조사의 결론입니다.**

### 3-3. NAV 의 기준 시점을 확인하십시오

`nav` 가 당일 종가 기준 NAV 인지, 전일 확정 NAV 인지 확인하십시오. **NAV 가 하루 밀려 있으면 두 방법 모두 틀립니다.**

`close` 와 `nav` 의 괴리율 분포를 보십시오. 정상적인 ETF 라면 괴리율이 대부분 ±0.5퍼센트 안에 들어옵니다. **분포가 그보다 넓게 퍼져 있으면 시점 불일치를 의심하십시오.**

**3-1 부터 3-3 까지 보고한 뒤 순유입 계산 방식 승인을 요청하십시오.** 여기서 다시 한 번 멈춥니다.

## 5. 작업 C: `shares` 를 D1 까지 연결

**어느 계산 방식을 채택하든 두 값을 모두 보관해야 판정이 가능합니다. 저장은 지금 하십시오.**

### 5-1. 다섯 지점을 모두 고치십시오

```
1  scripts/publish_market_source_snapshot.py   L124~135 페이로드에 "shares" 추가
2  functions/api/internal/ingest-market-source.js  L205 normalizeEtf 반환 객체에 shares 추가
3  functions/api/internal/ingest-market-source.js  L134 INSERT 컬럼과 bind 에 추가
4  migrations/0016_*.sql   market_source_etf_daily 와 briefing_etf_daily 에 ALTER TABLE ADD COLUMN shares
5  workers/market-briefing-publisher/src/source-materializer.ts  L145 INSERT 컬럼과 bind 에 추가
```

**다섯 곳 중 하나라도 빠지면 값이 조용히 사라집니다.** `normalizeEtf` 가 `navValue` 와 `assetDetail` 을 반환 객체에서 누락시켜 D1 에 전부 NULL 로 들어갔던 사고와 같은 구조입니다.

### 5-2. 타입과 결측 처리

`shares` 는 정수 좌수입니다. **REAL 이 아니라 INTEGER 로 선언하십시오.**

마스터 CSV 1,164행 전부 채워져 있습니다. **그래도 NULL 허용으로 두고, 결측 건수를 발행 로그에 출력하십시오.**

### 5-3. 마이그레이션 파일에 BOM 을 넣지 마십시오

`0011` 과 `0012` 선두에 BOM 이 있습니다. **새 파일은 BOM 없는 UTF-8 로 저장하십시오.**

### 5-4. 검증

**적재 후 D1 에서 확인하십시오.**

```sql
SELECT COUNT(*) AS total, COUNT(shares) AS with_shares,
       SUM(CASE WHEN ABS(aum_value/nav_value - shares) / shares > 0.001 THEN 1 ELSE 0 END) AS mismatch
FROM briefing_etf_daily WHERE as_of_date = '<최신 거래일>' AND nav_value > 0 AND shares > 0;
```

**`mismatch` 가 300 안팎으로 나와야 합니다.** 발신 측 검산과 맞는지 대조하는 것이 목적입니다. **0 이 나오면 어느 한쪽이 다른 쪽에서 계산된 값이라는 뜻이므로 보고하십시오.**

## 6. 작업 D: 테이블 생성

**3-2 컬럼 구성 원안을 승인합니다. 다음 세 가지만 바꾸십시오.**

### 6-1. `shares` 기반 컬럼을 함께 두십시오

`market_scale_daily` 와 `peer_flow_daily` 의 `net_flow` 를 **두 벌로 두십시오.**

```
net_flow_shares    실측 좌수 기준
net_flow_derived   AUM/NAV 역산 기준
net_flow_method    채택된 방식 ('shares' | 'derived' | NULL)
```

**둘 다 적재하되 `net_flow_method` 는 3번 조사가 끝날 때까지 NULL 로 두십시오.**

API 는 `net_flow_method` 가 NULL 이면 순유입을 반환하지 않습니다. **화면에는 "집계 방식 검증 중" 으로 표기하십시오.**

이렇게 하면 조사가 끝났을 때 재발행 없이 컬럼 하나만 채우면 확정됩니다.

### 6-2. 가중수익률은 기초 AUM 으로 가중하십시오

```
aum_weighted_return_pct = SUM(AUM(T-1) * change_pct) / SUM(AUM(T-1))
```

**T 시점 AUM 으로 가중하지 마십시오.** 그날 오른 종목의 AUM 이 이미 커져 있으므로 수익률이 구조적으로 위로 편향됩니다.

**T-1 에 없는 신규 상장 종목은 가중수익률 계산에서 제외하고, 제외 건수를 컬럼에 남기십시오.**

### 6-3. 모집단은 교집합으로 고정하십시오

2026-08-21 은 1,055건, 08-24 와 08-25 는 1,015건입니다. **40건 차이가 있습니다.**

`is_general_etf` 는 `risk_type == normal` 이고 `asset_class` 가 금리 파킹이 아닌 종목입니다. 금리 파킹이 43종목이므로 **8월 21일 발행 시점에 이 제외 조건이 없었을 가능성이 큽니다. 확인해 보고하십시오.**

**순유입은 T 와 T-1 양쪽에 존재하는 종목만 계산하고, 한쪽에만 있는 종목은 `flow_excluded_count` 에 분리 집계하십시오.** 모집단이 바뀐 것을 자금 유출로 기록하면 안 됩니다.

**`new_listing_count` 와 `flow_excluded_count` 를 구분하십시오.** 신규 상장은 T 에만 있는 것이고, 상장폐지와 분류 변경은 T-1 에만 있는 것입니다. 성격이 다릅니다.

## 7. 커버리지 임계값

**원안을 승인합니다.**

```
AUM 유효성      aum_coverage_pct  >= 95%     미달 시 total_aum = NULL, reason 기록
순유입 유효성    flow_coverage_pct >= 90%     미달 시 net_flow = NULL, reason 기록
주간 동향        trading_days >= 5            미달 시 진행률 표기
월간 동향        trading_days >= 21           미달 시 진행률 표기
```

**미달 시 파이프라인을 중단시키지 마십시오. NULL 과 사유만 남기고 통과시키십시오.**

**`reason` 을 화면에서 그대로 노출하지 마십시오.** `low_aum_coverage` 같은 내부 코드는 로그와 API 응답용이고, 화면에는 한국어 문장으로 바꿔 표기하십시오.

## 8. 주간 월간 진행률 표기

**소급 계산이 불가능함을 발신 측에서 확인했습니다.**

```
functions/api/internal/ingest-prices.js L8
INSERT INTO etf_prices (ticker, date, close) VALUES (?, ?, ?)
```

**백필된 `etf_prices` 에는 종가만 있습니다. AUM 도 NAV 도 좌수도 없습니다.** 과거 구간의 자금 흐름을 되살릴 재료가 존재하지 않습니다.

**따라서 진행률 표기안을 승인합니다.**

```
주간 동향   집계 준비 중  3 / 5 거래일 수집됨
월간 동향   집계 준비 중  3 / 21 거래일 수집됨
```

**"0.0 조원" 을 절대 표시하지 마십시오.** 데이터 없음과 값이 0 인 것은 다릅니다.

**진행률 숫자를 하드코딩하지 마십시오.** `SELECT COUNT(DISTINCT as_of_date)` 로 매번 세십시오. 주간은 9월 2일경, 월간은 9월 24일경 자연히 채워집니다.
