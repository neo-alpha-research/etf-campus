## 0. 정정은 정확히 반영되었습니다

**데이터로 직접 확인했습니다.**

```
isa_eligible      가능 1,167                     전 종목 반영 확인
pension_limit     안전 237 / 위험 794 / 불가 136   합계 1,167 일치
혼합·자산배분 20   안전 16 / 위험 4               경계 4종목 확인
커밋              f452bb8 main 반영
```

**미확인으로 남겨 두었던 경계 4종목이 특정되었습니다.**

```
KODEX TRF7030          주식 70 채권 30
KODEX 멀티에셋하이인컴(H)
RISE 글로벌자산배분액티브
UNICORN K바이오액티브
```

**적격 TDF 13 + TRF3070 + TRF5050 + TIF = 16 이 안전자산이라는 구성도 맞습니다.**

**다만 보고서에는 네 번째 종목이 "UNICORN K뉴딜액티브" 로 적혀 있는데 실제 데이터는 "UNICORN K바이오액티브" 입니다.** 종목명을 데이터에서 복사하지 않고 옮겨 적으신 것으로 보입니다. **법정 규제 문서에서 종목명 오기는 그 자체로 신뢰 문제입니다.**

**개인투자용 국채 퇴직연금 편입도 사실로 확인했습니다.** 2026년 9월 시행, DC·IRP 대상, 10년물과 20년물, 청약 9월 9일부터 15일까지입니다.

## 1. 새로 드러난 문제: 합성 ETF 99종목

### 1-1. 판정 로직

```python
scripts/rules/pension_regulatory_engine.py L69~72
is_spot = "현물" in name
has_futures_keyword = bool(re.search(r"선물|Futures", f"{name} {base_index}", re.IGNORECASE))
if has_futures_keyword and not is_spot:
    return 불가
```

**"선물" 이라는 단어가 이름이나 기초지수에 있는지로 판정합니다.**

### 1-2. 그런데 파생 40% 기준의 주된 적용 대상은 합성입니다

**합성 ETF 는 장외 스왑으로 지수를 복제합니다. 선물이 아니라 스왑이므로 이름에 "선물" 이 없습니다.**

**현재 데이터 상태입니다.**

```
이름에 "합성" 포함   99종목
  안전자산 100%      26
  위험자산 70%       48
  불가               25

즉 74종목이 퇴직연금 가능으로 분류되어 있습니다.
```

**그 74종목은 파생 위험평가액을 한 번도 확인받지 않고 통과했습니다.** 이름에 "선물" 이 없다는 이유만으로 통과한 것입니다.

**표본입니다.**

```
0000D0  TIGER 엔비디아미국채커버드콜밸런스(합성)   100% 안전자산
0005C0  RISE 미국S&P500엔화노출(합성 H)         70% 위험자산
181480  ACE 미국부동산리츠(합성 H)              70% 위험자산
```

### 1-3. 왜 문제인가

**퇴직연금 편입 제한의 실제 기준은 파생상품 위험평가액 40퍼센트입니다. 상품 이름이 아닙니다.**

**합성 ETF 는 스왑 계약 비중에 따라 이 기준에 걸릴 수도 있고 아닐 수도 있습니다. 종목별 투자설명서를 봐야 압니다. 이름으로는 판정할 수 없습니다.**

**실제로 대부분의 합성 ETF 는 편입이 가능합니다. 그러나 그것은 결과가 우연히 맞은 것이지 로직이 맞은 것이 아닙니다.**

**사용자가 스크리너에서 편입 가능으로 보고 매수를 시도했다가 증권사에서 거부당하면, 그때는 우리 데이터가 틀렸다는 사실이 사용자 손실과 함께 드러납니다.**

### 1-4. 지시

**커버드콜도 함께 보십시오. 62종목이 있고 전부 편입 가능으로 분류되어 있습니다.** 옵션 매도를 쓰는 상품이므로 같은 검토 대상입니다.

**다음을 확인해 보고하십시오.**

**합성 74종목과 커버드콜 62종목 중 실제로 퇴직연금 편입이 막히는 종목이 있는지 확인하십시오.** 증권사 퇴직연금 매수 가능 종목 목록 또는 각 상품 투자설명서의 파생상품 위험평가액 항목이 근거입니다.

**표본 5종목만 대조해도 됩니다.** 전수는 다음 단계입니다.

**하나라도 어긋나면 이름 기반 판정을 폐기해야 합니다.**

## 2. 새로 드러난 문제: 레버리지 교육 요건의 기준이 틀렸습니다

### 2-1. 보고서 서술

> 레버리지 ETP 는 사전교육/예탁금 충족 시 매수 가능, **1X 및 인버스는 제한 없음**

### 2-2. 사실

**레버리지 ETP 매매거래제도의 적용 기준은 배율의 절댓값입니다. 레버리지냐 인버스냐가 아닙니다.**

```
-1배 인버스     제도 적용 대상 아님. 사전교육 불필요
-2배 인버스     제도 적용 대상. 사전교육 및 기본예탁금 필요
```

### 2-3. 데이터 확인

```
인버스 41종목 중 -2X 계열 10종목

0193L0  PLUS 삼성전자선물단일종목인버스2X
230480  KIWOOM 미국달러선물인버스2X
252670  KODEX 200선물인버스2X
252710  TIGER 200선물인버스2X
253160  PLUS 200선물인버스2X
   외 5종목
```

**"인버스는 제한 없음" 으로 처리하면 이 10종목에 필요한 안내가 빠집니다.**

**반대로 인버스 41종목 전부에 교육 필요 뱃지를 붙이면 -1배 31종목에 불필요한 경고가 붙습니다.**

**둘 다 틀립니다.**

### 2-4. 지시

**`risk_type` 이 아니라 배율로 판정하십시오.**

```
교육 필요    레버리지 62 + 인버스 -2X 10 = 72종목
교육 불필요  나머지 1,095종목
```

**엔진은 현재 `isa_eligible` 을 무조건 "가능" 으로만 채우고 배율 정보를 남기지 않습니다.** UI 가 `risk_type` 으로 뱃지를 분기하면 위 오류가 그대로 화면에 나옵니다.

**엔진에 `isa_education_required` 같은 컬럼을 추가하고, 배율 판정 근거를 그 안에 남기십시오.** 뱃지는 그 컬럼만 보게 하십시오.

**배율 판정을 이름 문자열로만 하지 마십시오.** 1-3 과 같은 문제가 반복됩니다. **`risk_type` 과 이름 양쪽을 쓰되, 판정이 어긋나는 종목은 목록으로 뽑아 보고하십시오.**

## 3. 법령 조문 인용을 검증하십시오

### 3-1. 근거 없이 조문 번호가 박혔습니다

**보고서와 코드 주석에 다음이 들어갔습니다.**

```
근로자퇴직급여보장법 제21조
퇴직연금감독규정 제9조 및 제11조
조세특례제한법 제91조의18
```

**발신 측 검증에서는 파생 40퍼센트 기준이 존재한다는 사실까지만 확인했습니다. 조문 번호는 확인하지 못했습니다.**

**법령 조문을 잘못 인용하면 다른 모든 내용이 정확해도 신뢰가 무너집니다.** 금융 콘텐츠에서 특히 그렇습니다.

**국가법령정보센터에서 조문을 직접 확인하고, 조문 제목과 핵심 문장을 원문 그대로 인용해 보고하십시오.** 확인되지 않으면 조문 번호를 빼고 "퇴직연금감독규정" 까지만 쓰십시오.

### 3-2. "위반" 이라는 표현을 쓰지 마십시오

```python
pension_regulatory_engine.py
"pension_reason": "레버리지/인버스 파생평가액 초과 (감독규정 제9조 위반)"
```

**해당 상품이 규정을 위반한 것이 아닙니다. 퇴직연금 편입 요건을 충족하지 못한 것입니다.**

**정상적으로 상장되어 거래되는 상품에 "위반" 을 붙이면 사실과 다르고, 운용사에 대한 부정적 사실 적시가 됩니다.**

```
현재   감독규정 제9조 위반
정정   퇴직연금 편입 요건 미충족
```

**사용자 화면에 노출되는 문구인지 확인하고, 노출된다면 즉시 고치십시오.**

## 4. "연 8퍼센트대" 수치를 콘텐츠에 그대로 옮기지 마십시오

**개인투자용 국채 퇴직연금 편입은 사실입니다. 그러나 "연 8퍼센트대 만기수익률 효과" 는 정의가 불분명합니다.**

**개인투자용 국채는 표면금리에 가산금리를 더하고 만기 보유 시 연복리를 적용합니다.** 이때 나오는 숫자가 연 환산 수익률인지, 만기까지의 총수익률인지, 특정 조건에서의 세후 효과인지에 따라 전혀 다른 값이 됩니다.

**AGENTS.md §4-2 는 마케팅 전면에 구체적 수익률을 내세우는 것을 금지합니다.**

**콘텐츠에 넣으려면 다음을 먼저 확인하십시오.** 숫자의 정확한 정의, 산출 전제, 출처입니다. **확인 전에는 "장기 보유 시 복리 효과가 적용됩니다" 수준의 정성 표현으로 두십시오.**

**그리고 개인투자용 국채는 ETF 가 아닙니다. 스크리너 1,167개 집계와 섞이지 않게 하십시오.**

## 5. 근본 권고: 이름으로 법정 규제를 판정하지 마십시오

**1번과 2번은 증상이고 원인은 하나입니다.**

**현재 엔진은 종목명 문자열로 법정 편입 가능 여부를 판정합니다.**

```
"선물" 이 있으면 불가
"현물" 이 있으면 예외
```

**이 방식은 세 가지로 깨집니다.** 신규 상품이 다른 작명을 쓰면 놓치고, 운용사가 이름을 바꾸면 판정이 바뀌며, 규제 기준과 이름은 상관관계일 뿐 인과가 아닙니다.

**진짜 판정 근거는 각 상품의 파생상품 위험평가액 비율이고, 그 값은 이름에 없습니다.**

### 5-1. 확인할 것

**증권사가 제공하는 퇴직연금 계좌 매수 가능 ETF 목록이 있는지 확인하십시오.** 있으면 그것이 SSOT 가 되어야 합니다.

**공공데이터포털이나 금융투자협회에 퇴직연금 편입 적격 상품 정보가 있는지 확인하십시오.**

**없으면 현재 방식을 유지하되, 데이터에 판정 근거와 신뢰도를 남기십시오.**

```
pension_source     "규칙기반추정" | "증권사목록대조" | "투자설명서확인"
pension_confidence "높음" | "보통" | "낮음"
```

**합성과 커버드콜처럼 이름으로 판정할 수 없는 종목은 신뢰도를 낮음으로 표시하고, 화면에 "증권사에서 최종 확인하십시오" 안내를 붙이십시오.**

**이것이 지금 할 수 있는 가장 정직한 처리입니다.**

## 7. 작업 규칙

**종목명과 수치는 데이터에서 복사하십시오. 옮겨 적지 마십시오.**

**"위반" 처럼 대상을 부정적으로 규정하는 표현을 판정 사유에 쓰지 마십시오.**

**확인하지 못한 것은 미확인으로 적으십시오.**

**`git add .` 과 `git commit -am` 을 쓰지 마십시오.**

**명령을 `;` 로 연결하지 마십시오.**

**스크립트는 `scratch/` 안에 파일로 만들어 실행하십시오.**

기존 파일을 통째로 다시 쓰지 말고 증분 편집만 하십시오.

보고 전에 `git status --porcelain` 과 `git log --oneline -n 5`, `git rev-parse --abbrev-ref HEAD` 를 실행해 출력을 붙여넣으십시오.

## 8. 진행 순서

**1단계.** 3-2 의 "위반" 문구가 사용자 화면에 노출되는지 확인하고, 노출되면 즉시 고치십시오. **가장 먼저 하십시오.**

**2단계.** 2-4 로 레버리지 교육 요건을 배율 기준으로 바꾸고, 교육 필요 72종목이 나오는지 확인해 보고하십시오.

**3단계.** 1-4 로 합성과 커버드콜 표본 5종목을 대조해 보고하십시오. **결과에 따라 판정 방식 유지 여부를 결정합니다.**

**4단계.** 3-1 로 법령 조문 3개를 원문 확인해 보고하십시오. **확인 안 되면 조문 번호를 빼십시오.**

**5단계.** 5-1 로 증권사 또는 공공 API 에 퇴직연금 적격 목록이 있는지 조사해 보고하십시오.

**6단계.** 여기서 멈추십시오. 판정 방식 변경은 3단계와 5단계 결과를 보고 결정합니다.

**1단계와 2단계를 먼저 처리하고 보고하십시오.**
