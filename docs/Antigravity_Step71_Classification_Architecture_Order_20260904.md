## 0. 운영자 제안에 대한 판정

**운영자께서 제시한 방향입니다.**

> 법적 문구를 모아 그에 맞춰 분류하는 로직으로 자동화하고, 자산운용사 등의 소스로 대조해 오류율을 0퍼센트에 가깝게 만든 뒤, 신규 상장 ETF 도 그 로직으로 판단한다.

**방향은 옳습니다. 다만 그대로는 성립하지 않습니다. 이유는 법령 기준이 세 종류인데 그중 하나만 로직화가 가능하기 때문입니다.**

### 0-1. 법령 기준 세 종류

**기준 1. 배율**

레버리지와 인버스입니다. **법령이 관측 가능한 속성으로 정의합니다.** 종목명과 `risk_type` 에 명시되어 있습니다.

**로직화 가능하며 이미 정확합니다. 오류율 0퍼센트를 달성한 유일한 영역입니다.**

**기준 2. 상품 구조**

선물형, 합성형, 커버드콜입니다. **그런데 법령은 "선물형이면 불가" 라고 쓰지 않았습니다.**

**법령이 쓴 것은 기준 3입니다. 상품 구조는 그 값을 짐작하는 대리 변수일 뿐입니다.**

**기준 3. 파생상품 매매에 따른 위험평가액 40퍼센트**

**이것이 실제 법정 기준입니다. 그리고 이 값은 각 상품의 투자설명서에 있는 숫자입니다. 우리 데이터에 없습니다.**

**따라서 현재 로직은 법령을 구현한 것이 아니라, 법령이 요구하는 숫자를 이름으로 추측하고 있습니다.**

### 0-2. 오류율 0퍼센트가 불가능한 이유

**입력이 없기 때문입니다.**

**대조로 규칙을 다듬으면 오류율은 내려갑니다. 그러나 0 에 수렴하지 않습니다.** 이름과 위험평가액 사이에 완전한 대응이 없기 때문입니다.

**대조는 규칙의 정확도를 측정할 뿐, 규칙에 없는 정보를 만들어 내지 못합니다.**

### 0-3. 마지막 단계가 특히 위험합니다

> 신규 상장 ETF 도 해당 로직으로 판단

**이것이 성립하려면 로직이 신규 종목에 대해서도 맞다는 것을 확인할 방법이 있어야 합니다.**

**그런데 5단계 조사에서 퇴직연금 적격 ETF 통합 API 가 존재하지 않음이 확인되었습니다.**

**즉 신규 상장 종목을 자동으로 검증할 소스가 없습니다. 검증 없이 계속 돌아가는 로직이 됩니다.**

**그리고 현재 로직은 신규 종목이 들어왔을 때 이름에 "선물" 이 없으면 자동으로 편입 가능으로 판정합니다. 기본값이 "가능" 입니다. 가장 위험한 설정입니다.**

## 1. 그래서 어떻게 해야 하는가

### 1-1. 진짜 해법은 숫자를 가져오는 것입니다

**각 ETF 의 투자설명서와 집합투자규약에 다음 취지의 문장이 있습니다.**

```
파생상품 매매에 따른 위험평가액이 자산총액의 100분의 XX 를 초과하지 않습니다
```

**이것이 법령이 요구하는 바로 그 숫자입니다. 이름 매칭을 대체합니다.**

**조사할 것**

**금융투자협회 전자공시(`dis.kofia.or.kr`)에 펀드 공시 자료가 있습니다.** 위험평가액 한도가 조회 가능한지 확인하십시오.

**각 자산운용사 상품 페이지에 투자설명서 PDF 링크가 있습니다.** 해당 문장이 정형화된 위치에 있는지 표본 5종목으로 확인하십시오.

**운용사 상품 페이지에 "퇴직연금 편입 가능" 표기가 있는 경우가 많습니다.** 있으면 그것이 가장 싼 대조 소스입니다.

**세 경로 중 무엇이 가능한지 확인해 보고하십시오. 수집을 시작하지는 마십시오.**

**한 번 수집하면 이후에는 신규 상장분만 추가하면 됩니다. 월 5건에서 10건 수준입니다. 지속 가능합니다.**

### 1-2. 그때까지는 3계층으로 나누십시오

**현재는 2계층입니다. 확정과 추정입니다. 하나가 빠졌습니다.**

```
확정    배율 기준. 레버리지·인버스. 신뢰도 높음
추정    구조 기준. 선물·합성·커버드콜. 신뢰도 보통
미판정  신규 상장으로 아직 대조되지 않은 종목. 판정 보류
```

**신규 상장 종목이 자동으로 "가능" 이 되지 않도록 하십시오.**

**상장일로부터 일정 기간, 또는 대조가 이루어질 때까지 `pension_confidence = 낮음` 과 함께 화면에 "확인 중" 으로 표시하십시오.**

**틀린 답을 주는 것보다 답을 미루는 것이 낫습니다.**

### 1-3. 오류율을 실제로 측정하십시오

**현재 "오류 0건" 은 자기 규칙이 자기 데이터와 일치하는지를 본 것입니다.**

```
verify_zero_hallucination.py
Total Errors: 0
```

**규칙이 틀렸으면 0건이 나와도 전부 틀린 것입니다.** 지난주 백필 지수 더미를 이 검사기가 통과시킨 것과 같은 구조입니다.

**오류율은 외부 대조군이 있어야 나옵니다.**

**운용사 소스로 50종목을 대조하면 오류율과 신뢰구간이 처음으로 산출됩니다. 그 수치가 없으면 "0퍼센트에 가깝다" 는 말 자체를 할 수 없습니다.**

**대조 대상은 무작위로 뽑지 마십시오. 규칙이 약한 곳에서 뽑으십시오.** 합성, 커버드콜, 선물형, TR, 혼합형 경계 종목입니다.

## 2. 이번 작업에서 확인된 것

**조문 정정을 확인했습니다.**

```
70% 한도 근거   퇴직연금감독규정 제12조 제4항
제11조          DB 전용이므로 판정 엔진에서 제외
```

**오류를 보고서 서두에 명시하신 것도 확인했습니다. 그 방식이 맞습니다.**

**메타데이터 도입도 데이터로 확인했습니다.**

```
pension_source      표본대조 5 / 규칙기반추정 1,162
pension_confidence  높음 1,046 / 보통 121
```

**보통 121 의 산출도 맞습니다.** 합성 74 + 커버드콜 62 에서 중복 10과 표본 5를 뺀 값입니다.

**표본 일반화 철회와 종목코드 인용 오류 인정도 확인했습니다.**

## 3. 그런데 신뢰도 부여가 비대칭입니다

### 3-1. 선물형 33종목이 전부 "높음" 입니다

```
판정 불가 136종목의 신뢰도

leverage  62  높음      배율 기준. 타당함
inverse   41  높음      배율 기준. 타당함
normal    33  높음      이름에 "선물" 이 있다는 이유만으로 불가
```

**33종목은 합성·커버드콜과 정확히 같은 로직으로 판정되었습니다. 이름 문자열 매칭입니다.**

**그런데 통과시킨 쪽은 "보통" 으로 강등하고, 차단한 쪽은 "높음" 으로 두었습니다.**

**같은 근거인데 결론의 방향에 따라 확신도가 다릅니다. 성립하지 않습니다.**

### 3-2. 게다가 차단 오류가 더 나쁩니다

**합성·커버드콜을 "가능" 이라 했다가 틀리면 사용자가 매수를 시도하다 실패합니다. 오류가 드러납니다.**

**선물형을 "불가" 라 했다가 틀리면 사용자는 그 종목이 존재한다는 것조차 모릅니다. 화면에 나오지 않기 때문입니다.**

**드러나지 않는 오류가 더 위험합니다.**

### 3-3. 지시

**선물형 33종목의 `pension_confidence` 를 "보통" 으로 내리십시오.**

**배율 기준으로 판정된 103종목만 "높음" 을 유지하십시오.**

**결과적으로 분포는 다음과 같아야 합니다.**

```
높음   배율 기준 103 + 파생 요소 없는 일반 종목
보통   합성·커버드콜 121 + 선물형 33 = 154
```

**그리고 편입 불가 종목에도 화면 안내가 필요한지 검토하십시오.** 현재 안내는 "가능" 쪽에만 붙습니다. **불가로 걸러진 종목을 사용자가 볼 방법이 없다면, 필터에 "편입 불가 종목 보기" 옵션을 두는 것을 제안합니다.** 이번에 구현하지는 마십시오.

## 4. 4단계 주장에 출처가 없습니다

**보고서 4-2 에 다음이 적혀 있습니다.**

> 금융위원회는 무차입 1배수 증권형 합성 ETF 의 경우 ... 감독규정 개정(적격 장외파생상품 편입 ETF 예외 조항)을 통해 퇴직연금 편입 시 파생상품 위험평가액 한도를 100퍼센트까지 예외 허용하도록 규제를 완화한 바 있습니다.

**이 주장이 사실이면 판정 로직의 근거가 완전히 바뀝니다. 합성 ETF 는 예외 조항으로 편입되는 것이지 40퍼센트를 안 넘어서가 아니게 됩니다.**

**그런데 조문 번호도 개정 시점도 없습니다.**

**직전 라운드에서 조문 인용을 검증하라고 지시했고, 그 결과 제11조 오류를 찾아내셨습니다. 같은 문제가 4단계에서 반복되고 있습니다.**

**해당 예외 조항의 근거를 찾아 보고하십시오.** 감독규정 조문 번호, 별표 항목, 개정 시점입니다.

**찾지 못하면 4-2 의 결론을 [미확인] 으로 표시하십시오.** 지우지 말고 미확인으로 남기십시오. 나중에 확인할 단서가 됩니다.

**이 조항이 확인되면 0번의 판정이 달라집니다.** 배율과 구조만으로 판정이 가능해지므로, 운영자께서 제안하신 로직 자동화가 실제로 성립할 수 있습니다. **그래서 이것이 지금 가장 중요한 조사입니다.**

**누가 왜 지웠는지 확인해 보고하십시오. 복구가 필요한지 판단이 필요합니다.**
