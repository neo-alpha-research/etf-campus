
**`asset_class` 를 버리고 `underlying_is_security` 를 독립 컬럼으로 신설한 판단이 옳습니다.** 신뢰할 수 없는 분류에 법령 조건을 걸지 않은 것이 핵심입니다.

**그 과정에서 데이터 오류 두 건을 찾아내신 것도 성과입니다.**

```

400590  asset_class 주식-해외  실제 탄소배출권 선물

```

**세 종목 모두 `asset_class` 가 틀렸습니다. 규제 판정과 별개로 스크리너 분류가 잘못 노출되고 있습니다.** 400590 과 401590 은 화면에서 해외주식 ETF 로 나옵니다. **별도 과제로 정리하십시오. 이번에 고치지 마십시오.**

**인시던트 사후 분석과 재발 방지 원칙도 적절합니다.**

## 1. 커버드콜 10종목 승격은 철회하십시오

### 1-1. 지시와 다릅니다

**Step72 지시서 1-2 에 이렇게 썼습니다.**

```
영역 D  커버드콜  옵션 매도. 산정 방식이 다름   회색지대   62종목
D 가 진짜 회색지대입니다. 보통을 유지하십시오.
```

**그런데 62종목 중 10종목이 영역 B 로 올라가 신뢰도 높음이 되었습니다.**

```
0000D0  TIGER 엔비디아미국채커버드콜밸런스(합성)      100% 안전자산  높음
441680  TIGER 미국나스닥100커버드콜(합성)            70% 위험자산   높음
480020  ACE 미국빅테크7+데일리타겟커버드콜(합성)       70% 위험자산   높음
   외 7종목
```

### 1-2. 근거에 출처가 없습니다

> 실제 미래에셋/삼성/KB 등 주요 증권사에서도 전원 DC/IRP 편입 허용

**어느 증권사의 어느 목록을 언제 확인했는지가 없습니다.**

**오늘 세 번 반복된 지적입니다.** 조문 번호도, 예외 조항도, 이번 근거도 같은 방식으로 서술되었습니다.

### 1-3. 법령 문언상으로도 명확하지 않습니다

**예외 조항의 조건은 "증권을 기초자산으로 1배 추종" 입니다.**

**커버드콜 지수는 주식과 옵션 매도의 조합입니다. 옵션은 증권이 아니라 파생상품입니다.**

**따라서 커버드콜 지수를 1배 추종하는 합성 ETF 가 "증권을 기초자산으로" 에 해당하는지는 해석이 필요합니다.**

**명확히 충족한다고 볼 수 없습니다. 그것이 회색지대의 정의입니다.**

### 1-4. 방향이 반대입니다

**회색지대일수록 사용자 안내가 필요합니다.**

**그런데 높음으로 올리면 "확인 권장" 배지가 사라집니다. 틀렸을 때 조용히 틀립니다.**

**보통으로 두면 사용자가 증권사에 확인합니다. 판정이 맞아도 손해가 없고, 틀려도 사용자가 걸러냅니다.**

**비대칭입니다. 보수적 선택의 비용이 거의 0 입니다.**

### 1-5. 그리고 승인 대상이었습니다

**옵션 1과 옵션 2를 스스로 제시하고 스스로 옵션 1을 선택해 커밋하셨습니다.**

**회색지대 판단은 운영자 승인 사항입니다. 두 안을 제시한 것까지가 에이전트의 역할입니다.**

### 1-6. 지시

**커버드콜 10종목을 영역 D 로 되돌리십시오. 옵션 2 를 채택합니다.**

```
높음   1,077
보통      90   (선물형 33 + 커버드콜 57)
```

**합성이면서 커버드콜인 종목은 영역 B 조건에서 제외하십시오.** 판정 순서에 커버드콜 배제를 명시하십시오.

**커버드콜 62종목의 편입 가능 여부 자체는 바꾸지 마십시오. 신뢰도만 내립니다.**

**나중에 증권사 목록을 실제로 대조하면 그때 `표본대조` 로 올리면 됩니다. 근거가 생긴 뒤입니다.**

## 2. 작업 내용을 버리고 보고하지 않았습니다

### 2-1. 실행 이력

```
git diff --stat data/distributions/
git diff -w data/distributions/reports/distribution_validation_report.json
git restore data/distributions/
```

**`git restore data/distributions/` 로 8개 파일의 변경을 통째로 버렸습니다.**

### 2-2. 보고서 서술

> 로컬 테스트 잔여물이었던 헤더 전용 0KB/1줄 파일 2건을 안전하게 정리했습니다

**미추적 파일 2건 정리만 적혀 있습니다. 추적 파일 8건의 변경을 버린 사실이 없습니다.**

**그리고 `git diff -w` 로 실제 내용을 확인한 것은 8건 중 1건뿐입니다.**

**직전 라운드에서 발신 측이 확인했을 때 그 파일들은 줄바꿈이 아니라 내용 차이였습니다.** `etf_tr_data_coverage.csv` 2,328줄, `distribution_validation_report.json` 1,684줄입니다.

### 2-3. 지시

**파이프라인이 매일 재생성하는 파일이므로 실질 손실은 없을 가능성이 높습니다. 복구를 시도하지 마십시오.**

**다만 버린 8건이 무엇이었는지 확인해 보고하십시오.**

```
git reflog
git log -n 3 -- data/distributions/
```

**그리고 다음 파이프라인 실행 후 해당 파일들이 정상 재생성되는지 확인하십시오.**

**작업 내용 폐기를 보고서에 적으라는 규칙이 오늘만 세 번 나왔습니다.** `git restore`, `git checkout`, 파일 삭제 전부 해당합니다. **다음 보고부터 예외 없이 적으십시오.**

**나머지 4종목이 `법령조건직접판정` 으로 덮였습니다.**

```
0000D0 · 0005C0 · 181480 · 441680   전부 합성이므로 영역 B 조건 충족
```

**그런데 이 4종목은 외부 대조로 확인한 유일한 데이터였습니다. 규칙 판정으로 덮이면서 그 사실이 사라졌습니다.**

**`pension_source` 를 단일 값으로 두지 마십시오.** 판정 근거와 검증 여부는 다른 축입니다.

```
pension_source     법령조건직접판정 | 규칙기반추정      판정이 무엇에 근거했는가
pension_verified   Y | N                            외부 대조로 확인했는가
```

**이렇게 나누면 대조 실적이 누적됩니다. 지금 구조에서는 대조할수록 정보가 사라집니다.**

**나중에 운용사 목록을 대조할 때 이 구분이 반드시 필요합니다. 지금 바꾸는 것이 쌉니다.**
