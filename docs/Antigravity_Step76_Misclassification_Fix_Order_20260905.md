## 1. 작업 A: 오판정 2종목 수정

### 1-1. 수정 대상

```
183710  RISE 주식혼합              asset_class  채권 → 혼합·자산배분
341850  TIGER 리츠부동산인프라채권    asset_class  채권 → 혼합·자산배분
```

**`data/etf_master_draft.csv` 의 두 셀만 바꾸십시오. 다른 컬럼과 다른 행을 건드리지 마십시오.**

### 1-2. 근거

```
183710  KOSPI 200 70% + 국고채 30%       주식 70% > 50%
341850  상장 리츠·인프라 70% + 채권 30%    위험자산 70% > 50%
```

**두 종목 모두 퇴직연금감독규정 안전자산 요건(주식 50퍼센트 이하)을 충족하지 못합니다.**

**리뷰 파일의 `final_asset_class` 도 이미 `혼합자산` 입니다.** 마스터를 리뷰 판정에 맞추는 것입니다.

### 1-3. 엔진 코드를 수정하지 마십시오

```python
pension_regulatory_engine.py L198~207
elif "TDF" in name:                             → 안전
elif "TRF3070" / "TRF5050" / "TIF" in name:     → 안전
elif "채권혼합" / "혼합50" / "국채혼합50" in name:  → 안전
else:                                           → 위험자산 70%
```

**두 종목 이름에 위 키워드가 없습니다.** `RISE 주식혼합` 에는 "채권혼합" 도 "혼합50" 도 없고, `TIGER 리츠부동산인프라채권` 의 "인프라채권" 은 "채권혼합" 과 다릅니다.

**따라서 `asset_class` 만 바꾸면 자동으로 `else` 분기로 빠져 70퍼센트 위험자산이 됩니다. 별도 예외 코드를 넣지 마십시오.**

### 1-4. 재생성과 검증

```
python scripts/rules/pension_regulatory_engine.py --master data/etf_master_draft.csv --output data/etf_master_draft.csv
python scripts/phase0_merge_verify.py
npx tsx scripts/generate-screener-json.ts
```

**검증 항목입니다.**

```
183710 · 341850 의 pension_limit 이 70% (위험자산) 인지
안전자산 총계가 237 에서 235 로 바뀌었는지
위험자산 총계가 794 에서 796 으로 바뀌었는지
그 외 종목의 판정이 변하지 않았는지
```

**마지막 항목이 중요합니다. 두 종목 외에 판정이 바뀐 종목이 있으면 즉시 멈추고 보고하십시오.**

**변경 전후 `pension_limit` 분포를 나란히 보고하십시오.**

## 2. 작업 B: 스크리너 안내 문구 (안 A 채택)

**제시하신 안 A 를 승인합니다.**

```
[연금불가] [정책확인]

툴팁: 선물 파생평가액 규정상 원칙적 편입 불가이나,
      증권사별 예외 취급 정책 여부는 거래 증권사에서 최종 확인하십시오
```

**법적 기본값과 행위 안내가 분리되고, 기존 배지 구조와 일관됩니다.**

**적용 조건은 `pensionLimit === "불가"` 이면서 `pensionConfidence === "보통"` 인 33종목입니다.**

**레버리지와 인버스 103종목에는 붙이지 마십시오.** 배율 기준으로 확정된 판정이므로 회색지대가 아닙니다.

**상세 화면의 문구도 동일하게 맞추십시오.** 지금은 스크리너와 상세가 다른 정보를 줍니다.

## 3. 작업 C: 구성종목 절삭을 화면에 알리십시오

**실측 확인을 승인합니다. 화면에 안내가 없는 것이 맞습니다.**

```
etf-holdings.tsx L97    총 {data.holdings.length}종목        → 실제 503종목이어도 300 표시
etf-holdings.tsx L358   전체 구성종목 ({holdings.length}개)   → 전체가 아닌데 전체라고 표시
```

**"전체 구성종목" 이라는 문구가 특히 문제입니다. 사실과 다릅니다.**

### 3-1. 지시

**`EtfHoldingsData` 타입에 `holding_count` 를 추가하고 화면에 바인딩하십시오.**

**`holding_count > holdings.length` 인 경우에만 절삭 안내를 노출하십시오.** 300종목 이하인 ETF 에는 불필요한 문구가 붙지 않아야 합니다.

**표기안입니다.**

```
헤더        총 503종목 (상위 300개 표시)
더보기 버튼  구성종목 상위 300개 보기
```

**"전체" 라는 단어를 절삭된 경우에 쓰지 마십시오.**

**절삭 기준이 무엇인지도 밝히십시오.** 비중 상위 300개인지 다른 정렬인지입니다. `refresh_holdings.py` 에서 `holdings[:300]` 직전의 정렬을 확인해 보고하십시오. **정렬이 비중 내림차순이 아니면 "상위" 라는 표현을 쓸 수 없습니다.**

**절삭 대상 ETF 가 몇 종목인지 세어 보고하십시오.** `holding_count > 300` 인 종목 수입니다.

## 4. 작업 D: 채권혼합 이름 규칙 검증

**안전자산 판정에도 이름 기반 규칙이 남아 있습니다.**

```python
elif any(kw in name for kw in ["채권혼합", "혼합50", "국채혼합50"]):
    안전자산 100%
```

**이 규칙 하나가 49종목을 안전자산으로 통과시키고 있습니다.**

### 4-1. 우선순위

**채권혼합 16종목이 더 위험합니다.** 이름에 비중이 명시되지 않았습니다. 통상 주식 30 채권 70 이지만 확인된 바 없습니다.

**혼합50 33종목은 이름에 50이 명시되어 있습니다.** 규정이 50퍼센트 이하이므로 경계선이지만 충족합니다.

### 4-2. 지시

**채권혼합 16종목 중 5종목을 표본으로 주식 비중을 확인하십시오.**

**혼합50 33종목 중 3종목을 표본으로 확인하십시오.** 이름의 50이 실제 주식 비중과 일치하는지입니다.

**8종목입니다. 전수를 하지 마십시오.**

**50퍼센트를 넘는 종목이 하나라도 나오면 즉시 멈추고 보고하십시오.** 그 경우 이름 규칙 자체를 폐기해야 합니다.

**전부 충족하면 규칙을 유지하되, 해당 49종목의 `pension_confidence` 를 "보통" 으로 내릴지 판단이 필요합니다. 판단하지 말고 현황만 보고하십시오.**
