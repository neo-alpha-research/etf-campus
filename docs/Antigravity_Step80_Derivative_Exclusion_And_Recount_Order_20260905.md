## 1. 45건 중 42건은 오분류가 아닙니다

### 1-1. 파생형 ETF 는 실측이 자산군을 알려주지 않습니다

```
114800  KODEX 인버스
        원화현금                  99.99%
        2026-09 코스피200지수선물  -99.91%
```

**인버스 ETF 는 증거금만 현금으로 들고 선물 숏 포지션을 잡습니다. 구성종목이 현금 100퍼센트인 것은 정상 구조입니다.**

**자산군은 현금이 아니라 주식-국내가 맞습니다. 코스피 하락에 베팅하는 상품이기 때문입니다.**

**레버리지 18건도 같습니다.** 파생 100퍼센트에서 178퍼센트가 나오는 것은 구조 그대로입니다.

### 1-2. 실측 부적용 영역이 하나 더 생겼습니다

```
합성 ETF    99건   스왑이라 기초자산 미노출          이미 알고 있던 것
파생형 ETF  42건   증거금 더하기 선물 구조라 자산군 왜곡  이번에 드러난 것
```

**파생형에 실측을 적용하면 전부 오분류로 잡힙니다.**

### 1-3. 따라서 핵심 성과 지표를 다시 세야 합니다

**789건 중 실측이 주식이 아닌 건수는 45건이 아니라 3건입니다.**

```
480460  리츠 95.69%          진짜
400570  탄소배출권 98.69%     진짜
0036Z0 계열 원자재→주식 5건   진짜 (789건 밖일 수 있음. 확인 필요)
인버스·선물형 24건            파생 구조. 오분류 아님
레버리지 18건                파생 구조. 오분류 아님
460960                     39 대 37. 판정 불가 (아래 2-2)
```

## 2. 판정기를 두 곳 고치십시오

### 2-1. 파생 구조 제외 조건

**`abs(measured_derivative_pct) >= 20` 이면 실측 판정을 적용하지 마십시오.**

**`measured_applicable = "N"` 과 `measured_skip_reason = "파생구조"` 를 남기십시오.**

**임계값 근거입니다.** 일반 ETF 가 유동성 관리용으로 쓰는 선물은 통상 10퍼센트 미만입니다. 20퍼센트를 넘으면 파생이 운용 수단입니다.

```
114800  derivative -99.91   제외
122630  derivative 100.40   제외
143850  derivative  28.45   제외
0138Y0  국채선물 ETF 는 bond 로 분류되므로 derivative 에 안 잡힘   유지
```

**`risk_type` 으로 거르지 말고 실측값으로 거르십시오.** 이름이나 분류가 아니라 실제 구조로 판정하는 것이 이 작업의 취지입니다.

**임계값을 상수로 두고 주석에 근거를 남기십시오.**

### 2-2. 최대 자산군 판정에 하한을 두십시오

```
460960  ACE 글로벌인컴TOP10
        채권 39.10 / 주식 36.81 / 현금 24.04
        최대값이 채권이지만 39 대 37 입니다
```

**최대값 하나로 자산군을 정하면 이런 경우에 틀립니다. 사실상 혼합형입니다.**

**최대 자산군이 50퍼센트를 넘을 때만 판정하십시오.**

**미만이면 `measured_dominant = "혼합"` 으로 두고 불일치 목록에 넣지 마십시오.**

**근거는 과반입니다. 절반을 넘지 못하면 지배적이라고 할 수 없습니다.**

## 3. `unknown` 118건을 분해하십시오

**전체의 10퍼센트입니다. 원인을 알아야 판정기를 더 다듬을지 판단할 수 있습니다.**

**unknown 으로 남은 구성종목을 이름 기준으로 집계해 상위 30개를 보고하십시오.** 등장 횟수와 가중치 합계를 함께 적으십시오.

**다음 세 가지로 분류하십시오.**

```
국내 ETF 순환 참조 회피    의도적. 정상
패턴 누락                판정기를 다듬으면 잡힘
정말 판정 불가            남겨 둠
```

**두 번째가 많으면 패턴을 보강하십시오. 다만 기본값을 주식으로 두는 것은 여전히 금지입니다.**

## 4. 재집계

**2번 수정 후 전수를 다시 돌리고 다음을 보고하십시오.**

```
measured_applicable = Y 인 종목 수
파생구조로 제외된 종목 수
합성으로 제외된 종목 수
unknown 10% 초과 종목 수
최대 자산군 50% 미만으로 판정 보류된 종목 수
```

**그리고 789건 기본값 중 실측이 주식이 아닌 건수를 다시 세십시오. 이것이 진짜 성과 지표입니다.**

**131건 불일치도 다시 세십시오.** 파생형과 판정 보류를 제외한 뒤의 숫자입니다.

## 5. 그다음 3단계부터 5단계입니다

### 5-1. 설계 비중 대비 20퍼센트포인트 괴리 (Step79 §4-2)

**이름에 비중이 명시된 종목만 대상입니다.**

```
혼합50, 채권혼합50, 국채혼합50   주식 50%
TRF3070 / TRF5050 / TRF7030    주식 30 / 50 / 70%
```

**명시 비중과 `measured_equity_pct + measured_reit_pct + measured_commodity_pct` 의 차이를 산출하십시오.**

**20퍼센트포인트를 넘는 종목만 보고하십시오.**

**`measured_applicable = N` 인 종목은 제외하십시오.**

### 5-2. 실측 위험자산 70퍼센트 초과인데 안전자산 (Step79 §4-3)

**현재 `pension_limit` 이 100퍼센트 안전자산인 235종목 중, 실측 위험자산이 70퍼센트를 넘는 종목을 보고하십시오.**

**`183710` 과 `341850` 은 이미 수정되었으므로 목록에 없어야 합니다. 나오면 수정이 반영되지 않은 것입니다.**

**50퍼센트대나 60퍼센트대는 보고하지 마십시오. 판정하지 않습니다.**

### 5-3. `holdings_count` 5 미만 147건 (Step78 §6)

**합성 99건을 빼면 48건이 남습니다. 그 48건이 무엇인지 확인하십시오.**

**합성이 아닌데 구성종목이 5개 미만이면 홀딩스 수집 자체가 실패했을 수 있습니다.**

**티커, 종목명, `holdings_count`, 구성종목 전체를 목록으로 보고하십시오.**

## 7. 작업 규칙

**`risk_type` 이나 이름이 아니라 실측값으로 파생 구조를 거르십시오.**

**임계값 20퍼센트와 50퍼센트에 근거를 주석으로 남기십시오.**

**판정되지 않은 것을 주식으로 채우지 마십시오.**

**성과 지표를 부풀리지 마십시오.** 45건이 아니라 3건입니다. 실제 숫자를 쓰십시오.

**API 동시 호출은 8건 이하입니다.**

**작업 내용 폐기와 파일 삭제는 본문에 적으십시오.**

**`git add .` 과 `git commit -am` 을 쓰지 마십시오.**

**푸시 전에 보고하십시오.**

**명령을 `;` 로 연결하지 마십시오.**

**스크립트는 `scratch/` 안에 파일로 만들어 실행하십시오.** `holdings_asset_classifier.py` 는 정식 산출물입니다.

기존 파일을 통째로 다시 쓰지 말고 증분 편집만 하십시오.

`docs/Data_Catalog.md` 는 커밋 대상이고 `Antigravity_Step*.md` 는 커밋하지 마십시오.

보고 전에 `git status --porcelain` 과 `git log --oneline -n 5`, `git rev-parse --abbrev-ref HEAD` 를 실행해 출력을 붙여넣으십시오.

## 8. 진행 순서

**1단계.** 2-1 의 파생 구조 제외와 2-2 의 50퍼센트 하한을 판정기에 넣으십시오. **정답지 17종목 대조를 다시 돌려 여전히 통과하는지 확인하십시오.**

**2단계.** 3번으로 `unknown` 118건을 분해해 보고하십시오. **패턴 누락이 많으면 보강 후 다시 대조하십시오.**

**3단계.** 4번으로 재집계하고 성과 지표를 다시 보고하십시오.

**4단계.** 5-1 의 20퍼센트포인트 괴리 종목을 보고하십시오.

**5단계.** 5-2 의 70퍼센트 초과 안전자산 종목을 보고하십시오.

**6단계.** 5-3 의 48건을 확인해 보고하십시오.

**7단계.** 여기서 멈추십시오. `asset_class` 수정은 다음 지시입니다.

**1단계부터 3단계를 먼저 보고하십시오. 정답지 대조를 통과하지 못하면 그 지점에서 멈추십시오.**
