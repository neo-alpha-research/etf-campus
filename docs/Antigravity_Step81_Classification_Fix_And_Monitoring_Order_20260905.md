## 2. 작업 B: 적격 TDF 조문 확인

**보고서가 `퇴직연금감독규정 제9조의2` 를 일곱 번 인용했습니다. 근거가 없습니다.**

**"글라이드패스 초기 주식비중 80퍼센트 미만 요건" 도 출처가 없습니다.**

**결론 자체는 타당합니다.** TDF2060 이 주식 75퍼센트인 것은 설계상 정상이고, 적격 TDF 의 안전자산 인정은 확립된 사실입니다.

**다만 오늘 제9조와 제11조와 제12조로 세 번 정정했습니다. 같은 실수를 네 번째로 만들지 마십시오.**

**국가법령정보센터에서 적격 TDF 근거 조문을 확인해 조문 번호와 제목과 핵심 문장을 원문으로 보고하십시오.**

**확인되지 않으면 조문 번호를 빼고 "적격 TDF" 까지만 쓰십시오.**

## 3. 작업 C: 감시 체계 설계안 제시 (구현 금지)

**오늘 만든 실측 도구를 일회성으로 버릴지 상시 체계로 만들지 결정해야 합니다.**

### 3-1. 원칙

**실측을 판정에 쓰지 않습니다. 이상 탐지에만 씁니다. 이 원칙은 바뀌지 않습니다.**

**따라서 `measured_*` 를 `data/etf_master_draft.csv` 에 넣지 마십시오.** 마스터는 판정 입력이고, 감시 데이터가 섞이면 언젠가 판정에 쓰입니다.

**`data/regulatory/holdings_measured_composition.csv` 를 그대로 유지하는 것이 맞습니다.**

### 3-2. 검토할 것

**주기입니다.** 매일 1,167건 API 호출이 필요한지, 주 1회나 월 1회로 충분한지입니다. **구성종목은 매일 크게 변하지 않습니다. 판단 근거를 제시하십시오.**

**탐지 항목입니다.** 오늘 쓴 세 가지가 유효했습니다.

```
dominant 자산군과 asset_class 불일치
설계 명시 비중 대비 20%p 이상 괴리
안전자산인데 실측 위험자산 70% 초과
```

**세 가지를 유지할지, 임계값을 조정할지 제안하십시오.**

**알림 방식입니다.** 탐지되면 무엇을 할지입니다. 리포트 파일 생성인지, GitHub 이슈 생성인지, 워크플로 실패인지입니다.

**워크플로를 실패시키지 마십시오.** 이상 탐지가 파이프라인을 중단시키면 안 됩니다. 오늘 확인했듯 대부분은 정상 드리프트입니다.

### 3-3. 제출할 것

**설계안만 제출하십시오. 워크플로 파일과 스크립트를 만들지 마십시오.**

**주기, 탐지 항목, 임계값, 알림 방식, 예상 실행 시간 다섯 가지를 적으십시오.**
