## STEP 2 — 정렬·정규화 엔진 (순수 함수)

`lib/domain/normalize-series.ts` 를 신설하십시오. React 의존성 없는 순수 함수여야 하고, 여기에 테스트를 집중시킵니다.

```ts
export type SeriesInput = { ticker: string; dates: string[]; values: number[]; filled?: number[] };
export type NormalizedSeries = {
  ticker: string;
  points: { date: string; value: number | null; isFilled: boolean }[];
  terminalReturn: number | null;
  anchorDate: string;
  maxDrawdown: number;      // 음수 %, 선택 기간 내
  coverage: "full" | "partial" | "insufficient";
};
export function normalizeMulti(inputs: SeriesInput[], from: string, to: string): {
  series: NormalizedSeries[];
  anchorDate: string;
  truncated: { ticker: string; reason: "late_listing" | "data_floor" }[];
};
```

규칙 — 이대로 구현하십시오.

1. **달력**: 선택 구간 안에서 입력 종목들의 날짜 **합집합**을 오름차순 정렬해 공통 x축으로 씁니다. **교집합(inner join)을 쓰지 마십시오.** 한 종목의 거래정지가 다른 종목의 정상 데이터까지 지워버립니다.
2. **앵커**: `anchorDate` = 선택 구간 안에서 **모든 표시 대상 종목이 실제 값을 가진 첫 거래일**. 각 종목이 자기 시작일을 따로 앵커링하는 방식은 **금지**합니다. 서로 다른 기간을 비교하게 됩니다.
3. **정규화**: `R_t = (V_t / V_anchor - 1) × 100`. 앵커 값이 0 이하이거나 결측이면 그 종목은 `coverage: "insufficient"` 로 제외합니다.
4. **LOCF**: 합집합 달력에서 어떤 종목에 값이 없는 날은 직전 거래일 값으로 채우고 `isFilled: true` 를 세웁니다. 단,
   - 앵커 **이전**은 채우지 않습니다(`value: null`).
   - 해당 종목의 **마지막 실제 데이터 이후**는 절대 채우지 않습니다(`value: null`).
   - 연속 채움이 **5거래일을 초과**하면 그 구간 전체를 `isFilled: true` 로 표시해 STEP 3이 점선으로 그리게 합니다.
5. **신규상장 처리**: 종목의 첫 거래일이 요청 시작일보다 늦으면
   - 기본 동작: 그 종목을 포함해 `anchorDate` 를 뒤로 밀고(=공통 기간 자동 축소), `truncated` 에 `late_listing` 으로 기록합니다.
   - 축소 후 남은 거래일이 **20일 미만**이면 그 종목은 `coverage: "insufficient"` 로 차트에서 제외하고 사유를 반환합니다(실측 12종목 해당).
   - 축소 폭이 요청 기간의 **50%를 넘으면** `coverage: "partial"` 로 표시해 STEP 3이 경고 배너를 띄우게 합니다.
6. **하한**: 요청 시작일이 2023-01-02보다 이르면 2023-01-02로 클램프하고 `truncated` 에 `data_floor` 로 기록합니다.
7. **MDD**: 선택 기간 내 정규화 시계열의 최고점 대비 최대 낙폭을 계산해 반환합니다(STEP 5에서 씁니다).

**게이트**: `lib/domain/__tests__/normalize-series.test.ts` 에 최소 9건.
① 동일 길이 2종목 정상 ② 한 종목 중간 결측 → LOCF ③ 마지막 데이터 이후 미연장 ④ 신규상장 → 앵커 이동 ⑤ 20일 미만 → 제외 ⑥ 2023-01-02 클램프 ⑦ 앵커 값 0/음수 → insufficient ⑧ 5일 초과 연속 채움 → 구간 전체 filled ⑨ MDD 계산값 검증.

### 레이아웃 (모바일 360px 기준)

```
전체 높이 244px
  ├ 플롯 영역      176px
  ├ x축 라벨        24px
  └ 상/하 여백      44px
가로: 좌 여백 8 / 플롯 / 우 라벨 거터 60px  ← 뱃지는 거터에 두고 플롯 위에 겹치지 마십시오
```

- 기획서의 220px는 말단 뱃지를 겹쳐 그려야 나오는 수치입니다. 겹치면 마지막 20%의 궤적이 가려지므로 거터를 분리하고 244px를 쓰십시오.

### 그리기 규칙

- 선 두께 1.75px, `strokeLinejoin="round"`, `vector-effect="non-scaling-stroke"`. **곡선 보간 금지**(직선 연결만).
- 기준 종목(`base` 쿼리 파라미터 종목)은 2.25px + 팔레트 첫 색으로 고정.
- `isFilled` 구간은 `stroke-dasharray="3 3"` 으로 분리해 그립니다.
- 0% 기준선: 1px 실선, 그리드보다 진하게. y 그리드는 **최대 4개**, 점선.
- 면적 채움(area fill) 금지 — 3개 이상이면 뭉갭니다.
- 포커스(터치·호버) 시: 대상 선 2.5px, 나머지 1px + `opacity 0.3`.
- 색상: 현재 팔레트의 `#f59e0b`(amber)와 `#f43f5e`(rose)는 1.75px 선에서 구분이 흐립니다. 명도 대비를 벌린 5색으로 교체하고, 다크모드 토큰도 함께 정의하십시오.

### 말단 뱃지 충돌 회피

D3-force를 쓰지 마십시오. n ≤ 5의 1차원 라벨 분리 문제이므로 아래 결정적 알고리즘으로 충분합니다(약 20줄, O(n log n)).

```
1. 각 뱃지의 이상적 y = 해당 시리즈의 마지막 점 y
2. y 오름차순 정렬
3. 위→아래 1패스: prev.y + minGap(18px) 보다 작으면 아래로 밀기
4. 하단 경계 초과분을 위쪽으로 되밀기(역방향 1패스)
5. 상·하단 클램프
6. 변위가 4px를 넘은 뱃지에만 1px leader line을 실제 끝점까지 연결
```

- 수익률은 **소수점 1자리 유지**. +5.1% / +5.3% 를 반올림해 같은 값으로 만들지 마십시오.
- 뱃지에는 수치와 색만 넣고 순위 숫자("1위")는 넣지 마십시오(컴플라이언스).

### 모바일 인터랙션

- 크로스헤어 요약은 **차트 위에 떠 있는 팝오버가 아니라 플롯 상단의 고정 스트립**으로 렌더링하십시오. 244px 캔버스에서 플로팅 팝오버는 차트 대부분을 가립니다.
- 스트립 내용: 날짜 + 종목별 `색 점 · 종목 약칭 · 수익률`. LOCF로 채운 날이면 "직전 종가" 표기.
- 터치 이동 중 `touch-action: pan-y` 를 유지해 세로 스크롤을 막지 마십시오.
- 접근성: `<svg role="img">` + `aria-label` 에 "기간·기준·종목별 최종 수익률"을 텍스트로 요약하고, 시각장애 사용자를 위해 `<table class="sr-only">` 로 말단 수치를 제공하십시오.

### 툴바

360px 폭에 기간 5개 + PR/TR + PNG를 한 줄에 넣으면 터치 타깃이 32px 아래로 내려갑니다.

## STEP 4 — 상태 단일화

`compare-client.tsx` 를 최소 수정하십시오.

- `period`(기본 `3m`)와 기존 `isTrMode` 를 URL 쿼리와 동기화: `/compare?tickers=...&base=...&period=3m&basis=tr`
- `useSearchParams` 는 이미 임포트돼 있습니다(10행). 기존 `tickers`/`base` 파싱 로직 옆에 붙이십시오.
- 공유 URL 생성부(24~25행)에 `period`·`basis` 를 포함시키십시오.
- 데이터 페칭: 선택된 2~5종목의 v2 JSON을 **병렬 fetch**. 요청 기간이 1Y 이하면 `.recent.json`, 그 이상이면 전 구간 파일. 애그리게이터 API를 신설하지 마십시오(종목 조합이 캐시 키가 되면 에지 히트율이 0에 수렴합니다).
- 로딩 중에는 기존 막대 차트가 아니라 스켈레톤을 보여주고, fetch 실패 종목은 차트에서 빼되 **다른 종목의 차트는 정상 렌더**하고 실패 사유를 표기하십시오.

## STEP 5 — 비교표의 역할 분리 (중복 제거의 실제 해법)

## STEP 6 — TR 표기와 컴플라이언스

현재 토글 라벨은 `TR (배당 재투자)` 뿐이고, 실제로는 **세전(Gross)** 기준입니다. 세후 지수는 계산돼 있으나 화면에 없습니다. 수식이 아니라 표기가 문제입니다.

1. 토글 라벨을 **`TR (분배금 세전 재투자)`** 로 변경하십시오.
2. 세후(Net TR)를 **토글의 세 번째 상태로 만들지 마십시오.** 15.4%는 일반계좌 보유 개인 기준이고, 국내주식형 ETF의 매매차익 비과세·연금/ISA의 과세이연·금융소득종합과세 여부에 따라 실효세율이 달라집니다. 5종목을 한 규칙으로 세후 환산하면 서로 다른 세제를 같은 식으로 뭉개게 되고, 특정 투자자에게만 맞는 수치가 "그 ETF의 수익률"처럼 보입니다.
3. 차트 하단에 상시 각주 3줄을 고정하십시오.
   - 분배금은 분배락일 종가로 재투자했다고 가정한 이론 수치이며, 실제 지급일·재투자 시점·거래비용은 반영하지 않았습니다.
   - 세금은 반영하지 않은 세전 기준입니다. 계좌 유형에 따라 실제 세후 수익률은 달라집니다.
   - 과거 성과가 미래 수익을 보장하지 않습니다.
4. `hasDistribution: false` 인 207개 종목은 TR 모드에서 **"분배 이력 없음 (시장가격과 동일)"** 배지를 달아 주십시오. 파일이 없어서가 아니라 **원장에 이벤트가 0건이라서** 동일한 것임을 근거로 표기해야 합니다.
5. 순위·우열을 단정하는 문구("1위", "가장 우수한")를 차트·뱃지·요약 어디에도 넣지 마십시오. 수치와 색만 제시합니다.
6. 세후 기준은 별도 "계좌 유형 선택(연금·ISA·일반)" 기능으로 분리해 백로그에 남기고, 이번 단계에서는 구현하지 마십시오.
