# 마켓 브리핑 아카이브 구조 기획

작성일: 2026-08-26
작성 주체: EVS Navigator
목적: 거래일마다 쌓이는 마켓 브리핑을 SEO 자산으로 만들고, 목록 증가에 대응하는 구조를 확정

---

## 1. 먼저 해결할 충돌

### 1-1. `/briefing/[date]` 가 이미 다른 용도로 쓰이고 있습니다

저장소를 확인한 결과입니다.

| 경로 | 파일 | 데이터 출처 |
|---|---|---|
| `/briefing/` | `app/briefing/page.tsx` | **D1 마켓 브리핑** |
| `/briefing/2026-08-25` | `app/briefing/[date]/page.tsx` | **마크다운 콘텐츠** |

`[date]/page.tsx` 는 `lib/content/briefings` 를 읽습니다. `isLearningExample` 플래그와 "학습용 예시" 배지가 있는 것으로 보아 **교육용 예시 브리핑을 위한 별도 시스템**입니다.

**두 시스템이 같은 URL 네임스페이스를 씁니다.** 마켓 브리핑을 `/briefing/2026-08-25` 로 만들려면 충돌합니다.

### 1-2. 결정이 필요합니다

**운영자 판단 사항입니다.**

**가.** 학습용 예시를 다른 경로로 옮기고 `/briefing/{날짜}` 를 마켓 브리핑에 준다

**나.** 마켓 브리핑을 `/market-briefing/{날짜}` 같은 새 경로에 둔다

**다.** 학습용 예시를 폐지한다

**"가" 를 권합니다.** `/briefing/2026-08-25` 가 가장 자연스럽고 짧습니다. 학습용 예시는 개수가 적을 것이고 `/learn/briefing/{날짜}` 같은 곳으로 옮기면 됩니다.

**다만 학습용 예시가 몇 개이고 검색에 이미 잡혀 있는지 확인해야 합니다.** 이미 인덱싱되었다면 301 리다이렉트가 필요합니다.

## 2. 정적 export 제약을 먼저 이해해야 합니다

### 2-1. 확인된 설정

```typescript
// next.config.ts
output: "export"
trailingSlash: true
```

**정적 export 입니다. 서버 렌더링이 없습니다.**

`[date]/page.tsx` 에도 이미 이렇게 되어 있습니다.

```typescript
export const dynamicParams = false;
export function generateStaticParams() { ... }
```

**빌드 시점에 존재하는 날짜만 페이지가 생성됩니다.**

### 2-2. 이것이 뜻하는 바

**새 브리핑이 나오면 재빌드가 필요합니다.** Cloudflare Pages 가 git push 로 빌드하므로, 일간 워크플로가 데이터를 커밋하면 자동으로 재빌드됩니다. **이 흐름은 이미 작동합니다.**

**다만 내용이 HTML 에 박혀야 SEO 의미가 있습니다.** 클라이언트에서 API 를 불러 채우면 검색엔진이 빈 페이지를 봅니다.

**따라서 빌드 시점에 브리핑 내용을 가져와야 합니다.** 두 가지 방법이 있습니다.

**가.** 빌드 중 D1 API 를 호출해 내용을 가져온다. 빌드가 외부 API 에 의존하게 되고, API 가 죽으면 빌드가 깨집니다.

**나.** 워크플로가 브리핑 내용을 파일로 커밋하고, 빌드는 그 파일을 읽는다. 빌드가 자기완결적이고 이력이 git 에 남습니다.

**"나" 를 권합니다.** 마크다운 시스템(`lib/content/briefings`)이 이미 이 방식이며, 같은 패턴을 재사용할 수 있습니다.

**구체적으로는** 일간 워크플로가 발행 성공 후 `content/briefings/2026-08-25.md` 같은 파일을 생성해 커밋하는 것입니다. Pages 가 재빌드하면서 정적 페이지가 만들어집니다.

## 3. 삭제는 소프트 삭제가 불가능합니다

### 3-1. 확인된 제약

```sql
status TEXT NOT NULL DEFAULT 'ready' CHECK (status = 'ready')
```

**`status` 가 `'ready'` 외의 값을 받지 않습니다.** 상태를 바꿔 목록에서 숨기는 방법이 막혀 있습니다.

`as_of_date` 가 PRIMARY KEY 이므로 **한 날짜에 한 행만 존재할 수 있습니다.**

### 3-2. 따라서 삭제는 행 제거입니다

**연관 테이블을 함께 지워야 합니다.**

```
market_briefings              (주 테이블)
market_briefing_asset_classes
market_briefing_focus_etfs
```

**외래키 CASCADE 가 걸려 있는지 확인이 필요합니다.** 없으면 순서대로 지워야 합니다.

### 3-3. 이것이 8월 24일 정정 방법이기도 합니다

**8월 24일 브리핑에 8월 21일 지수 값이 들어가 있고, 중복 발행 가드 때문에 재발행이 막혀 있습니다.**

**행을 지우고 다시 발행하면 됩니다.** 별도의 정정 경로를 만들 필요가 없습니다.

**8월 19일, 8월 20일 삭제와 같은 작업입니다.** 하나의 삭제 절차로 세 가지가 해결됩니다.

## 4. 목록 증가 대응

### 4-1. 현재 상태

```javascript
// functions/api/briefings/history.js
const DEFAULT_LIMIT = 12;
const MAX_LIMIT = 31;
WHERE status = 'ready' ORDER BY as_of_date DESC
```

**넘칠 걱정은 없습니다. 최대 31건에서 잘립니다.**

**문제는 반대입니다. 31건을 넘어가면 옛 브리핑에 UI 로 도달할 방법이 없습니다.** 한 달 반이면 그 상태가 됩니다.

### 4-2. 단계별 대응

**1단계. 개별 페이지가 먼저입니다.** 각 브리핑이 고유 URL 을 가지면, 목록에 없어도 검색으로 도달할 수 있습니다. **이것만으로 접근 불가 문제의 절반이 해결됩니다.**

**2단계. 목록에 커서를 붙입니다.** `history.js` 에 `before=YYYY-MM-DD` 파라미터를 추가하고 "더 보기" 버튼을 답니다. 기존 `limit` 구조를 그대로 쓰면 됩니다.

**3단계. 월별 아카이브를 만듭니다.** `/briefing/archive/2026-08` 같은 경로에 그달 브리핑을 모읍니다. 정적 생성이므로 월별 페이지도 빌드 시점에 만들어집니다.

**4단계. 사이트맵에 넣습니다.** 검색엔진이 개별 브리핑을 발견하려면 필요합니다. 정적 export 이므로 빌드 시 생성하면 됩니다.

### 4-3. 메인 목록 노출 개수

**현재 12건은 적당합니다.** 다만 화면에 한 번에 다 보이면 길어지므로, **최근 5건만 펼치고 나머지는 접는 형태**를 권합니다.

## 5. 자동화 공백을 짚어야 합니다

**Private 로 되돌리면 GitHub Actions 무료 한도가 다시 적용됩니다.**

8월 청구 주기가 소진된 상태이며 **9월 1일경 복구됩니다.**

**따라서 Private 복귀 시점부터 9월 1일까지 스케줄이 돌지 않습니다.** 8월 26일, 27일, 28일 브리핑이 자동 생성되지 않습니다.

**선택지는 셋입니다.**

**가.** 9월 1일까지 Public 유지. 5일간 노출이 늘지만 자동화가 끊기지 않습니다.

**나.** Private 복귀 후 공백을 감수하고 9월에 소급 수집합니다.

**다.** Private 복귀 후 필요할 때만 잠시 Public 으로 전환해 수동 실행합니다.

**운영자 판단이 필요합니다.** 다만 브리핑을 SEO 자산으로 삼는다면 **날짜가 비는 것 자체가 손실**입니다.
