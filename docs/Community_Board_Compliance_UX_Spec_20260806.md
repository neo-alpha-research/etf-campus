작성일 2026-08-06 · 대상: 프론트엔드 구현 에이전트
전제: Next.js(App Router) + TypeScript. 아래 항목은 그대로 컴포넌트 단위 작업 지시로 사용 가능.

## 0. 시작 전 확정해야 할 분기 2가지

설계가 갈리므로 개발 착수 전에 운영자가 확정할 것.

| 분기 | A안 | B안 | UI 영향 |
|---|---|---|---|
| **챌린지 유료 여부** | 무료 | 유료(참가비·구독) | 유료면 "대가를 받고 불특정 다수에게 투자조언" 요건에 근접 → 유사투자자문업(자본시장법 제101조) 신고 검토 필요. 이 경우 §1의 게이트를 **전부 P0**로 올리고, Q&A 운영자 답변은 사전 검토 큐를 거쳐 발행 |
| **회원 간 1:1 기능** | 미구현(권장) | 쪽지·DM 제공 | DM을 열면 리딩방 유입 경로가 생기고 모니터링이 사실상 불가능 → **1인 운영에서는 미구현 강력 권장** |

**가장 큰 규제 리스크는 자유게시판이 아니라 4번 Q&A입니다.** 유사투자자문업으로 신고하더라도 *특정 개인의 상황을 전제로 한 1:1 조언*은 허용 범위를 벗어납니다(투자자문업 등록 영역). 따라서 Q&A는 "개별성 제거"를 UI 구조로 강제해야 합니다(§1-5).

## 1. 컴플라이언스 방어 UI

### 1-1. `TypeFirstComposer` — 빈 textarea를 없앤다

가장 효과적인 통제는 경고문이 아니라 **입력 형식 자체를 제한**하는 것입니다. "글쓰기" 버튼이 곧바로 자유 입력창을 열지 않게 합니다.

```
[글쓰기] 클릭
  → 유형 선택 시트 (3택)
     ① 오늘의 인증        → ChallengeSubmitForm (구조화 폼, 자유서술 최대 300자)
     ② 질문하기           → QuestionForm (개별성 게이트 포함)
     ③ 소통·후기          → FreeTalkForm (자유서술 최대 500자, 린터 최고 강도)
  → 유형별로 다른 폼 · 다른 경고 배너 · 다른 린터 프로파일 적용
```

- 유형 미선택 상태로는 본문 입력 불가
- 각 폼 상단에 유형별 고정 배너(`ComposerNoticeBanner`) — 닫기 버튼 없음
  - 인증: "수익률·평가금액·특정 종목명은 자동으로 가려집니다"
  - 질문: "개별 계좌·보유 종목에 대한 판단은 답변하지 않습니다"
  - 소통: "종목 추천·매수 권유는 즉시 블라인드 처리됩니다"

### 1-2. `ComplianceLinter` — 실시간 인라인 린터 (핵심 컴포넌트)

작성 중 `onChange` 디바운스 300ms로 검사, 매칭 토큰을 본문에서 하이라이트하고 하단에 사유를 인라인 표시. **제출 버튼 상태를 3단계로 제어.**

| 판정 | 트리거 예시 | UI 동작 |
|---|---|---|
| `BLOCK` | 매수/매도 권유형 어미, 목표가, 수익보장·원금보장, 외부 메신저 링크/아이디, 카톡·텔레그램·오픈채팅 문자열 | 제출 버튼 **비활성화** + 빨간 인라인 사유 |
| `WARN` | ETF 종목명·티커, 금액·수익률 숫자 패턴, "몰빵/풀매수/물타기" 등 | 제출 가능하되 노란 배너 + **자동 치환 제안 버튼** 노출 |
| `PASS` | — | 통과 |

**종목명 사전은 새로 만들지 말고 기존 자산을 재사용하십시오.** `data/etf_master_draft.csv`의 `ticker`·`name` 컬럼(1,150여 종)을 빌드 타임에 경량 트라이(trie) 또는 정규식 유니온으로 변환해 `lib/compliance/ticker-dictionary.ts`로 생성. 국내 개별주 종목명까지 필요하면 별도 사전 추가.

치환 제안 UX (서비스 철학 "종목이 아니라 기준"과 정확히 일치):

```
입력: "TIGER 미국S&P500 담았어요"
린터: ⚠ 종목명이 감지됐습니다.
      [ 자산군 표현으로 바꾸기 ] → "미국 대형주 지수형 ETF 담았어요"
```

클라이언트 린터는 UX용이며, **동일 규칙을 서버(또는 서버 액션)에서 반드시 재검증**할 것. 클라이언트만 두면 우회됩니다.

### 1-3. `SensitiveNumberGuard` — 금액·수익률 자동 마스킹

정규식으로 `숫자+원|만원|억`, `숫자+%`, `수익률|평가금액|잔고` 인접 패턴 감지 → 작성 모달에 **"금액 가리기" 토글을 기본 ON**으로 노출.

- ON 상태로 발행 시 렌더 결과: `+12.4%` → `▨▨%`, `3,200만원` → `▨▨▨만원`
- 작성자 본인에게만 원문 표시(툴팁 없이, 본인 뷰에서만)
- 목적: 수익률 자랑 → 타 참가자 유인 → 투자성과 광고처럼 작동하는 경로를 UI 레벨에서 차단

### 1-4. `ScreenshotRedactor` — 이미지 인증의 강제 마스킹 단계

계좌 캡처 업로드는 **컴플라이언스 + 개인정보 이중 리스크**입니다(계좌번호·성명·평가금액 노출). 업로드 즉시 다음 단계를 건너뛸 수 없게 합니다.

```
파일 선택
  → [1] EXIF 자동 제거 (클라이언트 canvas 재인코딩)
  → [2] 마스킹 에디터 오버레이 — 드래그로 검은 사각형 추가 (블러 아님, 복원 방지)
  → [3] 체크박스: "계좌번호·성명·평가금액을 가렸습니다" (미체크 시 [등록] 비활성화)
  → [4] 원본은 업로드하지 않음. 마스킹 적용된 canvas 출력만 전송
```

권장: 인증 과제는 가급적 **캡처 없이 구조화 입력으로 대체**(§2-1). 캡처가 꼭 필요한 과제만 이미지 필드를 허용.

### 1-5. Q&A 개별성 차단 — `QuestionIntentGate` + `AnswerTemplateLock`

**질문 작성 측 (`QuestionForm`)**

의도 분류 라디오를 필수로 두고, 위험 항목 선택 시 폼을 전환합니다.

```
질문 유형을 선택하세요
 ○ 제도·용어 (DC/IRP 규정, 세제, 용어 뜻)        → 정상 진행
 ○ 사이트 사용법                                  → 정상 진행
 ○ 상품 구조 일반 (환헤지란? TR과 PR 차이 등)     → 정상 진행
 ○ 내 계좌·내 종목을 봐주세요                     → 폼 잠금 + 안내 카드로 대체
```

마지막 항목 선택 시 입력창을 숨기고 안내 카드 표시: *"개별 계좌·보유 종목에 대한 판단은 제공하지 않습니다. 같은 궁금증을 일반적인 형태로 바꿔서 질문해 보세요."* + [일반 질문으로 바꾸기] 버튼(예문 3개 제시).

추가로 본문에 개인 상황 신호(`제 나이`, `잔고`, `저는 ~살`, 보유 종목명 + 물음표)가 감지되면 WARN. **나이·금액·보유종목 입력 필드를 애초에 만들지 마십시오.** 필드가 없으면 개별 자문 구성 자체가 어려워집니다.

**운영자 답변 측 (`AdminAnswerEditor`)**

- 답변 본문 상단에 **삭제 불가 고정 블록**이 자동 삽입되어 렌더됨(에디터에서 편집 불가 영역): *"본 답변은 일반적인 금융·제도 지식 전달이며 특정 상품의 매매를 권유하거나 개별 투자자에게 적합성을 판단해 드리는 것이 아닙니다."*
- 답변 에디터에도 §1-2 린터를 **가장 강한 프로파일**로 적용(운영자 발화가 가장 위험)
- 답변 템플릿 스니펫 버튼: `[제도 설명]` `[용어 정의]` `[답변 불가 - 개별 판단]` `[공식 출처 링크]`
- `답변 불가` 클릭 시 정형 문구가 자동 입력되어 1초 만에 종결 가능 → 1인 운영 부담 감소와 컴플라이언스가 동시에 해결됨

### 1-6. 외부 유입 경로 차단

- 회원 프로필에 **외부 링크·연락처 필드를 만들지 않음**(오픈채팅·텔레그램 유입 방지)
- 본문·닉네임·이미지 대체텍스트 전 영역에 URL/메신저 아이디 정규식 `BLOCK`
- 회원 간 DM·쪽지 **미구현**(§0 B안 채택 시에도 최소한 초기 코호트에서는 비활성)

### 1-7. 상시 고지 UI

- `StickyDisclaimerBar`: 커뮤니티 라우트 전역 하단 고정 24px 바 — *"본 서비스는 투자 권유·종목 추천을 제공하지 않습니다"* (스크롤해도 유지, 닫기 없음)
- `PostCard` 푸터: 수익률·숫자가 포함된 게시글 카드 하단에만 조건부로 *"과거 수익률은 미래 수익을 보장하지 않으며 추천이 아닙니다"* 캡션 자동 부착
- 커뮤니티 최초 진입 1회: 이용 규칙 모달(3개 체크박스 동의). 이후 재노출 없음 — 마찰은 최초 1회에만 배치하고 이후는 인라인 린터로 대체

### 1-8. `ReportButton` + 자동 블라인드

1인 운영에서 24시간 모니터링은 불가능하므로 회원을 감시망으로 활용합니다.

- 모든 게시글·댓글에 [신고] — 사유 프리셋 4개(`종목 추천/리딩`, `수익 인증 과시`, `외부 채널 유도`, `기타`)
- **서로 다른 사용자 3회 누적 시 즉시 자동 블라인드** → 관리자 큐 최상단으로 승격
- 블라인드 상태 UI: 본문을 가리고 *"신고 누적으로 검토 중인 게시물입니다"* + 작성자 본인에게는 열람 가능

### 1-9. 감사 로그

- 게시글 **수정 이력 전량 보존**(발행 후 본문 교체를 통한 우회 방지). 화면에는 "수정됨" 배지만 노출하고 이력은 어드민에서만 열람

## 2. 1인 운영 자동화 (일 30건을 5분 내 처리)

### 2-1. 과제 스키마 기반 동적 폼 — `challenge-tasks.json`

Day별 폼을 손으로 만들지 않습니다. 스키마 1개 파일에서 폼·검증·판정이 모두 파생됩니다.

```jsonc
{
  "day": 7,
  "title": "내 DC 계좌의 현재 자산배분 비중 확인하기",
  "verb": "확인",            // 화이트리스트: 확인 | 기록 | 학습 | 비교 | 점검
  "fields": [
    { "id": "done",    "type": "radio",  "label": "확인했나요?", "options": ["예", "아직"], "required": true },
    { "id": "ratio",   "type": "number", "label": "주식형 비중(%)", "min": 0, "max": 100, "required": true },
    { "id": "note",    "type": "text",   "label": "느낀 점", "maxLength": 300, "linter": "strict" },
    { "id": "capture", "type": "image",  "required": false, "redact": true }
  ],
  "autoPass": { "requireAll": ["done", "ratio"], "linter": "no-warn" }
}
```

**과제 설계 원칙(중요):** `verb`는 화이트리스트로 강제합니다. "확인·기록·학습·비교·점검"은 안전하지만, **"배분해보기·담아보기·매수해보기"는 사실상 투자 권유**가 되므로 과제 자체가 성립하지 않습니다. 스키마 검증 단계에서 금지 동사를 차단하십시오.

### 2-2. 3단계 자동 판정 규칙

| 판정 | 조건 | 처리 |
|---|---|---|
| `AUTO_PASS` | 필수 필드 충족 + 린터 무경고 + 중복 아님 | **즉시 게시·완주 카운트 반영**, 관리자 큐 미진입 |
| `REVIEW` | 린터 `WARN` 1개 이상 / 이미지 포함 / 자유서술 200자 초과 / 유사도 임계 초과 | 관리자 큐 진입, 게시 보류 |
| `BLOCK` | 린터 `BLOCK` / 필수 필드 미충족 | 제출 자체 불가, 인라인 사유 표시 |

목표 비율: `AUTO_PASS` 80% 이상. 그러려면 §2-1처럼 **자유서술을 줄이고 구조화 입력을 늘리는 것이 유일한 방법**입니다.

### 2-3. `AdminTriageQueue` — 키보드 우선 어드민

무한 스크롤 테이블이 아니라 **카드 스택 + 단축키**로 설계합니다.

- 단축키: `J/K` 이동, `A` 승인, `R` 반려(사유 팔레트 오픈), `B` 블라인드, `U` 직전 처분 취소
- 카드에는 판정 사유가 배지로 표시(`⚠ 종목명 감지` `⚠ 이미지 포함`) → 어디를 볼지 즉시 파악
- 반려 사유 프리셋 클릭 시 작성자에게 정형 안내가 자동 전달 + 재제출 링크 포함
- 하루 30건 중 `REVIEW`가 6건 내외로 떨어지면 **1일 3분 처리** 달성

### 2-4. 일괄 처리

- 큐 상단 [무경고 항목 전체 승인] — 조건: 린터 무경고 + 필수 필드 충족. 확인 다이얼로그 1회로 N건 승인
- 반대로 [신고 누적 항목만 보기] 필터

### 2-5. 완주율 · 이탈 감지

- `StreakGrid` (30칸 히트맵) 컴포넌트를 **참가자 마이페이지와 어드민에서 동일 컴포넌트로 재사용**
- 어드민 대시보드 상단: `오늘 제출 24/32 · 2일 연속 미제출 5명 · 검토 대기 6건`
- 2일 연속 미제출 자동 리스트 + [리마인드 발송] 원클릭(이메일 정형 문구)

### 2-6. 중복·복붙 감지

직전 3일간 제출 본문과 정규화(공백·기호 제거) 후 자카드 유사도 0.9 이상 → `REVIEW`. 성의 없는 반복 제출로 완주율이 왜곡되는 것을 막습니다.

## 3. 코호트 활성화

### 3-1. 게시판 5개 → **탭 3개 + 전역 버튼 1개**로 재편 (가장 중요한 제안)

초기 코호트(수십 명) 기준 게시판 5개는 **네 개가 비어 보이는 결과**를 낳습니다. 빈 게시판은 커뮤니티가 죽었다는 신호로 읽혀 이탈을 가속합니다.

| 현재 | 변경안 | 근거 |
|---|---|---|
| ① 공지·자료실 | **탭1 "공지·자료실"** 유지 | 리드마그넷 전환 지점, 유지 필요 |
| ② 30일 인증 | **탭2 "챌린지 피드"** — ③을 여기로 흡수 | 트래픽 집중 |
| ③ 자유 소통 | **폐지 → 탭2의 댓글·응원 레이어로 흡수** | 독립 자유게시판은 트래픽이 가장 적으면서 **리딩 리스크는 가장 큼**. 자유 서술 공간을 줄이는 것이 컴플라이언스에도 유리 |
| ④ ETF/연금 Q&A | **탭3 "Q&A"** 독립 유지 | 면책 UI·답변 템플릿이 완전히 달라 통합 시 통제가 흐려짐 |
| ⑤ 오류 제보 | **게시판 폐지 → 전역 플로팅 버튼 + 비공개 폼** | 애초에 열람 대상이 없어 게시판일 이유가 없음. 우측 하단 고정 버튼이 제보율도 높음 |

부수 효과: 관리 대상 화면이 5개 → 3개로 줄어 1인 운영 부담이 그대로 감소합니다.

### 3-2. 리액션 설계 — 좋아요를 쓰지 마십시오

일반적인 [좋아요]는 **수익률 자랑 글에 반응이 몰리는 구조**를 만들어 컴플라이언스와 정면 충돌합니다.

- 리액션은 **단일 버튼 「같이 하고 있어요」**(👊 응원). 카운트만 표시, 순위 집계에 미사용
- 인기순 정렬 **미제공**(최신순·Day순만). 인기순은 곧 수익률 랭킹으로 수렴함
- 댓글은 1단계만(대댓글 없음) — 모니터링 범위 축소

### 3-3. 스트릭 + 복구권 — 이탈 방지 장치

30일 챌린지의 최대 적은 "하루 빠뜨린 뒤 포기"입니다.

- `StreakCounter`: 연속 제출일 표시
- **`StreakFreeze` 월 2회**: 하루 빠져도 스트릭 유지. "복구권 2개 중 1개 사용됨" UI로 명시 → 심리적 완주 가능성 유지
- 지난 Day **소급 제출 허용**(늦은 참여자·복귀자 흡수). 카드에 `Day 5 · 늦은 인증` 중립 배지, 페널티 표현 금지

### 3-4. `CohortProgressBar` — 사회적 증거

피드 최상단 고정: **"3기 32명 · 오늘 24명 제출(75%) · 평균 진행 Day 12"**

개인 순위가 아니라 **집단 진행률**을 보여주는 것이 핵심입니다. 개인 랭킹은 상위권만 동기부여되고 하위권을 이탈시킵니다.

### 3-5. 배지 시스템 — 성과가 아닌 행동에 부여

수익률·수익금 기반 배지는 **절대 만들지 마십시오.** 행동 기반만 허용합니다.

| 배지 | 조건 |
|---|---|
| 첫걸음 | Day 1 제출 |
| 일주일 | 7일 연속 |
| 반환점 | Day 15 도달 |
| 완주 | 30일 중 25일 이상 제출 |
| 길잡이 | 타인 인증글에 응원 댓글 10회 |
| 질문왕 | Q&A 유효 질문 5건 |

`길잡이`·`질문왕`은 **운영자 개입 없이 커뮤니티가 굴러가게 하는 유일한 레버**이므로 반드시 포함하십시오.

### 3-6. 운영자 존재감 자동화

- 어드민 큐에서 승인 시 **정형 응원 코멘트 원클릭 삽입**(5종 로테이션). 초기 코호트에서는 운영자 반응 1회가 리텐션에 가장 큰 영향을 주지만, 30건에 직접 코멘트를 다는 것은 지속 불가능
- 주 1회 자동 생성 리캡 카드: "이번 주 우리 기수 제출 168건 · 완주 예상 78%" → 공지 탭 자동 게시(운영자 승인 후 발행)
