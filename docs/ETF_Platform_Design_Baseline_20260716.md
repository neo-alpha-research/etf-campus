# ETF 플랫폼 설계 기준 문서 (Design Baseline)

작성일: 2026-07-16
작성 주체: EVS Navigator
승인 주체: 운영자
문서 지위: 본 프로젝트(유력안 ETF캠퍼스, 구 가칭 알파컴퍼스)의 설계 SSOT. 이후 모든 기획·개발 결정은 본 문서를 기준으로 하며, 변경 시 §12 결정 대장에 기록 후 본문을 갱신한다.
주의: 서비스명 "ETF캠퍼스"는 상표·도메인 확인 미완 상태의 유력안. 확정 전 대외 노출 금지.

## 1. 서비스 정의

국내 상장 ETF 투자자를 위한 독립 정보 창고이자 커뮤니티. 로그인 없이 도달하여 ETF 시세·수익률·분류 정보를 조회하고, 투자 기준(원칙)을 배우며, 이후 단계에서 기준 중심 커뮤니티에 참여하는 웹 서비스.

**커버 범위**

- 대상 상품: 국내 상장 ETF 전체 (일반 계좌 + 연금 계좌 통합 설계). 단 유동성 기준 미달 종목은 기본 목록에서 제외한다 (§5.1 배제 기준)
- 초기 소구점: DC/IRP 연금 특화 (마케팅·콘텐츠의 창끝)
- 해외 상장 ETF: Phase 4 이후 별도 결정 (본 문서 범위 외)

일반과 연금을 처음부터 하나의 데이터 모델로 설계한다. 연금은 별도 서비스가 아니라 전체 ETF 데이터 위에 얹힌 "필터·맥락 레이어"다. 이렇게 설계하면 초기에는 연금 특화로 소구하고, 이후 일반 투자 전체로 확장할 때 구조 변경이 없다.

**플랫폼 형태** (2026-07-19 정정): Phase 1은 반응형 웹까지 (PWA manifest·서비스 워커 미도입 — 정적 사이트에 SW 캐싱은 갱신 이슈 대비 이득이 작음). PWA는 Phase 1.5~2, 앱은 Phase 3 Capacitor 래핑.

## 2. 포지셔닝

**한 문장**: 발행사도, 증권사도, 일임업자도 아닌 — 투자자 편에 서서 기준을 가르치는 유일한 독립 ETF 플랫폼.

**경쟁 지형과 공석**

| 서비스 | 운영 주체 | 성격 | 구조적 한계 |
|--------|----------|------|------------|
| ETF CHECK | 코스콤 (준공공 인프라) | 데이터 완전체 | 관점·의견·교육을 실을 수 없음 |
| FunETF | 삼성자산운용 (발행사) | 콘텐츠 풍부 | 자사 상품 중심 편향 불가피 |
| K-ETF | ETF Lab (독립 소규모 팀) | 웹 + 유튜브 | 우리와 동일 체급의 최근접 경쟁자 |
| fint | 로보어드바이저 (투자일임업) | 직접 운용 | 다른 규제 카테고리, 경쟁 대상 아님 |
| justETF (해외) | 독립 | 스크리너 + 지식 베이스 | 참조 모델 (유럽에서 독립 포지션 입증) |

데이터 완성도로는 코스콤을 이길 수 없다. 데이터는 체류를 위한 기본기로 두고, 승부처는 아래 3개다.

1. **연금 맥락 깊이**: 가능/불가 표시를 넘어 위험자산 70% 한도·안전자산 30% 구성·계좌별 세제 맥락까지 통합한 정보 설계 (경쟁 전무)
2. **기준(원칙) 지식 베이스**: "그래서 어떤 기준으로 고르는가"를 가르치는 justETF형 교육 레이어. "어려운 것은 쉽게" 원칙의 구현
3. **기준 중심 커뮤니티**: 종목 토론이 아니라 규칙·기준을 공유하는 판 (Phase 2)

**표준 카피 방향** (주식은안물어요 사례 차용): "추천하지 않습니다"를 명시하는 포지션 선언 + 전 페이지 푸터 면책 문안("본 서비스는 투자 권유·종목 추천을 제공하지 않으며, 모든 투자 판단의 책임은 이용자 본인에게 있습니다"). 문구 확정은 법률 검토 게이트 통과 후.

## 3. 3대 최상위 원칙과 컴플라이언스 경계

우선순위: 컴플라이언스 > 어려운 것은 쉽게 > 정확성 (브랜드 헌장과 동일)

**허용 / 금지 경계표**

| 구분 | 허용 | 금지 |
|------|------|------|
| 데이터 표시 | 종가·수익률·분배율 등 공시 사실의 표·차트 | 매수/매도 신호, 목표가, 점수·등급 부여 |
| 포트폴리오 | 자산군 수준 배분 가이드 (예: 주식형 70·채권 20·대체 10) + 해당 자산군 ETF "전체 목록" 필터 연결 | 특정 ETF 조합의 모델 포트폴리오 제시 (= 투자 권유 회색 지대) |
| 시황 브리핑 | 종가 데이터에 근거한 현상 서술 (무엇이 얼마나 움직였다) | 전망·예측·행동 제안 ("담을 때다", "비중 확대 유효") |
| 사용자 데이터 | 없음 (Phase 1), 비회원 이메일 브리핑 구독 정보 (Phase 1.5), 소셜 로그인 계정 (Phase 2) | 증권사 계좌 연동·잔고 조회 (마이데이터 허가 영역, 영구 제외) |
| 수익화 | 도서 제휴 링크, 광고 표기된 운용사 광고, 프리미엄 교육 콘텐츠 | 투자일임·자문형 유료 서비스 (라이선스 영역, 로드맵 제외) |

**법률 검토 게이트** (2026-07-18 확장): Phase 1 공개 전 1회 필수. 검토 항목 — 자산군 가이드 표현 수위, 시황 브리핑 자동 생성물의 유사투자자문 해당 여부, AI기본법(2026-01 시행) 생성형 AI 산출물 표시 의무, 면책 문안, 제휴 링크 표기. 추가 게이트 — Phase 2 유료 상품·운용사 광고 개시 전 법률 재검토 1회 필수 (무료 단계에서 적법하던 화면이 유료화 결합 시 판단이 달라질 수 있음 — 검토 시점을 리스크 발생 시점에 정렬)

**고지 위치 규칙** (2026-07-18 신설): 푸터 전 페이지 면책 외에 — ① 수익률 랭킹·상위 목록 테이블 직하단 1줄 고지("과거 수익률은 미래 수익을 보장하지 않으며 추천이 아닙니다") ② 이미지형 산출물(온보딩 결과 카드·브리핑 공유 카드)은 이미지 내부에 면책 1줄을 굽는(bake-in) 규칙 — 이미지 단독 유통 시 고지 소실 방지

**수익률 표기 원칙** (2026-07-16 확정): 기본 가격수익률, 라벨에 "가격 기준·분배금 미포함" 명시. 총수익률 토글과 월배당·커버드콜 유형의 분배율 병기는 Phase 2 안건.

## 4. 내부 자산 현황과 콘텐츠 루프

**보유 자산 (2026-07-16 실사 기준)**

1. 전자책 — 크티 등재본과 연동 (수수료 우위로 크몽 아닌 크티 채택, 2026-07-16 운영자 확정)
2. 웹소설 「알파를 읽는 자」 — 문피아 작품 홈 직결
3. Threads 마케팅 퍼널 (@neo.alpha.reader — 2026-07 2주차 가동, 유일한 활성 유입 채널)

Tistory·YouTube는 현재 활성 자산이 아니므로 본 설계는 Threads 단일 퍼널을 전제로 한다. K-ETF의 웹·유튜브 루프 모델은 참조하되, 우리의 루프는 "Threads ↔ 웹"으로 시작한다.

**퍼널 확정 문장 (2026-07-16)**: Threads는 시황·ETF 콘텐츠에 집중하여 유입을 만들고, 웹은 정보 창고로 체류를 만들며, 웹 안에서 웹소설(문피아)·전자책(크티)에 자연 노출시킨다.

**콘텐츠 루프 설계**

- 유입: Threads 글 (시황·ETF 집중) → 웹 화면 (시황 브리핑·대시보드·자산군 가이드)이 종착지
- 재확산: 웹의 자동 시황 브리핑 → Threads 공유본 생성 (아래 표현 수위 규칙 적용)
- 심화: 웹 방문자 → 웹소설·전자책 노출 (북 큐레이션·시황 브리핑 하단·저자 코너 등 상시 동선)

**Threads 표현 수위 (2026-07-16 개정)**: 웹·Threads 모두 공시 데이터에 기인한 사실 서술로서 ETF 상품명·수익률 병기를 허용한다. 종전 "Threads 상품명 지목 금지" 레드라인은 마감 데이터 인용 콘텐츠에 한해 다음 가드레일로 대체한다.

1. 수치는 공시 종가 데이터만 인용하고 출처·기준일 명시
2. 평가·전망·행동 제안 문장 0건 (사실 나열까지만)
3. 특정 종목 단독 부각 대신 표·목록 형태 (수익률 상위 5 등 기계적 기준)
4. 운영자 보유 여부 비공개 원칙 유지
5. 수익 보장·성과 단정 표현 금지 (기존 레드라인 유지)

본 개정은 Threads 표준 문서(SOP·성장 계획·모멘텀 메모)와 상충하므로, 해당 문서들의 동시 개정이 필요하다 (§11 미결 사항). 시황 인용 외 콘텐츠(관점·서사 글)는 종전 레드라인이 그대로 유지된다.

## 5. 핵심 기능 설계 — Phase 1 (비로그인 MVP)

### 5.1 ETF 대시보드 (기본기)

- 전 국내 상장 ETF 목록: 종가, 등락률, 거래대금, 1/2/3/6/12개월 가격수익률 (2026-07-16 기간 확정)
- 2축 분류 상시 노출: 레버리지·인버스 구분 배지 / 연금(DC/IRP) 편입 가능 배지
- 자산군 분류 (주식-국내, 주식-해외, 채권, 금리·파킹, 원자재, 리츠, 혼합 등)
- 정렬·랭킹: 기간별 수익률, 거래대금

**노출 계층 기준 (2026-07-17 전면 개정 — 큐레이션 철학 채택)**

서비스 목적을 "모든 ETF 데이터"가 아니라 "의미 있는 ETF"로 확정한다 (2026-07-17 운영자 결정). 무엇을 기본 화면에 올릴지 거르는 것 자체가 첫 번째 기준 교육이며, EVS의 큐레이션 포지션과 정합한다. 3계층 구조로 운영한다.

- 계층 1 — 기본 화면: 순자산총액 500억원 이상 (상장 기간 무관, 신규 상장 포함. 현재 604종목). 기관 편입·유동성 실무에서 통용되는 규모 기준
- 계층 2 — 전체 보기 토글: 순자산 100억~500억 종목 포함 노출. 100억 미만(158종목)은 토글 내에서도 "소규모 유의" 표시 (근거: 상장폐지 요건 50억의 2배 버퍼)
- 계층 3 — 신규 상장 메뉴 (2026-07-18 기간 조정 확정): 상장 3개월 미만이면서 순자산 100억원 이상인 종목의 별도 메뉴 (현재 60종목 규모). 500억을 넘기면 기본 화면에도 동시 노출. 3개월 근거 — "신규"라는 이름값과 시간 감각 일치, 신규 상장 캘린더·시황 브리핑의 신규 알림과 정합, 메뉴 볼륨 적정. 3~12개월·100~500억 구간은 전체 보기 토글에서만 노출 (검증 대기 구간으로 간주, 큐레이션 철학과 정합)
- 구현 요건 (2026-07-18 정정): 상장일 원천 API 부재 확인(KRX상장종목정보는 주권 전용). 시세 API 최초 시세 존재일로 first_traded_date를 근사 산출하고, 신규 진입 종목만 KRX 정보데이터시스템 ETF 상세에서 상장일 수기 1회 보정 (Spec §4 절차 참조)
- 거래량 기준은 Phase 1에서 사용하지 않는다. ETF는 LP 호가 의무가 있어 거래량과 실체결 가능성의 상관이 주식과 다르고, 임계선이 자의적이라 방어가 어렵다. Phase 2에서 공시 괴리율 데이터 확보 후 "괴리율 유의" 배지로 대체
- 기준 안내 페이지 상설: "왜 500억인가"를 설명하는 페이지 자체를 콘텐츠로 운영. 숨기는 것이 아니라 걸러주는 것임을 명시
- 적용 범위: 전 종목 일괄 적용, 데이터는 전 종목 수집 유지 (노출만 계층화)

### 5.2 스크리너 (justETF 차용 — 구현 제안)

justETF 필터 체계를 국내 실정에 맞게 축소 이식한다. Phase 1 필터 6종:

1. 계좌 유형 (전체 / 연금 가능만) — 우리의 시그니처 필터, 최상단 고정
2. 자산군 (§5.1 분류와 동일 체계)
3. 위험 유형 (일반 / 레버리지 / 인버스)
4. 총보수 구간
5. 분배 방식 (분배형 / TR·재투자형)
6. 순자산 규모 구간

구현 방식: 마스터 테이블의 태그 컬럼 조합 쿼리이므로 개발 난이도 낮음. 핵심은 UI가 아니라 태그 데이터의 정확성이다 (§7).

### 5.3 비교 기능 (2026-07-18 이월 확정 — Phase 1.5)

출시 범위에서 제외하고 Phase 1.5에 2종 비교로 도입한다 (ETF CHECK는 4종). 비교 항목: 총보수, 기간 수익률, 순자산, 연금 가능 여부, 자산군. 스크리너·상세 페이지가 안정된 후 붙이는 것이 순서다.

### 5.4 캘린더 (2026-07-18 이월 확정 — Phase 1.5)

분배금 지급 + 신규 상장 캘린더. 예탁결제원 API 신규 연동이 필요한 별도 파이프라인이므로 출시 범위에서 제외하고 Phase 1.5에 도입한다. 신규 상장 정보는 Phase 1에서도 신규 메뉴(§5.1 계층 3)가 부분 대체한다.

### 5.5 자동 시황 브리핑 (신규 확정 — 차별화 콘텐츠)

일일 종가 배치 완료 후 자동 생성·게시하는 "ETF 투자자용 마감 브리핑". ETF 투자자가 원하는 정보만 추린다:

- 자산군별 등락 요약 (주식·채권·원자재·리츠 등 무엇이 올랐고 내렸나)
- 거래대금 상위·수익률 상위/하위 ETF (사실 나열)
- 연금 계좌 관점 한 줄 (연금 가능 ETF 중 움직임이 큰 자산군)
- 분배금·신규 상장 일정 알림 (캘린더 연동)

발행 시각 권고 (2026-07-17 Navigator, API 실측 근거): 금융위 시세 API는 T+1 정오까지도 전일 데이터가 미적재될 수 있음을 확인했다. 따라서 시황 브리핑은 "당일 저녁 마감 브리핑"이 아니라 "전일 마감 브리핑을 다음 날 아침 발행"으로 설계한다. Threads 평일 아침 08:30 슬롯과 정합하며, 데이터 적재 시점 리스크가 사라진다. (단, 실제 적재 시각은 1주일 관측 후 확정)

생성 구조는 이택기 사례(수집 → 작성 → 리뷰어 검수 → 발행) 차용. 컴플라이언스 규칙을 리뷰어에 강제한다: 전망·행동 제안 문장 0건, 모든 수치는 원천 데이터 대조, 미검증 수치는 게시 차단. Threads 공유본은 §4 개정 표현 수위(사실 기반 상품명·수익률 병기 허용 + 가드레일 5항)에 따라 웹 본문에서 자동 요약 생성한다.

### 5.6 투자 스타일 진단 온보딩 (주식은안물어요 차용 + 2026-07-16 운영자 확장)

첫 방문 시 재미 요소를 갖춘 간단 설문으로 ETF 투자 스타일을 판정하고, 가이드와 "다음 볼 곳"을 안내한다.

- 문항: 선택형 3~5문항, 이메일·로그인 없음 (① 투자 계좌: 연금/일반/둘 다 ② 투자 성향 ③ 경험 수준 + 재미 문항 1~2개)
- 결과 카드: 스타일에 이름을 붙여 판정 (예: "천천히 쌓는 성벽형"). 8인 캐릭터 유니버스와 결합하면 차별화 극대화 — 스타일별 담당 캐릭터가 결과를 전달하는 방식 검토
- 다음 동선 안내: 결과 카드에서 곧바로 ① 내 스타일의 자산군 가이드 ② 스크리너 프리셋 결과 ③ 추천 첫 화면(시황 브리핑 등) 3개 버튼 제공. "판정 → 가이드 → 다음 볼 곳"의 3박자를 한 화면에서 완결
- 재방문자 처리: 응답·결과를 브라우저 로컬 저장(서버 미수집). 재방문 시 설문을 띄우지 않고 상단에 "내 스타일: OO형" 칩만 표시, 클릭 시 결과 재열람·재진단 가능. 첫 방문에도 "건너뛰기" 상시 제공
- 결과 카드의 이미지 저장·공유 기능은 Phase 2로 이월 (2026-07-18 과설계 제거 — 캔버스 렌더·면책 bake-in 구현 비용 대비 출시 우선순위 낮음. 도입 시 §3 고지 bake-in 규칙 적용). Phase 1은 화면 표시까지만

Phase 1.5 연결 (2026-07-22 운영자 확정): 진단 결과 확인 후 `주간 ETF 브리핑 받기`를 선택 동선으로 제공한다. ETF 검색과 진단 결과 열람에는 구독을 요구하지 않는다. 이메일과 선택 설문 정보의 연결은 이용자가 명시적으로 동의한 경우에만 수행한다.

### 5.7 자산군 포트폴리오 가이드

투자 성향별 자산군 배분 예시(비율만) + 각 자산군 클릭 시 스크리너 필터 결과로 연결. 표현 프레임은 VMD 3층 구조(거의 불변인 원칙 / 정보 따라 가변 / 매일 갱신) 차용. 특정 ETF 조합 제시 금지 (§3).

### 5.8 북 큐레이션

기준·원칙 중심 도서 선별 + 운영자 코멘트. 알라딘·쿠팡파트너스 제휴 링크(광고 표기 필수). 첫 수익원.

### 5.9 비회원 이메일 브리핑 구독 (2026-07-22 신설 — Phase 1.5)

초기 전환 기능은 회원 로그인 대신 이메일 이중 확인(double opt-in)을 사용하는 비회원 구독으로 구현한다. 비밀번호·소셜 로그인·자체 회원 계정은 만들지 않으며, ETF 검색·상세·콘텐츠 열람은 계속 비로그인으로 제공한다.

- 구독 가치: 주 1회 ETF 시황, 신규 상장 ETF의 사실 정보, DC·IRP 편입 상태 변경, 투자 기준 콘텐츠. 신규 ETF는 상장일·자산군·기초지수·순자산·거래대금·위험유형·연금 편입 여부·확보된 기간 수익률만 다루며 추천·전망 표현을 금지한다.
- 필수 수집: 이메일, 이메일 인증 여부, 구독 상태, 동의 일시·동의문 버전. 선택 수집: 관심 계좌(일반·연금저축펀드·DC·IRP·ISA), 관심 분야, 투자 경험, 연령대·성별(응답 안 함 포함). 정확한 생년월일·전화번호·주소·직장·소득·투자금액·보유종목·금융회사·계좌번호는 수집하지 않는다.
- 동의 분리: 브리핑 수신을 위한 개인정보 수집·이용, 선택 프로필 활용, 광고·이벤트 수신을 각각 분리한다. 선택 항목 미동의로 기본 브리핑 구독이나 공개 서비스 이용을 제한하지 않는다.
- 운영 구조: 검증된 관리형 이메일 발송 서비스의 호스팅 폼·구독자 저장소를 사용해 사이트의 정적 SSG 구조와 자체 DB 무도입 원칙을 유지한다. 모든 이메일에 구독 설정·즉시 해지 링크와 투자 비추천 고지를 포함한다.
- 보안: 비밀번호를 저장하지 않고 운영자 계정 MFA, 최소권한, 키의 서버 전용 보관, 전송·저장 암호화, SPF·DKIM·DMARC, 동의 이력, 삭제·내보내기 절차를 출시 조건으로 둔다. 처리업체·보관기간·국외 이전 여부는 도입 전 개인정보처리방침과 함께 확정한다.

## 7. 데이터 파이프라인

**원천 데이터 (전부 무료 공공 API)**

| 데이터 | 소스 | 용도 |
|--------|------|------|
| ETF 종가·등락·거래대금 | 금융위원회 증권상품시세정보 API (data.go.kr) | 대시보드·수익률·시황 브리핑 |
| 상장 종목 마스터 | 금융위원회 KRX상장종목정보 API | 마스터 테이블 기초 |
| 분배금 이력·일정 | 한국예탁결제원 주식정보서비스 API | 캘린더 (Phase 1.5), 총수익률 (Phase 2) — Phase 1 미연동 |

**일일 배치 (에이전트 아닌 단순 스크립트로 구현 — 과설계 금지)**

장 마감 후 1회: 시세 수집 → 수익률 계산 → 마스터 테이블 갱신 → 시황 브리핑 생성(이 단계만 LLM) → 검수 → 게시.

**ETF 마스터 테이블 — 태그 3종이 서비스 품질의 전부**

1. 위험 유형 태그 (일반/레버리지/인버스): 종목명·기초지수 규칙으로 자동 분류
2. 연금 편입 가능 태그: 규칙 기반(파생형·레버리지·인버스 제외 등) 1차 자동 분류 + 수동 검수. 자동 제공되는 원천 데이터가 없으므로 이 수작업 자체가 해자다
3. 자산군 태그: 기초지수·상품명 기반 분류 + 수동 검수

**정확성 규칙** (송무근 사례 피드백 차용): 모든 표시 수치에 원천·기준일 명시. 분류 태그는 표본 수기 대조(최초 전수, 이후 신규 상장분) 통과 후 반영. 미확인 값은 "확인 중"으로 표기하고 추정치를 만들지 않는다.

**전 종목 개시 + 검증 절차** (2026-07-16 개정): 축소 시험 구동 없이 전 종목(§5.1 유동성 기준 통과분)으로 개시한다. 품질은 절차로 보완한다 — 공개 전 태그 3종 전수 수기 대조 1회, 수익률 계산은 표본 30종목을 타 플랫폼 수치와 교차 검증, 공개 후 신규 상장분은 태그 검수 통과 전 "확인 중" 표기.

**구현 스택 (2026-07-16 확정)**

Lovable 무료판 + Claude 혼합은 가능하며, 다음 분업을 권고한다.

- Lovable (무료 크레딧): UI 스캐폴드·디자인 시안·랜딩 초안 생성까지만. 무료 크레딧이 소량이므로 반복 수정 용도로는 부적합
- GitHub 연동: Lovable 산출 코드를 GitHub로 내보내 이후 소유권을 코드 저장소로 이전
- Claude (Cowork·Claude Code): 이후 전 과정 담당 — 데이터 파이프라인(배치·수익률 계산·태그), 페이지 확장, 수정·유지보수. 반복 작업 비용이 구독료에 포함되어 한계 비용 0
- 인프라 (2026-07-18 개정): 호스팅 Vercel 무료 티어 + 정적 데이터(저장소 커밋) + 공공 API 무료. Phase 1 DB 없음 (§10-A.7), Supabase는 Phase 2 도입. 인프라 비용 0원
- 원칙: Lovable은 "첫 그림", Claude는 "본 공사". 반대로 쓰면 크레딧과 일관성 모두 잃는다
