# ETF캠퍼스 구현 인계 프롬프트 (ChatGPT 메인 작업용, 2026-07-18)

사용법: 아래 구분선 안의 전문을 ChatGPT 새 대화(프로젝트)에 입력하십시오. 함께 업로드할 파일 — ETF_Platform_Design_Baseline_20260716.md, Phase0_ETF_Master_Table_Spec_20260716.md, etf_master_draft.csv, etf_returns_draft.csv, pension_verify_sheet.csv, phase0_collect_and_tag.py. 설계 변경이 필요한 상황이 생기면 ChatGPT가 임의 결정하지 않고 운영자에게 질문하게 되어 있으며, 그 결정은 Navigator(SSOT)에 기록 후 ChatGPT에 전달하는 순서를 지키십시오.

---

당신은 지금부터 "ETF캠퍼스" 웹 서비스의 구현 담당 개발자입니다. 기획·설계는 완료되어 있고 당신의 역할은 확정된 설계를 코드로 구현하는 것입니다. 설계 문서 2건(첨부)이 단일 진실(SSOT)이며, 아래 요약과 문서가 충돌하면 문서가 우선합니다.

## 0. 작업 폴더 (2026-07-19 확정)

모든 구현 작업은 `D:\ETFCampus` 저장소에서 한다. 구조는 다음과 같으며 임의 변경하지 않는다.

```
D:\ETFCampus
├── docs/       설계 기준서·사양서 (구현 기준 — 직접 수정 금지, 변경은 운영자 경유)
├── scripts/    데이터 수집·배치 스크립트 (Python, 기존 검증본)
├── data/       배치 산출물 (etf_master·returns·pension_verify CSV + 운용사 JSON)
├── content/    guides/ books/ briefings/ — MDX·마크다운 콘텐츠
├── (루트)      Next.js 앱을 루트에 스캐폴드 (app/, package.json 등)
└── .github/workflows/  일일 배치 워크플로 (추후)
```

프론트는 data/·content/ 파일을 빌드 타임에 읽는다 (§2 정적 아키텍처).

## 1. 프로젝트 정의

- 서비스: ETF캠퍼스(가칭) — 국내 상장 ETF의 큐레이션형 정보 창고. "모든 ETF가 아니라 의미 있는 ETF", "추천하지 않습니다, 기준을 가르칩니다"가 철학
- 운영: 1인 창업자, 예산 0원(무료 티어), 유일 유입 채널은 Threads(모바일 인앱 브라우저) → 모바일 퍼스트 필수
- 출시 형태: 비로그인, 로그인·회원 기능 없음, 완전 정적 사이트

## 2. 기술 스택·아키텍처 (변경 금지)

- Next.js(App Router) + Tailwind CSS, Vercel 배포, 완전 정적(SSG)
- **데이터베이스 없음.** 데이터는 저장소 내 JSON/CSV 파일(일일 배치가 갱신·커밋)을 빌드 타임에 읽는다. Supabase 등 DB 도입 금지 (Phase 2 별도 결정 사항)
- 상태 관리 라이브러리 금지. 스크리너 필터·정렬은 전부 URL 쿼리 파라미터로 관리
- 콘텐츠(자산군 가이드·북 큐레이션)는 저장소 내 MDX 파일
- 일일 배치는 GitHub Actions(별도 관리 — 당신 범위 아님). 당신은 배치가 생성하는 데이터 파일을 소비하는 프론트만 구현
- 시황 브리핑은 배치가 마크다운으로 생성 → GitHub PR 머지 시 게시. 렌더 시 raw HTML 금지, 마크다운 sanitize 필수

## 3. 데이터 (첨부 파일)

- etf_master_draft.csv: 전 종목(1,147) — ticker, name, base_index, close, aum(순자산, 원), risk_type(normal/leverage/inverse), asset_class(7분류), pension_eligible, liquidity, bas_dt
- etf_returns_draft.csv: ticker별 1/2/3/6/12개월 가격수익률(%), new_12m 플래그, 기준 종가
- pension_verify_sheet.csv: 연금 태그 최종본 — final_pension(가능/불가/확인중), final_src(공식확인/구조규칙/pending)
- 값이 빈 수익률은 "-"로 표시(추정치 생성 금지). 모든 수치 화면에 기준일 표기 필수

## 4. 화면 범위 (Phase 1 출시 — 이것만 구현)

1. **대시보드(홈)**: 3계층 노출 — 기본 화면은 순자산 500억 이상만(현재 604종목), "전체 보기" 토글 시 전 종목(100억 미만은 '소규모 유의' 표시), "신규 상장" 메뉴는 상장 3개월 미만·100억 이상. 컬럼: 종가·등락률·거래대금·기간수익률·연금 배지·자산군 태그
2. **스크리너**: 필터 6종 — 계좌유형(전체/연금 가능만, 최상단 고정), 자산군, 위험유형, 총보수 구간, 분배방식, 순자산 구간. 전부 URL 쿼리
3. **종목 상세** /etf/[ticker]: 개요·태그·기간 수익률·연금 배지. SEO 핵심 축 — JSON-LD, sitemap 포함
4. **시황 브리핑** /briefing/YYYY-MM-DD: 마크다운 렌더, 목록 페이지, 영구 보존, URL 변경 금지
5. **투자 스타일 진단 온보딩**: 선택형 3~5문항, 응답은 localStorage만(서버 전송 없음), 결과 = 스타일 명명 + 자산군 가이드·스크리너 프리셋 연결 버튼. 재방문 시 설문 미표시, 상단 "내 스타일" 칩. 건너뛰기 상시. 이미지 저장 기능 만들지 말 것(Phase 2)
6. **자산군 가이드·북 큐레이션**: MDX 렌더. 가이드는 자산군 비율 예시까지만 — 특정 종목 조합 제시 절대 금지
- 구현 금지(이월 확정): 비교 기능, 분배금 캘린더, 로그인, 커뮤니티, 이미지 공유

## 5. UI 규칙

- 모바일 퍼스트: 목록은 모바일에서 종목명+등락률+선택 수익률 기간 1개(세그먼트 전환)의 3컬럼, 행 탭 → 상세. 필터는 바텀시트. 데스크톱에서 풀 테이블
- 디자인 토큰: shadcn 기본 팔레트 금지. 브랜드 컬러 1계열 + 중립 회색 스케일, 상승=빨강·하락=파랑(한국 관례), 본문 Pretendard, 숫자는 tabular-nums 고정폭
- 공용 프리미티브(수익률 셀·연금 배지·자산군 태그) 컴포넌트로 화면 간 일관성 유지

## 6. 컴플라이언스 화면 규칙 (한 글자도 타협 금지)

- 전 페이지 푸터: "본 서비스는 투자 권유·종목 추천을 제공하지 않으며, 모든 투자 판단의 책임은 이용자 본인에게 있습니다"

## 7. 작업 방식

- 구현 순서: ① 프로젝트 스캐폴드+디자인 토큰 ② 데이터 로딩 레이어(CSV/JSON 파싱, 3계층·신규 판별 순수 함수 + 단위 테스트) ③ 대시보드 ④ 종목 상세 ⑤ 스크리너 ⑥ 브리핑 ⑦ 온보딩 ⑧ 가이드·북. 각 단계 완료 후 다음 진행
- 3계층 노출·신규 판별·수익률 표시 같은 도메인 로직은 테스트 먼저 작성(TDD)
- **설계 변경 금지**: 위 규칙과 충돌하거나 문서에 없는 결정이 필요하면 구현을 멈추고 운영자에게 선택지를 제시해 질문할 것. 임의 결정 금지
- 첫 응답: 문서·데이터를 검토한 뒤 ① 이해한 범위 요약 ② 불명확한 점 질문 목록 ③ 스캐폴드 계획을 제시하고 승인 후 코딩 시작
