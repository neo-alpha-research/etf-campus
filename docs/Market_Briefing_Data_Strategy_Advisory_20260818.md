# ETF Campus 마켓 브리핑 데이터 전략 자문 답변

## 최종 권고안 (한 줄)

이미 보유한 공공데이터포털 인증키 하나로 KOSPI·KOSDAQ까지 확보하고, 미국 국채는 U.S. Treasury 공식 파일을 추가하는 선에서 V0를 출시하십시오. KRX Open API와 ECOS 경유 타 기관 통계는 상업적 이용 제한 때문에 초기 스택에서 제외하는 것이 안전합니다.

---

## 이 답변에서 가장 중요한 두 가지 발견

### 발견 1. KRX Open API는 비상업적 이용으로 제한됩니다 [확인됨]

KRX Data Marketplace OPEN API 이용약관(2025년 12월 26일 시행) 원문에 다음 조항이 있습니다.

제6조 제2항: "API 이용자는 API 서비스를 비상업적인 목적으로만 이용할 수 있으며, API 서비스를 이용한 결과에 대한 대가를 제3자에게 청구해서는 아니된다."

제11조 제2항: "API 이용자는 한국거래소로부터 제공받은 정보를 제3자에게 제공할 수 없다."

제10조 제3항: "API 이용자가 API 서비스를 이용한 결과를 사용하여 화면을 제작한 경우, 해당 화면에 '한국거래소 통계정보'를 사용한 결과임을 명시해야 한다."

ETF Campus는 무료 브리핑을 리드 마그넷으로 삼아 유료 뉴스레터 구독으로 전환하는 구조이므로, 브리핑 자체가 무료여도 사업 목적의 서비스로 해석될 여지가 큽니다. 제11조 제2항의 "제3자에게 제공"에 불특정 다수 대상 웹 게시가 포함되는지도 해석 위험이 있습니다. 따라서 KRX Open API는 KOSPI·KOSDAQ 확보 경로로 비권장합니다. 반드시 쓰려면 사전에 KRX에 사업 구조를 설명하고 서면 회신을 받으십시오.

출처: https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO002.jsp

### 발견 2. 이미 가진 키로 KOSPI·KOSDAQ을 받을 수 있습니다 [확인됨, 명세 확인 필요]

공공데이터포털에 금융위원회_지수시세정보(데이터 15094807)가 있고, 3개 오퍼레이션 중 주가지수시세가 KOSPI·KOSDAQ을 포함한 주요 주가지수의 시가·고가·저가·종가·등락률·거래량을 제공합니다. 공공데이터포털은 계정 단위로 인증키를 발급하므로, 현재 ETF 시세에 쓰고 있는 `DATA_GO_KR_SERVICE_KEY`를 그대로 쓸 수 있습니다. 즉 API 원천은 늘어나도 관리해야 할 secret과 인증 체계는 늘지 않습니다.

금융위원회 제공 서비스는 실시간이 아니며 기준일자로부터 영업일 하루 뒤 오후 1시 이후 갱신됩니다. 이는 현재 ETF 데이터의 갱신 시차와 동일하므로 브리핑 기준일 정합성이 오히려 좋아집니다.

출처: https://www.data.go.kr/data/15094807/openapi.do

## 질문 A. 최적 데이터 소스 구조

제시하신 세 안 중 어느 것도 그대로 권하지 않고, 2안을 변형한 네 번째 안을 권고합니다.

**권고안: 단일 키 우선안**

기존 공공데이터포털 인증키 하나로 ETF 시세와 KOSPI·KOSDAQ을 모두 받고, 여기에 인증이 필요 없는 U.S. Treasury 공식 파일만 더해 V0를 구성합니다. 원/달러·국고채·WTI는 약관 확인이 끝나는 대로 V1에서 추가하고, 미국 3대 지수는 V2로 미룹니다.

평가 기준별 근거는 다음과 같습니다.

비용 측면에서 V0는 전부 무료이며 신규 유료 계약이 없습니다. 재배포 리스크 측면에서 공공데이터포털 데이터는 공공누리 조건이 명시되어 있고 제1유형이면 출처표시만으로 상업적 이용이 가능합니다. U.S. Treasury 자료는 미국 연방정부 저작물이라 이용 제약이 사실상 없습니다. API 수와 장애 지점 측면에서 V0는 secret이 기존 1개 그대로이고 원천 도메인은 두 곳뿐입니다. 자동 갱신 안정성 측면에서 국내 데이터가 모두 같은 포털·같은 갱신 규칙(T+1 오후 1시 이후)을 따르므로 스케줄 설계가 단순해집니다. 커버리지 측면에서는 미국 3대 지수와 일일 WTI가 빠지지만, 이는 라이선스 리스크를 감수하지 않고는 해결되지 않는 항목입니다.

1안(완전 무료·다중 원천)을 권하지 않는 이유는 KRX Open API와 ECOS가 포함되어 있어 오히려 라이선스 리스크가 가장 큰 조합이기 때문입니다. 3안(유료 단일 API)은 V2에서 미국 지수가 사업적으로 반드시 필요하다고 판단될 때 검토할 선택지이며, 그 시점에도 계약서에 공개 웹 표시(display) 권한이 명시되는지 반드시 확인해야 합니다.

## 질문 B. ECOS·금융경제 스냅샷 사용 원칙

### B-1. 한국은행 작성 통계와 타 기관 작성 통계의 실무적 구분

기준은 단순합니다. ECOS 통계표 메타데이터의 작성기관(출처)이 한국은행이면 출처 표시만으로 상업적 이용이 가능하고, 그 외 기관이면 상업적 이용에 해당 기관의 승인이 필요합니다. 한국은행 이용지침은 타 기관 작성 통계에 대해 출처를 명시한 비상업적 이용만 허용하고, 상업적 이용은 작성기관 승인 후에 가능하다고 밝히고 있습니다. [확인됨]

실무적으로는 통계표 코드 단위가 아니라 항목(시계열) 단위로 확인해야 합니다. 같은 통계표 안에서도 항목별 원 출처가 다를 수 있기 때문입니다. 개발 시점에는 사용할 시계열 목록을 만들어 각각의 작성기관을 ECOS 통계표 설명에서 확인하고, 그 결과를 저장소 문서로 남기십시오.

첨부하신 표를 이 기준으로 보면, KOSPI·KOSDAQ은 KRX, 국고채는 KOFIA, 미국 국채는 U.S. Treasury, WTI는 IMF, 북미 주가지수는 OECD가 각각 작성기관이므로 전부 타 기관 통계입니다. 상업적 서비스인 ETF Campus가 ECOS를 경유해 이들을 쓰려면 원칙적으로 각 기관 승인이 필요합니다. 원/달러의 경우 ECOS 출처로 표시되어 있으나 환율 통계는 중개기관 자료를 수록하는 경우가 있으므로 작성기관을 별도로 확인해야 합니다. [확인 필요]

### B-2. 무료 공개 데이터라도 별도 확인이 필요한가

필요합니다. 판단 기준은 세 가지로 분리하십시오.

첫째, 접근이 무료인가. 둘째, 상업적 이용이 허용되는가. 셋째, 재배포 또는 공개 표시가 허용되는가. 이 셋은 서로 독립적이며, 무료라는 사실이 나머지 둘을 보장하지 않습니다. KRX Open API가 대표적인 사례로, 무료이지만 비상업 목적으로 제한되고 제3자 제공이 금지됩니다.

실무 판단 순서는 다음과 같습니다. 원 작성기관이 직접 공개하는 정식 경로가 있으면 그것을 씁니다. 그 경로의 이용조건이 공공누리 제1유형이거나 이에 준하면 출처표시로 사용합니다. 조건이 불명확하면 사용을 보류하고 기관에 문의해 회신을 보관합니다. 중계 플랫폼(ECOS 등)을 통해 타 기관 데이터를 받는 것은 원 작성기관 승인 없이는 상업 서비스에 쓰지 않습니다.

### B-3. 금융경제 스냅샷 내부 endpoint 사용

권하지 않습니다. 이유는 세 가지입니다.

첫째, 이용조건이 명시되지 않은 화면 구동용 내부 경로이므로 약관상 허용 범위를 입증할 수 없습니다. 값이 반환된다는 사실이 이용 권한을 뜻하지 않습니다. 둘째, 내부 endpoint는 공지 없이 경로·응답 구조가 바뀔 수 있어 운영 원천으로서 안정성이 낮습니다. 셋째, 스크래핑을 하지 않겠다는 프로젝트 원칙과 실질적으로 같은 성격의 회색지대 행위입니다.

대안은 명확합니다. 한국은행 자체 작성 통계가 필요하면 ECOS Open API 정식 통계표를 쓰고, 타 기관 데이터가 필요하면 그 기관의 정식 공개 경로(공공데이터포털 또는 기관 API)를 직접 씁니다. 스냅샷 화면은 어떤 지표가 존재하는지 탐색하는 참고용으로만 사용하십시오.

미국 시장 흐름을 카드에서 완전히 빼는 것이 아쉽다면, V1에서 미국 국채 2년·10년 금리를 미국 시장 온도계로 배치하는 방법이 있습니다. 금리는 미 재무부 공개 자료라 라이선스 부담이 없으면서도 위험자산 심리를 설명하는 데 충분한 서술력을 가집니다.

메인 화면 카드는 6개로 시작하는 것을 권합니다. 일반 ETF 시장지수(자체 지표), 코스피, 코스닥, 원/달러, 국고채 10년, 미국 국채 10년입니다. 자체 지표를 첫 칸에 두면 ETF Campus 고유 자산이 브랜드 자산으로 각인되고, 나머지 다섯은 국내 투자자가 매일 확인하는 최소 조합입니다. 국고채 3년·미국 2년·WTI는 금리·원자재 상세 영역으로 내리십시오.

## 질문 D. UI 출처·기준일 표기 정책

**권고: 2안(페이지 하단 또는 접이식 패널 통합 표기)**

1안(카드별 표기)은 6개 카드에 매번 출처를 붙이면 시각적 밀도가 높아져 원하시는 UX를 해칩니다. 3안(약관에만 표기)은 이용자가 실제로 접근하기 어려운 위치라 고지로서 실효성이 약하고, 데이터 기준일처럼 매일 바뀌는 정보를 담기에도 부적합합니다.

다만 2안을 택하더라도 두 가지는 카드 위에 남겨야 합니다. 첫째는 데이터 기준일이고, 둘째는 자체 계산 지표라는 표시입니다. 기준일이 없으면 이용자가 실시간 시세로 오인할 수 있고, 자체 지표에 표시가 없으면 공인 지수로 오인될 수 있습니다. 이 둘만 상단에 두고 나머지 원천·산식·면책은 접이식 패널로 내리면 화면은 깔끔하게 유지됩니다.

각 기관이 요구하는 특정 문구가 있으면 그 문구는 반드시 접이식 패널 안에 원문대로 넣으십시오. 예를 들어 KRX 계열 데이터를 쓰게 될 경우 화면에 한국거래소 통계정보를 사용했다는 명시가 약관상 의무입니다.

### UI 문구안

```
데이터 기준일: 2026.08.18 (국내 종가 기준)
시장 데이터는 원천별 갱신 시차가 있으며 실시간 시세가 아닙니다.
ETF Campus 지표는 국내 상장 일반 ETF를 대상으로 자체 산출한 값입니다.
투자 판단의 책임은 이용자 본인에게 있으며, 매매 시점의 정확한 정보는 공식 채널에서 확인하시기 바랍니다.
[데이터 출처 및 산식 보기]
```

접이식 패널 안에는 원천 기관 목록과 각 지표의 갱신 주기, 자체 지수의 유니버스·가중·리밸런싱·기준값·수익률 정의, 결측 시 처리 규칙을 넣으십시오. 자체 지수는 산식을 공개하는 편이 신뢰에 유리하고, 이미 초안에 정의가 잘 잡혀 있습니다.

## 질문 E. 일일 자동화 설계

### E-1. 수집·재시도 시점

국내 데이터는 금융위원회 서비스가 기준일 기준 영업일 T+1 오후 1시 이후 갱신되므로, 한국시간 14시 1차 수집, 실패 시 15시·16시·18시 재시도로 설계합니다. 4회 모두 실패하면 당일 갱신을 포기하고 직전 정상값을 기준일과 함께 유지합니다.

미국 데이터는 미국 영업일 종료 후 공개되므로 한국시간 익일 오전 7시에 수집합니다. 재시도는 8시·10시로 두 번이면 충분합니다.

브리핑 생성은 국내 수집이 성공한 시점에 트리거하되, 미국 데이터가 아직 없으면 해당 카드를 이전 기준일로 표시한 채 발행합니다. 미국 데이터를 기다리느라 국내 브리핑 발행이 밀리는 구조는 피하십시오.

휴장일 처리는 수집 첫 단계에서 국내 거래일 여부를 확인하고, 휴장이면 즉시 정상 종료하는 방식으로 둡니다.

### E-2. 최소 JSON 스키마

```json
{
  "as_of_date": "2026-08-18",
  "indicator_id": "kospi",
  "label": "코스피",
  "value": 2734.15,
  "change_pct": 0.42,
  "unit": "pt",
  "source_org": "금융위원회",
  "source_api": "data.go.kr/15094807",
  "source_status": "ok",
  "fetched_at": "2026-08-19T05:03:11Z",
  "is_stale": false,
  "stale_days": 0
}
```

`source_status`는 `ok`, `delayed`, `failed`, `suppressed` 네 값만 사용합니다. `suppressed`는 값을 받았지만 품질 검증에서 탈락해 의도적으로 공개를 보류한 상태로, 자체 지수의 AUM 커버리지 미달이 여기 해당합니다. `is_stale`은 `as_of_date`가 직전 거래일보다 오래된 경우 참이 되며, `stale_days`로 며칠 밀렸는지 함께 저장합니다.

### E-3. 결측·지연 fallback 규칙

원칙은 하나입니다. 값은 마지막 정상값을 보여 주되 기준일은 절대 오늘 날짜로 바꾸지 않습니다.

`stale_days`가 1이면 카드에 이전 기준일을 그대로 표시하고 별도 경고는 두지 않습니다. 2 이상이면 카드에 갱신 지연 배지를 붙이고 접이식 패널에 사유를 표시합니다. 5 이상이면 카드에서 값을 내리고 갱신 중단 상태로 표시합니다. 값을 조용히 감추는 것보다 상태를 드러내는 편이 신뢰에 유리하고, 잘못된 기준일을 표시하는 것보다 안전합니다.

`source_status`가 `failed`인 상태로 3거래일 연속 누적되면 운영자에게 알림이 가도록 하십시오.

### E-4. 자체 지표와 외부 벤치마크 혼합 시 품질 검증

검증은 세 층으로 둡니다.

값 검증 층에서는 전일 대비 변동이 지표별 상한을 넘으면 자동 게시를 보류합니다. 지수·환율은 일간 10퍼센트, 금리는 절대값 기준 100bp를 임계선으로 시작해 실측으로 조정하십시오.

정합 검증 층에서는 한 브리핑에 담기는 모든 국내 지표의 `as_of_date`가 동일한지 확인합니다. 서로 다른 기준일의 국내 지표를 한 문장에서 비교하면 사실관계가 깨집니다. 국내와 해외의 기준일이 다른 것은 정상이며, 이 경우 브리핑 문장에서 두 기준일을 명시적으로 분리해 서술해야 합니다.

자체 지수 층에서는 이미 정의하신 유효 AUM 커버리지 95퍼센트 규칙을 그대로 적용하고, 여기에 구성 종목 수 급변 검증을 추가하십시오. 전일 대비 유니버스 종목 수가 5퍼센트 이상 변하면 데이터 수집 오류일 가능성이 높습니다.

### E-5. AI 브리핑 생성 구조

모델에는 확정된 숫자와 레이블만 담긴 JSON을 넘기고, 원천 API 응답 원문이나 계산 과정을 넘기지 마십시오. 모델이 계산하게 두면 검증할 수 없는 숫자가 생깁니다.

프롬프트에는 다음 세 가지를 고정 제약으로 넣으십시오. 첫째, 입력 JSON에 없는 수치를 만들어내지 않는다. 둘째, 특정 종목·ETF의 매수·매도 권유, 목표가, 향후 방향 단정을 쓰지 않는다. 셋째, 모든 수치에 기준일을 함께 쓴다.

생성 후에는 기계 검증을 한 단계 두십시오. 출력 텍스트에서 숫자를 추출해 입력 JSON에 존재하는 값인지 대조하고, 금지 표현 사전(매수, 매도, 추천, 목표가, 전망, 상승할 것, 하락할 것 등)에 걸리는 단어가 있으면 발행을 보류하고 운영자 검수로 넘깁니다. 이 검증은 정규식 수준으로도 충분히 효과가 있으며, 컴플라이언스 방어선으로 기능합니다.

브리핑 하단에는 AI가 생성하고 운영자가 검수했다는 표시를 고정 노출하십시오.

## 구현 단계

### V0: 즉시 출시 가능

API 원천 2곳, 필요 secret 1개(기존 `DATA_GO_KR_SERVICE_KEY` 재사용), 신규 계약 0건.

포함 지표는 ETF 자체 지표 전체(일반 ETF 종목 수, 상승·하락 분포, AUM, 거래대금, 자산군별 분해, 자체 시장지수), 코스피, 코스닥, 미국 국채 2년·10년입니다.

메인 카드 6개는 일반 ETF 시장지수, 코스피, 코스닥, 미국 국채 10년과 자체 지표 2종으로 구성하고, 원/달러 자리는 V1까지 비워 둡니다.

### V1: 약관 확인 후 확장

신규 secret 최대 2개(한국수출입은행, EIA) 추가. 추가 지표는 원/달러 매매기준율, 국고채 3년·10년, WTI입니다.

이 단계 착수 전에 확인해야 할 항목은 세 가지입니다. 한국수출입은행 환율 API의 공공누리 유형과 호출 제한, 국고채 수익률의 공개 웹 재배포 조건, EIA API의 갱신 주기와 실제 지연폭입니다.

### V2: 사업성 판단 후 검토

미국 3대 지수 도입 여부를 결정합니다. 이 단계에서만 유료 단일 API 계약을 검토하며, 계약서에 공개 웹 표시 권한과 허용 사용자 수 조건이 명시되어 있는지 반드시 확인하십시오. 뉴스레터 유료 구독 매출이 데이터 비용을 감당할 수 있다는 근거가 생긴 뒤에 진행하는 것이 순서상 맞습니다.

## 결정을 위한 3개 선택지

**A. 완전 무료 MVP**
V0만 실행합니다. 기존 키 하나로 ETF 지표와 코스피·코스닥을 제공하고, 미국 국채 2종을 더합니다. 신규 secret 0개, 신규 계약 0건, 라이선스 리스크 최소. 환율·유가·미국 지수는 없습니다.

**B. 무료 + 국내 핵심 벤치마크 확장**
V0에 이어 V1까지 실행합니다. 원/달러·국고채·WTI가 추가되어 국내 투자자가 기대하는 지표 조합이 거의 완성됩니다. 신규 secret 2개, 사전 약관 확인 3건이 필요하며 착수까지 2주에서 4주가 소요될 수 있습니다.

**C. 유료 단일 보조 API 도입**
V0·V1에 더해 상용 API로 미국 3대 지수까지 채웁니다. 화면 완성도는 가장 높지만 월 고정비가 발생하고 표시 권한 계약 확인이 필요합니다. 무료 브리핑 단계에서 감당할 비용 구조인지 검증되기 전에는 권하지 않습니다.

권고 순서는 A로 출시하고, 실제 이용자 반응을 본 뒤 B로 확장하며, 유료 구독 매출이 확인된 뒤에만 C를 검토하는 것입니다.

## 제출 전 재대조가 필요한 항목

첫째, 금융위원회 지수시세정보의 주가지수시세 오퍼레이션이 실제로 KOSPI·KOSDAQ 종합지수를 포함하는지 Swagger 명세로 직접 확인하십시오. 검색 요약으로는 포함되어 있으나 응답 필드 수준까지는 확인하지 못했습니다.

둘째, 현재 사용 중인 ETF 시세 API를 포함해 공공데이터포털 각 데이터의 공공누리 유형을 데이터 상세 페이지에서 확인하고 기록해 두십시오. 제1유형이면 출처표시로 상업적 이용이 가능하지만, 제2유형 이상이면 조건이 달라집니다.

셋째, 국고채 수익률의 공개 재배포 조건은 이번 조사에서 확정하지 못했습니다. 공공데이터포털 경로와 금융투자협회 경로 중 어느 쪽이 재배포를 허용하는지 문의로 확인하십시오.
