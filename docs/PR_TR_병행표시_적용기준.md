# 배당형 ETF PR·TR 병행표시 적용 기준

> **목적:** 기존 시장가격 수익률(PR)은 모든 ETF에 유지하고, 배당형 ETF 중 원천·일정·커버리지가 완결된 경우에만 총수익률(TR)을 추가로 제공한다. 검증되지 않은 TR은 추정값·빈 차트·PR 대체값으로 노출하지 않는다.

## 1. 결론

배당형 ETF에 한해 PR과 TR을 병행하는 것은 ETF Campus의 비교 가치와 투자자 이해도를 높이는 방향이다. 특히 커버드콜·고배당 ETF는 현금 분배금이 투자 성과의 중요한 구성요소이므로, 가격만 반영한 PR만으로는 장기 성과를 충분히 해석하기 어렵다.

다만 현재의 **PR 차트와 PR 기간 수익률을 TR로 일괄 교체하면 안 된다.** 사용자가 가격 변동 자체를 보고 싶은 상황도 많고, 검증 데이터가 완결되지 않은 ETF에서 TR을 표시하면 데이터 신뢰 원칙을 훼손한다. 따라서 기본값은 현행 PR로 유지하고, 검증된 배당형 ETF에만 명확한 TR 전환 기능을 추가한다.

| 대상 | 기본 표시 | 추가 표시 | 금지 사항 |
|---|---|---|---|
| 비배당형 ETF | PR | 없음 | TR 탭·TR 배지 노출 금지 |
| 배당형, TR 준비 중 | PR | `TR 검증 중` 상태 안내 | 0%·추정치·PR 복제 라인을 TR로 표시 금지 |
| 배당형, 데이터 충돌·결손 | PR | `TR 제공 보류` 상태 안내 | 비완결 이벤트를 반영한 TR 노출 금지 |
| 배당형, 검증·커버리지·가격 이력 완결 | PR | PR/TR 전환 및 TR 기간 수익률 | PR과 TR 정의를 혼용한 수치 노출 금지 |

## 2. 현재 구조에서의 적용 원칙

현재 상세 차트는 `/api/prices/history`의 가격 데이터를 기준으로 기간별 누적 수익률을 계산하고, 화면에도 `분배금 미포함`이라고 명시한다. 이 값은 **PR**로 유지한다. 또한 상세 페이지의 기간 수익률 표도 현재 `etf.returns` 기반 PR이므로, TR 표시 시에는 차트와 표를 같은 기준으로 동시에 전환해야 한다.

현재 `etf_total_return_metrics.csv`는 기간별 TR 결과를 담을 수 있는 원장이지만, 차트에는 날짜별 시계열이 필요하다. 따라서 검증이 끝난 ETF는 아래처럼 별도 시계열 원장을 생성해야 한다.

```text
etf_total_return_history.csv
etf_id,ticker,date,price_close,distribution_cash,distribution_reinvested_units,tr_index,return_basis,verification_status
KR7...,483290,2026-07-30,10870,133,...,101.23,pre_tax_market_price_reinvestment,verified
```

`tr_index`는 검증된 분배락 적용일에 세전 현금분배금을 시장가격으로 재투자하는 기준으로 계산한다. 분배락 전일, 분배락 적용일, 지급일은 서로 다른 필드로 보존하며, 차트 계산에는 `krx_apply_date`만 사용한다.

## 3. 노출 게이트

TR 모드가 활성화되는 조건은 아래 조건을 모두 충족해야 한다.

| 게이트 | 판정 기준 | 미충족 시 화면 처리 |
|---|---|---|
| 배당형 대상 | 정적 배당형 워치리스트 또는 파생된 `is_income_etf` 값 | PR만 표시 |
| 이벤트 검증 | 해당 기간 이벤트가 모두 `verified` | `TR 검증 중` |
| 월별 커버리지 | 분배금·무분배 월이 `complete` | `TR 검증 중` |
| 기업행동 검증 | 분할·병합·상장폐지 등 가격 연속성 확인 완료 | `TR 제공 보류` |
| 가격 이력 | 선택 기간의 TR 시계열이 완결 | 해당 기간 TR 비활성화 |
| 계산 상태 | `calculation_status=calculated` | TR 탭 비활성화 |

권장 파생 데이터는 개별 화면이 여러 CSV를 직접 조인하지 않도록 `data/returns/etf_return_display_status.json`으로 정리한다.

```json
{
  "ticker": "483290",
  "isIncomeEtf": true,
  "prAvailable": true,
  "trStatus": "pending",
  "trAvailablePeriods": [],
  "trUnavailableReason": "2026년 7월 이후 KIND 분배락 적용일 검증 진행 중",
  "lastVerifiedAt": null
}
```

`trStatus`는 `not_applicable`, `pending`, `blocked_conflict`, `partial`, `available`만 사용한다. 클라이언트는 `available` 및 선택 기간 포함 여부일 때만 TR 데이터를 요청한다.

## 4. 모바일 우선 UX

차트 상단의 기간 필터 바로 아래에 수익률 기준을 둔다. 단, 배당형이며 TR이 완결된 경우에만 두 개의 동등한 버튼을 표시한다.

```text
[ 시장가격 수익률 PR ] [ 총수익률 TR ]
```

모바일에서는 `PR`과 `TR` 약어만 남기지 않고 다음 보조 문구를 함께 유지한다.

| 상태 | 차트 헤더 | 보조 문구 |
|---|---|---|
| PR | `시장가격 수익률(PR)` | `분배금 미포함` |
| TR | `총수익률(TR)` | `세전 분배금 재투자 가정` |
| 준비 중 | `시장가격 수익률(PR)` | `총수익률은 공식 공시 검증 후 제공` |
| 제공 보류 | `시장가격 수익률(PR)` | `일부 분배금 원천 확인이 필요해 TR 제공 보류` |

TR이 준비되지 않았을 때는 비활성화된 탭보다 **짧은 상태 배지와 설명 패널**을 우선한다. 사용자가 선택할 수 없는 UI를 매번 보여주면 기능 결손처럼 느껴지기 때문이다. 상세 페이지의 기간 수익률 표는 PR/TR 두 행을 겹쳐 보여주기보다, 차트 선택 기준과 동일하게 표 전체를 전환한다. 따라서 차트 상단 수익률, 선 그래프, 툴팁, 기간 표가 언제나 동일한 기준을 공유한다.

## 5. 비교 화면 규칙

ETF 비교의 기본 수익률은 계속 PR로 통일한다. ETF마다 TR 커버리지 상태가 다르면 단일 순위나 오버레이에서 비교 기준이 달라져 오해를 만들 수 있기 때문이다. 모든 선택 ETF가 동일 기간의 TR을 `available`로 충족할 때에만 비교 화면에 `총수익률(TR)` 전환을 추가한다. 하나라도 미완결이면 PR만 보여 주고, 미완결 사유를 각 ETF에 표시한다.

## 6. 구현 순서

1. `income_etf_collection_watchlist.csv`를 배포용 `isIncomeEtf` 플래그로 정규화한다.
2. `calculate_total_returns.py`가 검증 이벤트만 반영한 날짜별 `etf_total_return_history`를 생성하도록 확장한다.
3. 기간별 TR 수치와 차트 시계열의 기준일·시작일·종료일을 동일하게 검증한다.
4. 가격 이력 API에 `basis=pr|tr`와 표시 상태 메타데이터를 추가한다. `tr` 요청은 게이트 통과 시에만 반환한다.
5. `PriceHistoryChart`에 기준 선택 UI를 추가하고, `EtfDetail`의 기간 수익률 표를 같은 기준으로 전환한다.
6. 비배당형·준비 중·충돌·완결 네 상태의 모바일 스냅샷 및 회귀 테스트를 추가한다.

## 7. 출시 조건

초기 출시에서는 TR이 완결된 ETF만 노출한다. 각 수치와 차트에는 마지막 검증일, 기준일, 계산 정의 링크를 제공한다. TR이 아직 가능한 ETF가 없더라도 PR 차트의 현재 동작은 변경하지 않으며, 준비 상태만 정확히 안내한다.

이 구조는 데이터가 누적될수록 배당형 ETF의 TR 범위를 자연스럽게 확대하면서도, 미검증 분배금을 투자 성과에 섞지 않는 ETF Campus의 검증 원칙을 지킨다.
