## 1. 테이블 구조 (4개)

### 1.1 etf_master (종목 원장 — 서비스 품질의 핵심)

| 컬럼 | 설명 | 원천 |
|------|------|------|
| isin_cd | ISIN 코드 (기본키) | KRX상장종목정보 API |
| ticker | 단축코드 (6자리) | 동일 |
| name | 종목명 | 동일 |
| listing_date | 상장일 (수익률 기간 표시 가능 여부 판단) | 동일 |
| base_index | 기초지수명 | 증권상품시세정보 API |
| asset_class | 자산군 태그 (§2.3) | 규칙 + 수기 검수 |
| risk_type | 위험 유형 태그: normal / leverage / inverse (§2.1) | 규칙 + 수기 검수 |
| pension_eligible | 연금(DC/IRP) 편입 가능 태그 (§2.2) | 규칙 + 수기 검수 |
| liquidity_pass | 유동성 기준 통과 여부 (§2.4, 배치 자동 갱신) | 계산 |
| tag_status | confirmed / pending (신규 상장분은 pending, 화면에 "확인 중" 표기) | 운영 |
| delisted | 상장폐지 여부 | KRX 공시 |

### 1.2 etf_daily (일일 시세 — 배치 적재)

date, isin_cd, close(종가), change_pct(등락률), volume, trade_value(거래대금), nav, aum(순자산총액). 원천: 금융위 증권상품시세정보 API. 기준일 필드 포함 필수.

### 1.3 etf_return (기간 수익률 — 배치 계산)

date, isin_cd, r_1m, r_2m, r_3m, r_6m, r_12m. 계산 규칙은 §3.

### 1.4 etf_distribution (분배금 — 캘린더용)

isin_cd, 분배락일, 지급기준일, 지급일, 분배금액, 확정 여부. 원천: 한국예탁결제원 주식정보서비스 API. K-ETF 차용 필드(마지막매수일)는 분배락일에서 역산.

## 2. 태그 규칙

### 2.1 위험 유형 (risk_type) — 자동 분류율 목표 100%

- leverage: 종목명 또는 기초지수명에 "레버리지", "2X", "3X" 포함
- inverse: "인버스", "-1X", "-2X", "선물인버스" 포함
- 둘 다 해당(인버스2X)은 inverse로 분류하되 leverage 플래그 병기
- normal: 그 외 전부
- 예외 처리: "단일종목" 선물형 등 신종 유형은 수기 검수에서 포착

### 2.2 연금 편입 가능 (pension_eligible) — 규칙 초안, 전수 수기 검수로 확정

1차 규칙 (자동 배제): risk_type이 leverage 또는 inverse → 불가. 선물 기반 원자재·통화형 등 파생상품 위험평가액 기준 초과 유형 → 불가.
2차 (수기 검수): 1차 통과분을 ETF CHECK 연금 필터·증권사 퇴직연금 매매 가능 목록과 눈으로 대조하여 확정 (2026-07-17 확정). 대조는 사실 확인 행위로 허용하되, 타사 데이터의 수집·전재는 DB제작자 권리·이용약관상 금지한다. 판정 원천은 항상 자체 규칙이며 타사 데이터는 채점지 역할에 한정. 판단 애매 종목은 "불가"로 보수적 처리 (컴플라이언스 1순위 원칙).
비고: 이 태그는 자동 제공되는 원천 데이터가 없어 수기 검수 자체가 경쟁 우위다. 신규 상장분은 검수 전 pending.

### 2.3 자산군 (asset_class) — 8분류

주식-국내 / 주식-해외 / 채권 / 금리·파킹 / 원자재 / 리츠·인프라 / 혼합·자산배분 / 기타. 기초지수명·종목명 키워드 규칙으로 1차 분류 후 수기 검수. 테마 세분류(K-ETF식 114테마)는 Phase 2 안건.

### 2.4 유동성 기준 (liquidity_pass)

순자산총액(aum) 100억 원 이상. 일일 배치에서 갱신하되, 경계 종목의 잦은 출입을 막기 위해 이력 20영업일 평균으로 판정한다. 미달 종목은 기본 목록 제외 + "포함 보기" 토글 대상 (Baseline §5.1).

## 3. 수익률 계산 규칙

- 기준: 가격수익률 (분배금 미포함), 라벨 문구 "가격 기준·분배금 미포함" 고정
- 기간: 기준일로부터 1/2/3/6/12개월 전 동일 날짜의 직전 거래일 종가 대비 등락률
- 상장 기간 미달: 해당 기간 칸은 "-" 표기 (추정치 생성 금지)
- 검증: 공개 전 표본 30종목을 타 플랫폼(ETF CHECK 등) 수치와 교차 대조. 허용 오차 초과 시 원인 규명 전 공개 금지

## 4. 일일 배치 흐름 (2026-07-18 외부 검토 반영 개정)

GitHub Actions, 매일 07:00 KST 시작 (2026-07-18 정적 파이프라인 개정 — Phase 1 DB 무도입): ① KRX 휴장일 확인(휴장이면 정상 종료) → ② API 수집(대상일 미적재 시 1시간 간격 최대 5회 재시도) → ③ **변경 감지**: 전일 대비 종목명·기초지수명 diff — 변경 종목 tag_status=pending 강등 (운용사 리브랜딩 대응) → ④ 신규 상장·폐지 반영 (신규는 first_traded_date 기록 + pending) → ⑤ etf_return 계산 + **서킷브레이커**: 앵커 대비 ±40% 초과 수익률 게시 보류 (액면병합·분할 오염 차단) → ⑥ liquidity_pass 갱신 → ⑦ 데이터 JSON 생성·저장소 커밋 (git 이력이 곧 일일 백업) → ⑧ 시황 브리핑 초안 생성(LLM, 리뷰어 규칙) → GitHub PR 생성 → ⑨ 운영자 머지 시 Vercel Deploy Hook으로 전체 재빌드·배포.

실패 처리: API 응답 누락 시 전일 데이터 유지 + 화면 "기준일" 명시. 2회 연속 실패 시 운영자 통지(GitHub 실패 이메일). 브리핑 미승인 시 직전 브리핑이 최신으로 유지 (별도 로직 없음).

**키 보관 규정** (Phase 1): 공공 API 키·LLM 키 = GitHub Secrets만 (배치 전용, 프론트에는 어떤 키도 없음). 현재 대화에 노출된 공공 API 키는 출시 전 재발급. Supabase 관련 키 규정(service role 분리·RLS·클라이언트 번들 금지)은 Phase 2 DB 도입 시점에 적용.
