## 0. 한 줄 결론

**동물 10종은 "공유되는 정체성"으로 남기고, 3편 시리즈는 "다음 한 걸음(처방)"으로 뒤에 붙입니다.**
10문항(동물) → 3문항(처방) → 결과 1화면에서 `동물 + 시작점 1권 + 읽는 순서 3권`이 함께 나옵니다.

## 1. 왜 "동물을 3타입으로 줄이는 안"을 폐기했는가 (바이럴 관점 자문)

| 검토안 | 바이럴 판정 | 사유 |
| --- | --- | --- |
| A. 동물 폐기 → 모멘텀형/자산배분형/배당형 3종 | **폐기** | 결과가 3개면 확률 1/3. "나만의 결과"라는 감각이 사라져 공유 동기가 붕괴합니다. 게다가 결과 = 판매 상품명이라 광고로 읽힙니다. |
| B. 동물 10종 유지 + 결과 화면에 책만 얹기 | 부분 채택 | 안전하지만 5축(정보 탐색 습관)과 3편(계좌 과제)은 **측정 대상이 다릅니다.** 기존 축만으로 책을 배정하면 근거 없는 매칭이 되어 신뢰가 깨집니다. |
| **C. 2층 구조 (동물 10종 = 정체성 / 신설 3문항 = 처방)** | **채택** | 재미(공유)와 전환(책)을 분리하되 한 화면에서 만나게 합니다. 각 층의 근거가 서로 독립적이라 "왜 이 책인가"를 정직하게 설명할 수 있습니다. |

### 핵심 진단: 지금 설문에는 "책을 고를 축"이 없다

현행 5축은 전부 **정보를 어떻게 보는가**입니다. — 정보 시야 / 탐색 범위 / 점검 리듬 / 비교 방식 / 확인 깊이.
반면 3편 시리즈가 나누는 기준은 **계좌에서 무엇이 비어 있는가**입니다.

- ① 모멘텀 → 위험자산 안에서 **후보를 비교할 신호**가 없음
- ② 지수·자산배분 → 계좌 전체의 **목표 비율·허용 밴드(지도)**가 없음
- ③ 배당·현금흐름 → 분배금을 **현금흐름의 언어**로 읽는 기준이 없음

이 둘은 상관은 있어도 대체되지 않습니다. 따라서 **처방 전용 3문항(Q11~Q13)을 신설**합니다.

## 2. 바이럴 장치 4종 (이번 범위에 포함할 것)

1. **희소도(Rarity) 표시** — "이 유형은 최근 참여자 100명 중 6명"
   운영자가 선택한 D1 익명 통계가 곧바로 재미로 되돌아오는 구조입니다. 통계 수집의 명분이자 공유 트리거입니다.
   *표기 원칙*: "상위 X%" 같은 서열 표현 금지. "전체의 X%"라는 중립 사실만.
   *하한*: 누적 표본 300건 미만이면 "집계 중"으로 숨깁니다(작은 표본의 과장 방지).

2. **한 줄 정체성 문장(punchline)** — 캡처·인용의 최소 단위
   현행 `tagline`은 설명문이라 공유가 안 됩니다. 유형별로 **행동 장면 한 줄**을 신설합니다.
   예) 부엉이: "숫자가 어긋나면 그날 밤에 확인해야 잠이 옵니다."
   *금지*: 자기비하·조롱, 손익·수익률 암시.

3. **가장 다르게 보는 유형(대비 유형)** — 벡터 거리 최대값 1종을 함께 노출
   "나와 정반대 유형" 카드는 부부·팀·동료 간 비교 대화를 만듭니다. 계산은 기존 `vector`로 즉시 가능하며 추가 문항이 필요 없습니다.

4. **결과 전용 정적 URL** — `/style/{animal}/`
   모달 안에만 결과가 있으면 링크로 옮겨지지 않습니다. `output: "export"` 환경이므로 **10종을 빌드 타임에 사전 생성**합니다.
   *이번 범위*: 라우트 + 메타데이터 + 공유 텍스트까지. **OG 이미지 제작과 Web Share 버튼은 다음 단계로 분리**(운영자 지시).

## 3. 처방 로직 (설명 가능성 우선)

### 3-1. 신설 3문항

| 문항 | 질문 | 선택지 → 가점 |
| --- | --- | --- |
| Q11 (가중 3) | 지금 내 퇴직연금 계좌에서 가장 답이 없는 것은? | 무엇을 살지 고르는 기준 → `signal` / 전체를 얼마씩 나눌지 → `map` / 들어오는 돈을 어떻게 볼지 → `income` |
| Q12 (가중 2) | 최근 가장 후회한 장면은? | 오른 뒤에 따라 샀다 → `signal` / 한 종목에 쏠린 걸 뒤늦게 알았다 → `map` / 분배율만 보고 골랐다 → `income` |
| Q13 (가중 2) | 앞으로 12개월, 계좌에 남기고 싶은 것은? | 교체 신호 규칙 → `signal` / 목표 비율과 점검일 → `map` / 현금흐름 점검 루틴 → `income` |

- 각 니즈 점수 = 선택 가중의 합 (최대 7).
- **시작점 = 최고점 니즈.** 동점 시 ① Q11 선택 우선 → ② 그래도 동점이면 **②편(지도)** 우선.
- **읽는 순서 = 니즈 점수 내림차순**, 동점 규칙 동일.
- ②편 우선 원칙의 근거: 원고 자체가 "1편의 모멘텀과 3편의 배당은 이 지도 위에 놓인다"고 위계를 명시하고 있습니다. 알고리즘이 원고와 모순되지 않아야 합니다.

### 3-2. 기존 5축은 처방에 쓰지 않는다

축 점수는 **처방 카드의 설명 문구**에만 사용합니다(예: "변화가 보일 때 움직이는 편이라 교체 규칙이 있으면 덜 흔들립니다"). 배정 자체에는 개입시키지 않습니다. — 근거 없는 매칭으로 보이지 않게 하기 위함입니다.

### 3-3. 문항이 13개로 늘어나는 것에 대한 방어

- 화면 카피는 **"10문항 + 마무리 3문항"**으로 분리 표기합니다.
- **동물 결과를 먼저 보여주고**, 그 아래에서 3문항을 이어받습니다. 3문항을 건너뛰어도 동물 결과와 공유는 성립합니다(이탈 방어).
- 헤더 칩 문구는 "약 2분 · 10문항" → **"약 3분 · 13문항"**으로 갱신.

## 6. 저장소 실사에서 확인된 함정 (지시서에 그대로 반영)

1. `lib/onboarding/__tests__/style-diagnosis.test.ts`가 **`DIAGNOSIS_QUESTIONS` 10개, 축별 2문항, `STYLE_STORAGE_KEY === "etfcampus.style.v3"`, `diagnoseStyle(answers(1)) === "turtle"`** 을 고정. 문항 추가 시 즉시 실패 → 함께 갱신 필수.
2. `parseStoredDiagnosis`는 `version !== 3`이면 `null`. 스키마를 v4로 올리면 **기존 완료자 결과가 전부 초기화**됩니다 → v3 호환 경로를 두어 동물은 유지하고 3문항만 추가로 받게 해야 합니다.
3. 결과 화면의 `/guides?style=${style}` 링크는 **`app/guides/page.tsx`가 `style` 파라미터를 소비하지 않습니다.** 현재 사실상 죽은 파라미터.
4. `next.config.ts`가 `output: "export"` → **쿠키 기반 hydration 해결안은 이 저장소에서 무효**입니다(요청 시점 서버 렌더가 없음). 초기 깜빡임은 고정 폭 스켈레톤으로 처리.
5. `npm test`는 `verify:utf8`을 먼저 실행. 모든 신규 파일 UTF-8(BOM 없음).
6. Pages Functions는 `.js`(타입 없음), 테스트는 `.test.ts`로 병치 — `functions/api/community/_middleware.test.ts` 선례를 따릅니다.
7. 신규 정적 라우트는 `app/sitemap.ts`에 등록해야 합니다.
