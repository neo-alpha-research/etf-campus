## 1. 【P0】 `prebuild`가 사이트 전체 배포를 멈출 수 있습니다

### 사실

- `package.json` 의 `prebuild` 가 이번 커밋에서 이렇게 바뀌었습니다.
  `… && npx tsx scripts/generate-screener-json.ts && node scripts/generate-style-og-images.mjs`
- `scripts/generate-style-og-images.mjs:3` 은 `import sharp from "sharp";` 를 **가드 없이 최상단에서** 실행합니다.
- 그런데 **`sharp` 는 `package.json` 의 `dependencies` 에도 `devDependencies` 에도 없습니다.** `package-lock.json` 을 확인한 결과 `sharp@0.35.4` 는 **`miniflare` 와 `workers/market-briefing-distributor` 의 전이 의존성으로만** 존재합니다.

### 왜 위험한가

지금 로컬과 GitHub Actions(`npm ci` → 개발 의존성 포함)에서는 우연히 해결됩니다. 그러나 **Cloudflare Pages 빌드가 `NODE_ENV=production` 또는 `npm ci --omit=dev` 로 도는 순간, 혹은 `miniflare` 의 의존성 트리가 바뀌는 순간 `sharp` 가 사라지고 `prebuild` 가 throw 합니다.** `prebuild` 실패는 `next build` 자체를 막으므로 **스타일 페이지가 아니라 사이트 전체가 배포되지 않습니다.**

게다가 **OG PNG 10장은 이미 커밋되어 있습니다.** 매 빌드마다 재생성할 이유가 없습니다. 실패 확률만 새로 만든 셈입니다.

### 조치 (즉시)

1. `prebuild` 에서 `node scripts/generate-style-og-images.mjs` 를 **제거**하고, `"og:style": "node scripts/generate-style-og-images.mjs"` 로 **수동 스크립트 분리**.
2. `sharp` 를 **`devDependencies` 에 명시**(전이 의존성에 기대지 말 것).
3. 스크립트 최상단 import를 동적 import + try/catch로 감싸고, 실패 시 "기존 PNG 유지"로 경고만 남기고 종료(0).
4. OG 자산은 카피가 바뀔 때만 사람이 실행하고 결과 PNG를 커밋합니다.

## 2. 【P0】 OG 카드에 적힌 유형 이름·문구가 사이트와 다릅니다

`scripts/generate-style-og-images.mjs` 가 `lib/onboarding/style-diagnosis.ts` 의 `STYLE_PROFILES` 를 **import하지 않고 스크립트 안에 통째로 복제**했습니다. 그 복제본의 내용이 실제 사이트와 다릅니다.

**이름이 다른 유형 5종**

| 유형 | 사이트 표기 | 공유 카드 표기 |
| --- | --- | --- |
| 다람쥐 | 차곡차곡 살피는 다람쥐 | **부지런한 다람쥐** |
| 코끼리 | 큰 그림을 기억하는 코끼리 | **흔들리지 않는 코끼리** |
| 문어 | 여러 기준을 다루는 문어 | **원문을 파고드는 문어** |
| 독수리 | 시장을 넓게 보는 독수리 | **거시를 굽어보는 독수리** |
| 고슴도치 | 근거를 확인하는 고슴도치 | **기준을 세우는 고슴도치** |

**펀치라인은 10종 중 9종이 다릅니다.** 예:

- 부엉이 — 사이트 "설명글보다 숫자 표를 먼저 열고, 작은 소수점 차이까지 확인해야 잠이 옵니다." / 카드 "느낌으로 사지 않고 수치로 증명된 종목만 남깁니다."
- 코끼리 — 사이트 "단기 등락보다 이 자산군이 내 계좌에서 맡은 원래 역할을 먼저 떠올립니다." / 카드 "하루의 등락보다 10년의 자산배분 지도를 더 신뢰합니다."

바이럴 동선에서 이것이 가장 먼저 보이는 화면입니다. **카카오톡에서 "원문을 파고드는 문어"를 보고 들어왔더니 사이트는 "여러 기준을 다루는 문어"라고 말하는 상태입니다.** 문어 유형의 정체성 자체가 카드는 '원문 검증', 사이트는 '다기준 조율'로 서로 다른 사람을 묘사하고 있습니다.

### 조치

1. 스크립트가 **`lib/onboarding/style-diagnosis.ts` 를 직접 import** 하도록 바꾸십시오(`npx tsx` 로 실행하면 TS를 그대로 읽을 수 있고, `prebuild` 에 이미 `tsx` 를 쓰고 있습니다).
2. 그것이 어렵다면 최소한 **"스크립트의 프로필 문자열과 lib의 값이 100% 일치한다"는 vitest 테스트**를 추가해 다시 벌어지지 않게 하십시오.
3. 카피를 통일한 뒤 **OG PNG 10장을 재생성**하고, 재생성 없이는 카피만 바꾸지 마십시오(이미지는 캐시가 오래 남습니다).

## 3. 【P0】 복제된 카드 카피에 컴플라이언스 위험 문구가 있습니다

이미지는 화면을 떠나 단독으로 유통되고 회수할 수 없습니다. 하단 고지문이 있어도 본문 카피가 아래와 같으면 방어되지 않습니다.

| 유형 | 카드 문구 | 문제 |
| --- | --- | --- |
| 부엉이 | "느낌으로 사지 않고 **수치로 증명된 종목만 남깁니다**" | 종목 선별·추천 뉘앙스 + "증명된"이라는 단정 |
| 고슴도치 | "내 계좌의 방어벽을 먼저 치고, **검증된 ETF만 통과시킵니다**" | 특정 ETF가 검증되었다는 주장 |
| 독수리 | "숲의 방향을 놓치는 **실수를 하지 않습니다**" | 무오류 단정 |

§2의 단일 출처화로 자동 해결됩니다. 사이트의 기존 펀치라인 10종은 이미 이 기준을 통과한 문구입니다.

## 4. 【P1】 기존 사용자의 결과 3.7%가 조용히 사라집니다

`diagnoseStyle` 의 동점 처리를 바꾼 것은 옳은 조치입니다. 다만 `parseStoredDiagnosis` 는 여전히 다음을 유지하고 있습니다 — `lib/onboarding/style-diagnosis.ts:541`, `:576`

```ts
if (value.style !== style) return null;
```

과거 응답으로 저장된 `style` 값과, 새 알고리즘으로 재계산한 값이 다르면 **저장값 전체를 폐기**합니다. 동물 결과뿐 아니라 **처방(3권 읽는 순서)까지 함께 사라지고 헤더 칩이 "진단 미완료"로 되돌아갑니다.**

**구·신 알고리즘 비교 시뮬레이션(기존 1~10 슬라이더 응답 300,000건 무작위)**

- 결과가 바뀌는 비율: **3.7%**
- 소실 분포: 거북이 1.2%p / 부엉이 0.6%p / 돌고래 0.5%p / 코끼리·문어·수달·고슴도치 각 0.3%p

100명 중 4명이 다시 열었을 때 자기 결과가 없어진 화면을 봅니다. 재진단 유도 효과보다 신뢰 손상이 큽니다.

### 조치

응답(`answers`)이 유효하면 **저장된 `style` 과 달라도 폐기하지 말고, 재계산한 값을 채택해 저장값을 갱신**하십시오. 무결성 가드는 `isAnswers()` 검증만으로 충분하며, `style` 필드는 캐시된 파생값으로 취급하는 것이 맞습니다.

## 5. 【P1】 "사진첩에 1초 만에 저장"은 iOS와 앱에서 성립하지 않습니다

`components/onboarding/style-share-bar.tsx:91-95` 의 저장 방식은 `<a download>` + data URL입니다.

- **iOS Safari**: `download` 속성이 data URL에서 동작하지 않습니다. 새 탭이 열리거나 아무 일도 일어나지 않습니다. **사진첩 저장 불가.**
- **Capacitor WebView**(이 저장소는 `@capacitor/*` 앱 래퍼를 씁니다): 동일하게 무반응입니다.
- 정상 동작 범위는 데스크톱 브라우저와 안드로이드 크롬입니다.

인스타 스토리 공유는 대부분 iOS에서 일어납니다. 지금 상태로는 주 타깃에서 기능이 없는 것과 같습니다.

### 조치

1. `navigator.canShare?.({ files: [file] })` 가 참이면 **`navigator.share({ files })`** 로 네이티브 시트를 띄우십시오. iOS에서 "이미지 저장"이 여기서 나옵니다. (dataURL → `fetch(dataUrl).then(r => r.blob())` → `new File([blob], name, { type: "image/png" })`)
2. 실패·미지원 시에만 현행 `<a download>` 폴백.
3. `handleDownloadCard` 의 `alert()` 은 웹뷰에서 이벤트를 막을 수 있고 이미 토스트가 있으므로 **토스트로 통일**하십시오.

크기 자체는 정확합니다 — 540×960 CSS × `pixelRatio: 2` = **1080×1920** 맞습니다.

## 6. 【P1】 분포 검증 수치를 정정하십시오

`lib/onboarding/__tests__/style-distribution.test.ts` 는 LCG 시드를 고정해 **재현 가능**하게 만들었습니다(플레이키하지 않음, 잘한 부분). 다만 20,000회 **표본**이라 보고 수치에 오차가 있습니다.

**4단 척도 전수 계산(4¹⁰ = 1,048,576 조합, 표본 아님)**

| 순위 | 유형 | 점유 | | 순위 | 유형 | 점유 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 거북이 | **17.72%** | | 6 | 여우 | 8.59% |
| 2 | 돌고래 | 16.03% | | 7 | 코끼리 | 7.82% |
| 3 | 부엉이 | 12.68% | | 8 | 독수리 | 6.65% |
| 4 | 고슴도치 | 9.32% | | 9 | 문어 | 6.51% |
| 5 | 다람쥐 | 8.75% | | 10 | 수달 | **5.94%** |

기준(≤25%, ≥4%)은 충족합니다. 다만 보고서의 **"5.8% ~ 16.2%"는 실제와 다릅니다(정확히는 5.94% ~ 17.72%)**. 전수 계산이 1초 안에 끝나므로 테스트를 몬테카를로에서 **전수 열거로 교체**하고, 보고 수치도 갱신하십시오.

참고로 상위 3종 합은 46.4%로, 2지선다안(69.6%)보다 크게 개선됐고 기존 10단(39.2%)보다는 다소 집중돼 있습니다. 수용 가능한 수준입니다.

## 7. 【P2】 남은 공백 4건

1. **계측 이벤트 부재.** `app/layout.tsx` 에 GA4가 붙어 있어 `?ref=` 유입은 `page_location` 으로 관측되지만, **`style_open` / 문항별 이탈 / `style_completed` / `style_share_clicked` 커스텀 이벤트가 하나도 없습니다.** "완주율 개선"을 주장할 근거가 여전히 없습니다. 이 4개 이벤트를 붙이는 것이 다음 순위 1번입니다.
2. **딥링크 착륙 배너 없음.** `/style/turtle/?ref=share_btn` 으로 들어온 친구에게 "친구의 결과는 거북이입니다 → 나도 확인하기" 배너가 없어, 유입이 유형 소개 페이지에서 끊깁니다. 공유는 붙였지만 **받는 쪽 전환 동선이 비어 있습니다.**
3. **카드 하단에 `etf-campus.pages.dev` 하드코딩**(`style-share-bar.tsx` 푸터). 저장된 이미지는 영구히 남으므로 커스텀 도메인으로 옮기면 과거 카드가 죽은 주소를 광고하게 됩니다. 상수로 분리하십시오.
4. **미응시 방문자도 카드를 저장할 수 있습니다.** `/style/[animal]` 페이지에서 `axisScores` 가 없으면 `profile.vector`(이상치 ±1)로 폴백해 축 막대가 8%/92% 극단으로 그려집니다. 카드에 "이 유형의 기준점" 임을 명시하거나, 응시자에게만 저장 버튼을 노출하십시오.

## 8. 프로세스 지적 1건

`main` 브랜치에 직접 커밋·푸시했습니다. Cloudflare Pages가 `main` 을 자동 배포하는 구성이라면 **§1의 빌드 실패 리스크가 검토 없이 곧바로 프로덕션에 도달합니다.** 이 규모의 변경(알고리즘·빌드 파이프라인·공유 자산)은 작업 브랜치에서 검증 후 병합하십시오.
