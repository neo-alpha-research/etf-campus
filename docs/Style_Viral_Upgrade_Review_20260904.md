## 1. 【치명】 2지선다 전환은 진단을 붕괴시킵니다

### 근거

`lib/onboarding/style-diagnosis.ts` 의 산식은 다음과 같습니다.

- `getAxisScores()`: 응답을 `((answer - 1) / 9) * 2 - 1` 로 정규화하고 **축당 2문항 평균**
- `STYLE_PROFILES[*].vector`: 10종 전부 `±1` 좌표(코너)에만 존재
- `diagnoseStyle()`: 유클리드 최근접, 비교가 `distance < nearestDistance` **엄격 부등호**

2지선다로 바꾸면 응답이 `{1, 10}` 두 값뿐이므로 축 점수는 **`{-1, 0, +1}` 세 값**만 나옵니다. 그리고 축 점수가 `0`이면 그 축에서 `-1` 프로필과 `+1` 프로필의 거리가 **정확히 같아집니다.** 동점이 나면 엄격 부등호 때문에 **`STYLE_PROFILES` 객체에 먼저 선언된 유형(= `turtle`)이 채택**됩니다.

### 전수 시뮬레이션 결과 (2¹⁰ = 1,024개 응답 조합 전부 계산)

| 척도 | 동점 발생률 | 평균 동점 후보 | 1위 유형 점유 | 상위 3종 합 | 최하위 |
| --- | --- | --- | --- | --- | --- |
| **2지선다** | **75.4%** | 3.07개 | 거북이 **32.6%** | **69.6%** | 수달 2.2% |
| 4단 척도 | 46.0% | 1.76개 | 거북이 19.9% | 48.7% | 독수리 5.5% |
| 6단 척도 | — | — | 거북이 15.8% | 41.5% | 독수리 7.4% |
| 현행 10단 | 21.0% | — | 거북이 14.9% | 39.2% | 여우 8.0% |

**즉 2지선다에서는 응답자 4명 중 3명의 결과가 본인의 응답이 아니라 코드의 선언 순서로 결정됩니다.** 그리고 3명 중 1명은 거북이가 됩니다.

### 이것이 다른 전략을 연쇄로 무너뜨립니다

- 전략 2-①의 **"상위 8.4%만 보유한 희귀 성향"** 카피는 성립 불가능해집니다. 실제 분포가 32.6% / 2.2%로 벌어지면 희귀도는 재미가 아니라 알고리즘 편향의 증거가 됩니다. **희귀도를 화면에 노출하는 순간, 분포 편향은 사용자에게 보이는 숫자가 됩니다.**
- 전략 2-②의 궁합도 마찬가지입니다. 상대가 거북이일 확률이 3분의 1이면 "우리 팀 유형 맞춰보기"의 재미가 사라집니다.

### 요구 조치

1. **2지선다 대신 4단 선택**을 쓰십시오. 화면은 A/B 두 장 카드를 유지하되, 각 카드에 **"확실히 A / 조금 A / 조금 B / 확실히 B"** 4개 버튼을 배치하면 **터치 1회**로 끝나 인지 부하는 2지선다와 같고 해상도는 유지됩니다. 여유가 있으면 6단을 권장합니다(현행 10단과 거의 동일한 분포).
2. **`diagnoseStyle()`의 동점 처리를 결정론적으로 고치십시오.** 이것은 척도를 안 바꿔도 **현행 10단에서 이미 21% 발생 중인 기존 결함**입니다. 선언 순서 의존을 없애고 2순위 기준(예: 축별 가중 거리 → 여전히 동점이면 미리 정한 우선순위 배열)을 명시하십시오.
3. **분포 시뮬레이션을 vitest 테스트로 고정하십시오.** "전수 조합에서 어떤 유형도 25%를 넘지 않고 4% 미만도 없다"를 회귀 테스트로 박아 두면, 이후 문항·척도를 손댈 때 같은 사고가 재발하지 않습니다.

## 2. 【치명】 `?ref=turtle` 쿼리 공유는 이 저장소에서 미리보기가 뜨지 않습니다

`next.config.ts` 는 `output: "export"` 입니다. 요청 시점 서버 렌더가 없으므로 **쿼리 파라미터는 HTML을 바꾸지 못합니다.** `/style?ref=turtle` 로 공유하면 카카오톡·스레드·인스타가 읽는 OG 메타는 `/style/index.html` 하나뿐이라 **10종 전부 같은 미리보기**가 나갑니다. 제안서 Ⅱ-3-③의 "딥링크 착륙지 배너"는 자바스크립트 실행 후에야 보이는 것이라 미리보기와 무관합니다.

다행히 **경로형 정적 결과 페이지가 이미 구현되어 있습니다.** `app/style/[animal]/page.tsx` 에 `generateStaticParams()`(10종)와 `generateMetadata()`(유형별 OG)가 있습니다.

**요구 조치**

- 공유 URL은 반드시 **`https://etf-campus.pages.dev/style/turtle/`** (경로형, `trailingSlash: true` 준수).
- `?ref=` 는 **유입 계측 파라미터로만** 사용하십시오(`/style/turtle/?ref=share_kakao`).
- **`&name=민준` 은 폐기하십시오.** ① URL에 실명이 들어가면 재공유 경로 전체에 남습니다. ② 정적 export라 서버 측 sanitize 지점이 없어, 파라미터를 그대로 화면에 그리면 문구 조작·스크립트 주입 벡터가 됩니다. 이름 없이 "친구의 결과는 거북이입니다"만으로도 궁합 동선은 그대로 성립합니다.

## 3. 【치명】 지금 공유하면 미리보기가 깨집니다 — 이게 Phase 1보다 먼저입니다

실사 결과 두 가지가 어긋나 있습니다.

- `app/style/[animal]/page.tsx:19` 가 `OG_STYLE_IMAGE_PATH = "/images/og/style"` 를 참조하고 메타에 `{animal}.png` 를 넣고 있는데, **`public/images/og/` 디렉터리 자체가 없습니다.** 현재 상태로 결과 링크를 공유하면 카카오톡·스레드 카드가 **이미지 없이** 나갑니다.

**요구 조치**

- **Phase 0(선행)**: `public/images/og/style/{animal}.png` 10장(1200×630) 생성 + 결과 화면·결과 페이지에 `images/animals/*.jpg` 연결. 이것 없이 공유 버튼을 먼저 다는 것은 첫 바이럴을 회색 박스로 내보내는 일입니다.
- 일러스트가 `.jpg`(불투명 배경)이므로 9:16 카드 합성 시 배경 처리 방식을 먼저 정하십시오.

## 4. 【수정 필수】 "환장의 짝꿍" 카피와 "궁합 85점"

### 4-1. 낙인 문제

제안서 예시 문구 — 돌고래에 대해 **"매일 새로운 테마주 가져와서 원칙 흔들어놓고 혼자 탈출함"**.

10종 중 누군가는 반드시 '환장' 대상이 되고, 그 문구는 **그 유형을 받은 사용자에게도 그대로 보입니다.** 자기 결과 페이지를 자랑하려고 열었더니 다른 사람 화면에서 자기가 민폐로 묘사되는 구조입니다. 확정 규칙(자기비하·조롱 금지)과도 충돌합니다.

MBTI 궁합 바이럴의 동력은 **'대비'이지 '비하'가 아닙니다.** 양쪽 모두 기능적 서술로 바꿔도 공유율 손실은 거의 없습니다.

- `💡 서로를 채워주는 유형` / `⚡ 가장 다르게 보는 유형`
- 돌고래 예: "새로운 시장을 먼저 열어보는 쪽이라, 정해둔 점검일을 지키는 나와 리듬이 가장 다릅니다."

참고로 **`getOppositeStyle()` 이 이미 구현되어 있습니다**(`lib/onboarding/style-diagnosis.ts:411`). 새로 만들 필요 없이 카피만 얹으면 됩니다.

### 4-2. "투자 궁합 점수 85점"

5축 벡터 거리로 유사도 계산은 가능하지만, 그것을 **'투자 궁합'이라 부르는 순간 두 사람의 투자 상성에 대한 주장**이 됩니다. 금융 콘텐츠에서 방어할 수 없고, 85점이라는 두 자리 정밀도는 근거 없는 정확성을 암시합니다.

**대안**: 점수 대신 사실 서술. **"5개 축 중 3개가 반대 방향입니다"**, **"점검 리듬과 확인 깊이가 서로 정반대입니다"**. 공유 재미는 유지되고 주장은 하지 않습니다.

## 6. 컴플라이언스 체크

1. **"상위 8.4%만 보유한 희귀 성향"** → 서열 표현. 확정 규칙 위반입니다. **"전체의 8.4%"** 로.
2. **표본 하한 규칙 유지**: 현재 코드는 누적 300건 미만이면 희귀도를 숨깁니다(`components/onboarding/style-onboarding.tsx:508`). 제안서에 이 규칙이 빠져 있습니다 — 캐릭터 카드에도 동일 규칙을 적용하십시오(표본 부족 시 희귀도 줄 자체를 렌더하지 않음).
3. **다운로드 이미지에 고지 1줄 필수.** 결과 화면 하단의 "금융회사의 투자성향 진단·종목 추천이 아님" 고지는 화면에만 있습니다. **9:16 카드는 화면을 떠나 단독으로 유통되므로**, 이미지 하단에 같은 취지의 한 줄(예: "교육용 콘텐츠 · 투자권유 아님 · ETF 캠퍼스")을 반드시 굽어 넣으십시오.
4. **카카오 공유 문구 "내 퇴직연금 투자 성향은"** → '투자 성향(진단)'은 금융회사 투자성향진단 용어와 충돌합니다. **"ETF 탐색 성향"** 또는 **"ETF 정보 탐색 스타일"** 로.
5. 인스타 스토리 스티커 유도 문구 **"내 연금 동물은 거북이!"** 는 무해합니다. 다만 "연금 동물"보다 "ETF 스타일 동물"이 서비스 정의와 일치합니다.

## 7. 기대 효과 수치는 근거가 없습니다

- **K-Factor 1.2** 는 자기증식 임계값(1.0)을 넘긴다는 주장입니다. 이 수치를 목표로 못 박으면 이후 모든 회고가 실패 보고가 됩니다.
- **완주율 92%** 는 현재 완주율을 모르는 상태에서 세운 목표입니다. 지금 D1에는 **완료된 결과 1건만** 저장되고(`migrations/0018_style_diagnosis_stats.sql`), 진입·이탈·공유 이벤트는 **하나도 계측되지 않습니다.**
- **유입 250%** 는 비교 기준(일반 랜딩)이 존재하지 않습니다.

**요구 조치**: 목표 수치를 먼저 지우고, 아래 5개 이벤트부터 계측하십시오. 2주 baseline 후에 목표를 세웁니다.

## 9. 로드맵 재배열 (권고)

| 단계 | 내용 | 선행 이유 |
| --- | --- | --- |
| **Phase 0** | OG 이미지 10장(1200×630) 생성 + 기존 일러스트 연결 | 없으면 이후 모든 공유가 깨진 카드로 나감 |
| **Phase 1** | 경로형 공유 URL(`/style/{animal}/`) + Web Share + 링크 복사 + 궁합 카피 중립화 | 즉시 효과, 리스크 낮음 |
| **Phase 2** | 척도 4단(또는 6단) 전환 + `diagnoseStyle` 동점 처리 수정 + 분포 회귀 테스트 + 상황극 카피 | **알고리즘 변경이므로 단독 단계로 격리**. 여기서 희귀도 통계 신뢰성이 결정됨 |
| **Phase 3** | 9:16 카드 다운로드(고지 문구 포함) + 딥링크 착륙 배너(이름 없음) + 계측 이벤트 5종 | 카드가 나가기 전에 계측이 붙어 있어야 효과 측정 가능 |
| **별도 판단** | 카카오 SDK | 앱키·도메인 등록·커스텀 도메인 이전 시 재등록·웹뷰 변수. 1차 제외 |

Phase 2를 Phase 1과 합치지 마십시오. 척도 변경은 **기존 완료자의 결과가 바뀔 수 있는 유일한 작업**이라 회귀 검증을 독립적으로 받아야 합니다.

## 10. 이번 개선에서 반드시 지킬 회귀 조건

1. 기존 `etfcampus.style.v4` 저장값 보유자의 **동물 결과가 바뀌지 않을 것**(척도를 바꾸면 과거 응답의 재계산 정책을 명시하고, 재계산하지 않는 쪽을 기본으로).
2. 처방 3문항을 건너뛴 사용자도 결과 화면·공유가 정상 동작할 것.
3. `npm run lint` / `npm test` / `npm run build` 3종 통과, `out/style/{animal}/index.html` 10개 생성 확인.
4. 척도 변경 시 **전수 분포 시뮬레이션 테스트**가 함께 커밋될 것.
5. 다운로드 이미지·공유 카드·결과 페이지 **3곳 모두에 투자권유 아님 고지**가 존재할 것.
