# 역할·권한표

> **문서 상태:** Phase 1 SSOT
> **작성일:** 2026-08-15
> **원칙:** 공개 읽기, 인증 회원 참여, 최소 권한, 서버 측 권한 검증

## 1. 역할 정의

| 역할 | 정의 | 부여 원칙 | 기본 상태 |
|---|---|---|---|
| guest | 인증하지 않았거나 인증 상태가 확인되지 않은 공개 방문자 | 별도 부여 없음 | 모든 방문자는 guest로 시작한다. |
| member | 인증을 완료한 일반 회원 | 승인된 인증 절차 완료 후 부여 | 닉네임을 설정하고 작성·댓글·신고 기능을 이용한다. |
| moderator | 정책 집행을 위임받은 운영 역할 | admin의 명시적 부여와 내부 운영 기준 충족 후 부여 | 콘텐츠 검토·임시 보호·일반 제재를 수행한다. |
| admin | 서비스·정책·역할을 총괄하는 최고 운영 역할 | 최소 인원에게만 명시적으로 부여 | 역할 관리, 최종 제재, 운영 공지, 감사·이의 검토를 수행한다. |

역할은 누적 권한이 아니라 명시적인 서버 측 정책으로 판정한다. 클라이언트에서 버튼이 보이거나 숨겨진 사실은 권한의 근거가 될 수 없다. 어떤 역할도 이메일 인증 식별자, 선택 프로필, 신고자 정보, 내부 감사 기록을 목적 외로 열람하거나 외부에 공개할 수 없다.

| 운영 공지 읽기 | 가능 | 가능 | 가능 | 가능 | 공지는 상단 읽기 전용 영역에 표시한다. |
| 게시물 작성 | 불가 | 가능 | 가능 | 가능 | 인증·입력 검증·속도 제한을 통과해야 한다. |
| 댓글 작성 | 불가 | 가능 | 가능 | 가능 | 인증·입력 검증·속도 제한을 통과해야 한다. |
| 자신의 게시물·댓글 수정 | 불가 | 가능 | 가능 | 가능 | 수정 가능 기간, 수정 이력 공개 정책은 구현 전 별도 확정한다. |
| 자신의 게시물·댓글 삭제 요청 | 불가 | 가능 | 가능 | 가능 | 삭제·익명화·보존 방식은 개인정보 정책의 승인 항목을 따른다. |

| 타인의 게시물·댓글 숨김 | 불가 | 불가 | 가능 | 가능 | 정책 근거·처리자·시각을 내부 기록한다. |

| 장기·영구 제한 | 불가 | 불가 | 제안만 가능 | 가능 | 중대 사안은 admin이 근거와 이력 검토 후 확정한다. |

## 3. 콘텐츠 소유권과 운영 권한의 구분

member는 자신이 작성한 게시물과 댓글을 수정하거나 삭제 요청할 수 있지만, 이미 공개된 콘텐츠의 보존·익명화·삭제는 개인정보 정책과 운영상 예외를 따른다. member는 타인의 글을 편집·삭제할 수 없고, 문제를 발견하면 신고 기능을 사용한다.

moderator는 빠른 안전 조치를 위해 임시 숨김, 신고 분류, 정정 요청, 일반 경고 및 일시 제한을 수행할 수 있다. 그러나 역할 부여, 영구 제한, 정책 문구 변경, 운영 공지의 최종 게시, 보존 정책 변경은 admin의 권한이다. moderator가 자신의 콘텐츠, 자신의 신고, 직접적인 이해관계가 있는 사안을 처리해서는 안 된다.

admin은 최종 책임 역할이지만, 모든 데이터에 무제한 접근할 권한을 의미하지 않는다. admin 역시 목적에 필요한 최소 데이터만 열람하며, 운영자 권한의 사용은 추적 가능한 감사 기록을 남겨야 한다. 관리자 계정의 보안 요구사항, 다중 관리자 승인 여부, 비상 권한 회수 절차는 인증·보안 아키텍처 확정 시 별도 승인한다.

## 4. 권한 검증 요구사항

| 통제 항목 | 요구사항 |
|---|---|
| 인증 확인 | 작성·댓글·신고 요청마다 현재 인증 상태를 서버에서 확인한다. |
| 역할 확인 | 역할은 요청 시점의 서버 권한 정보로 확인하며 클라이언트 전달값을 신뢰하지 않는다. |
| 소유권 확인 | 수정·삭제 요청은 작성자 내부 식별자와 대상 콘텐츠의 소유자를 서버에서 비교한다. |
| 대상 보호 | 숨김·삭제·제재 대상, 신고자, 운영자 메모의 접근은 역할과 업무 필요성에 따라 분리한다. |
| 입력 검증 | 본문·제목·닉네임·신고 사유는 길이·형식·허용 문자·URL 정책을 서버에서 검증한다. |
| XSS 방어 | 사용자 입력은 안전하게 출력하고, 마크다운·HTML·URL 지원 시 허용 목록 기반 정제를 적용한다. |
| 속도 제한 | 작성·댓글·신고·인증 시도별로 서버 측 속도 제한과 악용 감지 정책을 적용한다. |
| 감사 기록 | 제재·역할 변경·민감 접근·정책 예외의 주체·시각·사유·대상을 최소 범위로 기록한다. |

## 5. 권한 운영의 금지 사항

운영 역할은 특정 회원의 비공개 정보·신고 이력·선택 프로필을 투자 권유, 광고, 개인적 호기심, 외부 공유, 차별적 대우에 사용해서는 안 된다. moderator 또는 admin이 커뮤니티의 공개성을 이용해 개인 상담, 투자 리딩, 추천인 활동을 해서는 안 된다. 역할이 부여된 회원도 일반 회원에게 적용되는 투자정보·개인정보·괴롭힘 금지 정책을 동일하게 준수한다.

권한 매트릭스의 상세 상태 값, 운영 도구 화면, 세션 관리, 인증 공급자, 테이블 스키마는 구현 단계에서 별도로 설계한다. 이 문서는 제품 권한의 기준이며, 기술 구현의 대체물이 아니다.
