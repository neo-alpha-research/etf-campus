# 커뮤니티 SSOT 결정 대장

> **문서 상태:** Phase 1 SSOT
> **작성일:** 2026-08-15
> **목적:** 커뮤니티의 제품 범위, 운영정책, 개인정보, 권한, 정보구조 결정과 승인 대기 항목을 단일 기준으로 관리한다.

## 1. 문서 우선순위와 적용 규칙

커뮤니티 관련 제품·운영·개인정보·권한·UI 결정은 이 결정 대장과 연결된 `docs/community/` 문서를 단일 진실 원천(SSOT)으로 한다. 같은 주제의 문서가 충돌하면 다음 순서로 해석한다.

| 우선순위 | 문서 또는 근거 | 적용 방식 |
|---:|---|---|
| 1 | 운영자가 이후 날짜로 승인한 결정 대장 항목 | 명시적으로 기존 결정을 대체한다. |
| 2 | 본 결정 대장과 연결된 Phase 1 커뮤니티 문서 | 현재 커뮤니티 제품·운영 기준으로 적용한다. |
| 3 | 전사·플랫폼 차원의 최신 승인 보안·인증·개인정보 결정 | 이 문서보다 상위의 기술·보안 제약으로 적용한다. |
| 4 | 과거 자문·제안·UX 명세 | 충돌하지 않는 범위에서 참고한다. 승인되지 않은 권고를 구현 결정으로 간주하지 않는다. |

기존 `docs/Community_Board_Compliance_UX_Spec_20260806.md` 및 `docs/Auth_Security_Architecture_Advisory_20260806.md`는 제목과 내용상 **자문·제안 성격의 이전 문서**로 참고한다. 이 문서가 확정한 커뮤니티 구조, 공개 읽기·인증 참여 원칙, 금지행위, 개인정보 최소화 원칙과 충돌하는 부분은 본 Phase 1 SSOT를 우선한다. 단, 이미 별도로 승인된 인증·DB 아키텍처가 존재한다면 그 승인 기록이 본 문서보다 우선하며, 구현 전에 위치와 버전을 확인해야 한다.

## 2. 확정 결정

| ID | 영역 | 결정 | 상태 | 근거 | 구현·운영 영향 |
|---|---|---|---|---|---|
| COM-001 | 제품 목적 | 커뮤니티는 종목 추천이 아니라 ETF 판단 기준을 학습·검증하는 공간이다. | 확정 | 사용자 지시 | 추천·목표가·수익 보장 UX와 문구를 배제한다. |
| COM-002 | 게시판 구조 | 연금 ETF Q&A, ETF 정보·질문, 30일 챌린지, 오류·기능 제안의 4개 영역만 제공한다. | 확정 | 사용자 지시 | 자유게시판·회사생활·정치·시사 일반 게시판은 Phase 1 범위에서 제외한다. |
| COM-003 | 운영 공지 | 상단 읽기 전용 고정 영역으로 제공한다. | 확정 | 사용자 지시 | admin만 최종 게시·고정·해제한다. |
| COM-004 | 이용 권한 | 공개 읽기, 인증 회원만 게시물 작성·댓글·신고 가능하다. | 확정 | 사용자 지시 | 서버에서 인증·역할·소유권을 검증한다. |
| COM-005 | 소통 범위 | 쪽지와 개인 채팅을 제공하지 않는다. | 확정 | 사용자 지시 | DM·개인 상담 유도 기능을 설계하지 않는다. |
| COM-006 | 성과 경쟁 | 수익률·매수 인증 경쟁·투자수익률 순위를 만들지 않는다. | 확정 | 사용자 지시 | 챌린지 지표·보상·피드·프로필에 성과 경쟁 요소를 두지 않는다. |
| COM-007 | 금지행위 | 투자 권유, 수익 보장, 영업·광고 유도, 찌라시, 허위 수익 인증, 개인정보 노출, 비방·도배, 출처 없는 단정, 확인하지 않은 AI 사실 위장을 금지한다. | 확정 | 사용자 지시 | 작성 전 안내, 신고 분류, 제재 기준으로 반영한다. |
| COM-008 | 필수 개인정보 | 이메일 인증 식별자와 공개 닉네임만 필수로 한다. | 확정 | 사용자 지시 | 공개 화면에는 닉네임만 표시한다. |
| COM-009 | 선택 개인정보 | 관심 계좌 유형·투자 경험 구간은 선택으로만 처리한다. | 확정 | 사용자 지시 | 핵심 기능 이용 조건·공개 프로필·광고 타기팅으로 사용하지 않는다. |
| COM-010 | 분리 원칙 | 연령·성별·마케팅 동의는 서비스 이용 필수정보와 분리한다. | 확정 | 사용자 지시 | 동의하지 않아도 핵심 커뮤니티 기능에 불이익을 주지 않는다. |
| COM-011 | 비밀번호 | 서비스가 비밀번호를 직접 저장하지 않는다. | 확정 | 사용자 지시 | 승인된 인증 제공자·안전한 인증 흐름을 사용한다. |
| COM-012 | 역할 | guest, member, moderator, admin 최소 역할 모델을 사용한다. | 확정 | 사용자 지시 | 역할별 최소 권한과 감사 기록을 적용한다. |
| COM-013 | 배포 경계 | 서비스 코드, DB 마이그레이션, 외부 서비스 설정은 Phase 1에서 변경하지 않는다. | 확정 | 사용자 지시 | 본 단계 산출물은 문서로 한정한다. |

## 3. 구현 전 운영자 승인이 필요한 결정

아래 항목은 개인정보·보안·제품·법률상 영향이 크거나 기존 승인 아키텍처 확인이 필요한 사항이다. 선택지를 확정하기 전에는 코드, DB 마이그레이션, 인증 공급자, 외부 서비스 설정을 변경하지 않는다.

| ID | 영역 | 결정 필요 사항 | 선택지 또는 확인 대상 | 결정을 미룰 때의 원칙 |
|---|---|---|---|---|
| PEND-001 | 인증·DB | **해결됨 — ADR-001 승인.** Supabase Auth + Seoul(`ap-northeast-2`)의 커뮤니티 전용 Supabase Postgres를 사용한다. | 이메일 6자리 OTP, Pages Functions API, Supabase RLS를 사용한다. 기존 `ETF_PRICES` D1은 가격 데이터 전용으로 유지한다. | service role 키는 서버 비밀값에만 저장하고 일반 회원 CRUD는 인증 사용자 JWT와 RLS를 우선한다. |
| PEND-002 | 탈퇴 콘텐츠 | **해결됨 — 탈퇴 화면에서 이용자가 선택.** 공개 게시물·댓글을 익명화 유지하거나 모두 삭제한다. | 익명화 시 작성자 연결을 되돌릴 수 없게 제거하고 “탈퇴한 사용자”만 표시한다. 삭제 선택 콘텐츠는 즉시 공개 노출을 중단하고 최대 30일 내 물리 삭제한다. | 이메일·내부 사용자 ID·기존 닉네임 연결을 유지하지 않는다. |
| PEND-003 | 보존 기간 | **해결됨 — 인증 계정·이메일 식별자·닉네임·선택 프로필은 탈퇴 처리와 함께 삭제하고 최대 7일 내 완료한다.** | 신고·제재 기록은 처리 종료일로부터 1년, 관리자·개인정보취급자 감사 기록은 원칙 1년(법령상 조건 시 2년), 일반 로그인 실패·악용 탐지 로그는 90일, 암호화 비공개 백업은 30일 롤링 후 자동 파기한다. | 법적 분쟁·보안사고 건은 해결 시점까지 제한 보관 후 1년 이내 삭제한다. 캐시·검색 인덱스는 즉시, 백업은 최대 30일 내 반영한다. |
| PEND-004 | 법률·고지 | 개인정보 처리방침, 이용약관, 투자정보 고지, 제재·이의 문안의 적정성 | 적격 개인정보·법률·금융 규제 검토 | 법률 효과를 확정적으로 표시하지 않는다. |
| PEND-005 | 운영 인력 | **해결됨 — 초기 admin 1명, moderator 없음.** | admin은 이메일 OTP 가입 후 서버 측 일회성 절차 또는 Supabase 관리 콘솔에서 UUID 기준으로 지정한다. 역할 변경은 보호된 서버 절차·보호 테이블만 가능하며 감사 기록을 남긴다. | 장기·영구 제재는 즉시 임시 제한 후 최소 24시간 뒤 근거를 재검토한다. 향후 moderator 또는 두 번째 admin 도입 시 최초 처리자와 다른 사람이 검토하도록 전환한다. |
| PEND-006 | 안전 통제 | 속도 제한값, CAPTCHA, 금칙어·URL 정책, AI·스팸 탐지, 감사 로그 세부 | 위협 모델·인프라·운영 역량 기준 확정 | 정확한 임계값을 문서·UI에 노출하지 않는다. |
| PEND-007 | 콘텐츠 기능 | 수정 가능 기간·수정 이력 표시, 링크 허용 범위, 첨부·이미지·검색·알림 지원 | 텍스트 중심 유지 또는 별도 단계 확장 | Phase 1에는 첨부·이미지·DM을 포함하지 않는다. |
| PEND-008 | 메뉴 배치 | **해결됨 — 상단 메뉴에 `커뮤니티`를 추가한다.** | 순서는 `ETF 탐색 / ETF 비교 / 시장 브리핑 / 투자 가이드 / 커뮤니티 / 북 큐레이션`으로 한다. | 기존 5개 메뉴의 명칭·경로·정적 동선을 제거하지 않는다. |

## 4. 단계 경계와 변경 통제

Phase 1은 SSOT 문서화 단계다. 다음 변경은 명시적인 다음 단계 승인 없이는 수행하지 않는다.

| 변경 유형 | Phase 1 허용 여부 | 비고 |
|---|---:|---|
| `docs/community/` 문서 추가·수정 | 허용 | 본 대장의 우선순위와 승인 상태를 유지한다. |
| 기존 서비스 코드 수정 | 불가 | UI·라우트·API·컴포넌트를 포함한다. |
| DB 스키마·마이그레이션 | 불가 | D1, 외부 DB, 로컬 스키마 모두 포함한다. |
| 인증·외부 서비스 설정 | 불가 | 시크릿, 환경 변수, 공급자 설정, OAuth 설정을 포함한다. |
| 기존 ETF 데이터 빌드 수정 | 불가 | 수집·정제·배치·정적 데이터 경로를 포함한다. |
| 신규 커뮤니티 브랜치의 문서 커밋 | 허용 | 코드 변경 없이 논리적 문서 단위로 커밋한다. |
