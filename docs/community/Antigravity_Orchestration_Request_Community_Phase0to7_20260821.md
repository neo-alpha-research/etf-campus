## 2-1. cp949 복원은 불가능합니다 — 대신 git 이력에서 복구하십시오

메모는 이렇게 지시했습니다.

> 복구 방법은 각 파일 바이트를 cp949로 디코딩해 원문이 복원되는지 확인한 뒤 UTF-8로 재저장하는 것입니다.

**이 방법은 동작하지 않습니다.** `functions/api/community/posts/index.js`를 실제로 시험한 결과입니다.

```
utf-8    실패: UnicodeDecodeError
cp949    실패: UnicodeDecodeError
euc-kr   실패: UnicodeDecodeError
```

손상 구간의 실제 바이트입니다.

```
b'UNAVAILABLE", "\xec\xbb\xa4\xeb??\x88\xed\x8b\xb0 \xea\xb8\x80??\xeb\xb6\x88\xeb\x9f\xac?????\x86\xec\x8a\xb5?\x88\xeb\x8b\xa4."'
                     └─"커"─┘  └┬┘                        └┬┘
                          정상 UTF-8   0x3F('?')로 대체되어 소실된 바이트
```

정상 UTF-8 바이트 사이사이에 **리터럴 물음표(0x3F)가 박혀 있습니다.** 원래 바이트가 `?`로 치환되어 **정보가 소실된 상태**입니다. 어떤 인코딩으로 디코딩해도 복원되지 않습니다. PowerShell이 cp949 콘솔을 경유해 UTF-8 텍스트를 쓸 때 나오는 전형적인 패턴입니다.

**올바른 복구 경로는 git 이력입니다.** 손상을 넣은 커밋을 특정했습니다.

```
3c79939a93321b5cc4524e04faa88bc84a6919be  2026-08-16
fix-functions-scope-community-helpers-to-pages-bundle
```

이 커밋이 손상된 6개 파일을 모두 건드렸고, **그 직전 상태(`3c79939a^`)에는 정상 UTF-8 원문이 남아 있습니다.** `posts/index.js`의 경우 `8f8934ac`(2026-08-15) 버전이 정상임을 확인했습니다.

프롬프트에는 이렇게 쓰십시오.

- `git show 3c79939a^:<파일경로>`로 손상 이전 버전을 꺼낸다
- 그 버전에서 **한글 문자열 리터럴만** 추출한다
- 현재 파일의 손상된 문자열을 그것으로 교체한다. **로직은 현재 파일 것을 유지한다** — 그 사이에 보안 수정 등이 들어갔을 수 있다
- 이전 버전에 없는 신규 문자열은 의미에 맞게 새로 작성한다

## 3-1. Supabase 실제 스키마 조회

커뮤니티는 D1이 아니라 Supabase입니다. `posts/index.js`가 `community_public_posts` 뷰와 `create_community_post` RPC를 호출합니다.

```sql
-- 테이블·뷰 목록
select table_name, table_type from information_schema.tables
 where table_schema='public' order by table_name;

-- 커뮤니티 관련 함수 정의 전체
select p.proname, pg_get_functiondef(p.oid)
  from pg_proc p join pg_namespace n on n.oid=p.pronamespace
 where n.nspname='public' and p.proname like '%community%';

-- 뷰 정의
select table_name, view_definition from information_schema.views
 where table_schema='public' and table_name like 'community%';
```

**게시글 생성이 SECURITY DEFINER RPC를 경유하므로, 구조화 필드(`is_pinned`, `visibility` 등)를 추가하려면 Postgres 함수 자체를 수정해야 합니다. Workers 코드만 고치면 필드가 저장되지 않습니다.** 이 점을 프롬프트에 명시하십시오.

```sql
select jobid, schedule, command, active from cron.job;
select jobid, status, start_time, end_time, return_message
  from cron.job_run_details order by start_time desc limit 20;
```

## 3-3. 관리자 인증 경계 확인 — 설계 판단이 필요합니다

모더레이션 화면에 대해 메모는 "기존 관리자 인증 체계(`admin_users`, `admin_user_sessions`)를 재사용하십시오"라고 했습니다. 그런데 확인해 보니 이렇습니다.

| 대상 | 저장소 |
| --- | --- |
| `admin_users`, `admin_user_sessions` | **Cloudflare D1** (`migrations/0008_market_briefing_editorial.sql`, `0009_...`) |
| 커뮤니티 게시물·댓글·회원 | **Supabase Postgres** |

즉 "D1 세션으로 인증하고 Supabase 데이터를 조작"하는 구조가 됩니다. 이는 저장소 전반의 아키텍처 원칙 — **"장애·권한·개인정보 경계를 분리하기 위해 의도적으로 나누었으므로 절대 결합하지 마십시오"** — 와 정면으로 부딪힐 소지가 있습니다.

선택지는 최소 세 가지입니다.

1. D1 admin 세션으로 인증 → Workers가 Supabase service role로 숨김 RPC 호출 (경계는 Workers 한 곳에만)
2. Supabase 쪽 `community_user_roles`의 admin 역할을 그대로 써서 커뮤니티 내부에서 완결 (D1과 무관)
3. 두 인증을 모두 요구 (가장 안전, 운영 부담 큼)

**이건 당신이 임의로 정할 사안이 아닙니다.** 조사 결과와 함께 세 안의 장단점을 정리해 **운영자에게 확인받은 뒤** 해당 단계 프롬프트를 작성하십시오. 확인 전에는 2단계 프롬프트에서 모더레이션 항목을 "운영자 결정 대기"로 표시해 두십시오.

# 5. 모든 프롬프트에 공통으로 넣을 작업 규칙

아래를 **각 프롬프트 파일마다 빠짐없이** 포함하십시오. 요약하지 말고 그대로 옮기십시오.

1. **증분 편집만.** 기존 파일을 통째로 다시 쓰지 마십시오. 파일 전체를 생성하는 스크립트 방식을 금지합니다. 1단계 인코딩 복구만 예외이며, 그 경우에도 문자열만 교체합니다.
2. **완료 보고에 `git diff --stat`을 반드시 포함.** 삭제 줄 수가 추가 줄 수보다 많은 파일이 있으면 사유를 별도로 설명해야 합니다.
3. **임시 파일·백업 파일을 저장소에 남기지 마십시오.** 커밋 전 `git status --porcelain`을 확인하십시오.
4. **기존 타입 계약을 변경하지 마십시오.** 프런트엔드 훅이 소비하는 응답 형태를 바꿔야 한다면 구현을 멈추고 질문하십시오.
5. **모든 파일은 UTF-8(BOM 없음)로 저장하고 저장 후 검증하십시오.**
6. **각 단계 완료 시 회귀 테스트를 함께 추가하십시오.** 기존 테스트를 삭제·skip·완화하지 마십시오.
7. **문서에 없는 결정이 필요하면 임의로 정하지 말고 질문하십시오.**

여기에 이 저장소의 사고 이력에서 나온 규칙을 더하십시오.

8. **PowerShell로 파일을 쓰지 마십시오.** `>`·`>>`·`Set-Content`·here-string 모두 금지입니다. 이 저장소에서 실제로 세 번 사고가 났습니다 — ① 테스트 파일에 UTF-8 BOM 삽입 ② here-string이 백틱과 `${...}`를 변수로 해석해 치환이 조용히 실패 ③ `>>`가 UTF-16LE로 기록해 `.gitignore`를 바이너리로 만듦. 에디터 도구로 편집하십시오.
9. **정규식 일괄 치환으로 기존 파일을 수정하지 마십시오.** 이 경로에서 `functions/api/briefings/latest.js`의 핵심 로직이 통째로 유실된 전례가 있습니다.
10. **`git checkout -- <file>`로 되돌린 뒤 재적용하는 패턴을 쓰지 마십시오.** 위 유실이 그 경로에서 발생했습니다.
11. **`git add .`와 광범위 글로브(`git rm *.py` 등)를 쓰지 마십시오.** 경로를 명시하십시오. 실제로 `git rm *.py`가 `scripts/` 하위 파이썬 121개까지 삭제할 뻔했습니다.
12. **테스트 실패를 "환경 한계"로 분류하지 마십시오.** 실패는 기본적으로 코드가 틀렸다는 신호입니다. 원인을 규명한 뒤에만 다른 판정을 내리십시오. 실제로 실패한 테스트를 모킹 문제로 넘겼다가, 그 테스트가 가리키던 것이 작업의 유일한 목적이었던 사고가 있었습니다.
13. **빌드 통과는 검증이 아닙니다.** 실제 요청을 보내 응답을 확인한 증빙을 제시하십시오. 확보하지 못했으면 "미확보"라고 그대로 적으십시오. **확보하지 못한 것을 확보했다고 적는 것만이 문제입니다.**
14. **리포트는 실제 수행한 명령·결과와 일치해야 합니다.**

# 6. 컴플라이언스 — 프롬프트에 반드시 반영

이 서비스는 판단 기준 학습이 목적입니다. 생성되는 어떤 코드·문구·시드 콘텐츠에도 아래가 들어가면 안 됩니다.

- ETF 종목 추천, 매수·매도 신호, 목표가, 수익 보장 문구
- 개인 수익률·보유 금액·수익 인증을 지표나 보상으로 삼는 설계

비밀값(service role key, Turnstile secret, SMTP 자격증명, 세션 토큰, OTP)과 실제 이용자 이메일·개인정보를 코드·로그·테스트 fixture·문서에 노출하지 마십시오.
