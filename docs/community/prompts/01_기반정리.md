# Antigravity 인계 프롬프트 — Phase 0: 기반 정리

당신은 이미 Production에서 운영 중인 `neo-alpha-research/etf-campus` 커뮤니티의 백엔드 결함을 복구하고 유지보수하는 시니어 엔지니어입니다.

**주의**: 이 프로젝트는 기능 신규 구축이 아니라 운영 중인 시스템의 개선 작업입니다.

## 아키텍처 경계
- 커뮤니티 = **Supabase (Postgres)**
- ETF 가격/관리자 인증 = **Cloudflare D1 (SQLite)**
이 둘은 물리적으로 분리되어 있으며 절대 결합하지 마십시오.

## 런타임 제약
- Next.js는 `output: "export"` 및 `trailingSlash: true` 로 정적 빌드됩니다. (동적 라우트 불가, 쿼리 파라미터 사용)
- Cloudflare Pages Functions는 Node가 아닌 Workers 런타임입니다 (`Buffer`, `node:crypto`, `fs` 모듈 사용 불가).
- **Supabase SDK 없음**: `@supabase/supabase-js`는 존재하지 않으며, `functions/api/community/_lib/supabase.js`에 구현된 자체 REST 클라이언트를 사용해야 합니다. 

## 선행 조건
- 직전 `PR #13`, `#14`, `#15` 가 `main`에 모두 머지되었는지 먼저 확인하십시오. 
- 커서가 `main` 최신 커밋을 가리키는지 점검하십시오.

## 작업 명세

### 1. 인코딩 손상 파일 복구
`functions/api/community/` 하위 파일 중 아래 6개 파일의 한글 에러 문자열이 손상되어 U+FFFD(물음표)로 깨져 있습니다. **문자열만 교체하고 로직은 절대 손대지 마십시오.** (보안 패치가 덮어씌워질 수 있습니다.)
- `functions/api/community/auth/account.js`
- `functions/api/community/auth/config.js`
- `functions/api/community/auth/profile.js`
- `functions/api/community/posts/index.js`
- `functions/api/community/posts/[slug]/comments.js`
- `functions/api/community/posts/[slug]/comments/[commentId].js`

**복구 지침**:
1. `git log -S "손상된문자열"` 등을 통해 `3c79939a^` 커밋 시점 등의 과거 원본 파일(예: `8f8934ac` 시점)을 조회하십시오.
2. 과거 파일에서 **한글 문자열 리터럴만 추출**하십시오. (예: "커뮤니티 글을 불러올 수 없습니다.")
3. 현재 손상된 파일에서 **문자열 부분만** 복원하십시오.

### 2. `error.code` 판정 전환
`components/community/community-post-detail.tsx` 파일에서 게시물 not-found 판정 시, 깨진 한글 문구 `===` 비교로 된 로직을 `error.code === "NOT_FOUND"` 로 변경하십시오. (PR #13이 이미 백엔드에서 `code`를 반환하도록 수정했습니다.)

### 3. 잔재 파일 제거
저장소 루트에 있는 `temp.json` (약 1.8MB) 파일을 Git에서 추적 해제하고 제거하십시오.
- `git rm temp.json`

(참고: `functions/api/briefings/latest.js.tmp`는 이미 정리되어 없으므로 무시하십시오.)

### 4. UTF-8 인코딩 검증 스크립트 추가
저장소 전체의 한글 깨짐을 방지하기 위해, UTF-8(BOM 없음) 및 U+FFFD 포함 여부를 검사하는 CI용 스크립트 `scripts/verify-utf8.mjs` 를 생성하고, `package.json`의 `test` 스크립트 실행 시 함께 동작하도록 연동하십시오.

## 작업 규칙 (금지 사항)
1. **증분 편집만.** 파일 전체를 재작성/생성하는 스크립트 방식 금지. 인코딩 복구도 리터럴 교체만 수행.
2. **`git diff --stat` 반드시 포함.** 삭제 라인이 추가 라인보다 많다면 이유를 명시하십시오.
3. 임시 파일, 백업 파일 저장소에 남기지 마십시오.
4. 기존 타입 계약 절대 변경 금지.
5. 모든 파일은 UTF-8(BOM 없음)로 저장하십시오.
6. 실패한 테스트를 환경 한계로 핑계대지 마십시오.
7. **PowerShell로 파일 생성·수정 금지** (`> `, `>>`, `Set-Content` 금지). 반드시 에디터 도구/Node 스크립트로 작성하십시오.
8. **정규식 일괄 치환(Sed 등) 금지.** 과거 핵심 로직 유실 전례가 있습니다.
9. `git checkout -- <file>` 후 덮어쓰기 금지.
10. `git add .` 및 광범위 패턴(`git rm *.py`) 사용 금지. 대상을 명확히 지정하십시오.
