# Antigravity 인계 프롬프트 — Phase 1: 커뮤니티 기반 확장

당신은 이미 Production에서 운영 중인 `neo-alpha-research/etf-campus` 커뮤니티의 백엔드 및 프론트엔드를 확장하는 시니어 엔지니어입니다.

## 아키텍처 경계
- 커뮤니티 데이터 = **Supabase (Postgres)**
- 이 작업은 커뮤니티 데이터 확장이므로 Supabase 마이그레이션과 Workers API, 클라이언트 렌더링에만 집중합니다. D1과는 결합하지 마십시오.

## 런타임 및 환경 제약
- Next.js 정적 빌드(`output: "export"`, `trailingSlash: true`). 동적 라우트 사용 불가.
- Cloudflare Workers 런타임 (`Buffer`, `node:crypto`, `fs` 금지).
- **Supabase SDK 없음**: `functions/api/community/_lib/supabase.js` 에 있는 REST 기반 자체 구현 객체 사용. 없는 기능은 최소한으로 `fetch`를 이용해 확장.

## 선행 조건
- 직전 `01_기반정리.md` 작업이 완료되었는지 확인하십시오. (UTF-8 에러 복구 등)

## 작업 명세

### 1. `notice` 카테고리 추가
기수 공고와 규칙을 위한 카테고리를 신설합니다.
- 작성 권한은 `moderator` 이상(현재 `admin`, `moderator` 역할)으로 제한합니다. 역할 검증은 이미 존재하는 `contracts.ts`와 DB의 `community_user_roles` 권한 테이블을 활용하십시오.

### 2. 고정 게시물(`is_pinned`) 체계
- 게시물 속성에 `is_pinned` (boolean) 필드를 추가합니다.
- `create_community_post` RPC나 별도 RPC를 통해 `moderator` 이상만 해당 플래그를 수정할 수 있게 변경하십시오. 
- **⚠️ RPC 수정 주의**: 구조화 필드를 추가하려면 `functions/`가 아니라 Postgres **함수 자체를 마이그레이션으로 수정**해야 합니다. `create_community_post`의 시그니처를 수정하여 처리하십시오.
- **제약 조건**: 카테고리별로 `is_pinned` 게시글은 **최대 3건**까지만 허용합니다. (DB 제약조건이나 트리거, 혹은 RPC 로직에서 방어)
- 목록 API(`GET /api/community/posts`) 반환 시 고정 게시글을 상단에 정렬하고, 그 이하는 `created_at` 내림차순으로 정렬하십시오.

### 3. 페이지네이션 (커서 기반 + 더보기)
현재 50건 `limit`만 있어 과거 글로 도달할 수 없습니다. 챌린지가 진행되면 며칠 만에 초기 데이터가 뒤로 밀립니다.
- API 및 뷰 쿼리에 커서 기반 페이지네이션(Cursor-based Pagination)을 구현하십시오. 
- 카테고리 필터와 호환되게 설계하고, 프론트엔드 피드 하단에 "더보기" 버튼을 배치하십시오.

### 4. 저자 시드 배지 추가
- `is_author_seed` 플래그(기본 false)를 추가합니다. `moderator` 이상만 설정 가능합니다.
- 이 글은 챌린지 완주 판정 집계 및 통계에서 **제외**되어야 합니다.
- 피드 목록 및 상세 페이지에 시각적으로 "저자 기록"이라는 뱃지가 노출되도록 뷰를 수정하십시오.

### 5. 모더레이션 기능 — [운영자 결정 대기: 구현 유예]
게시물 숨김 처리 등 관리자 모더레이션을 위한 인증 경계에 대해 아래와 같이 조사되었습니다.
- 커뮤니티 데이터는 Supabase, 기존 관리자 세션은 D1입니다.
- **조사 및 권고:** D1과 결합하는 것은 아키텍처 경계를 침범하므로, Supabase 내부의 `community_user_roles` (`admin`, `moderator`)를 활용해 커뮤니티 전용 계정/세션으로 모더레이션 권한을 통제하는 방안(2안)이 구조적으로 가장 안전합니다.
- **현재 지시**: 이 단계에서는 모더레이션(숨김 토글/UI) 기능 구현을 보류하십시오. 운영자의 방안 확정 전까지는 작업하지 마십시오.

## 필수 테스트 시나리오
| 검증 항목 | 목적 |
| --- | --- |
| `notice` 카테고리 권한 | 일반 회원이 `notice` 작성 시도 시 403 차단, moderator 작성 시 성공 |
| 고정 게시글 제한 및 정렬 | 한 카테고리에 고정 글 4개째 시도 시 실패, 조회 시 고정 글이 최상단 노출 |
| 커서 기반 페이지네이션 | "더보기" 요청 시 중복이나 누락 없이 이전 글이 이어서 조회됨 |
| 저자 시드 조회 | `is_author_seed=true` 인 게시글에 배지 속성이 반환되며 집계 테스트 시 배제됨 |
