# Antigravity 인계 프롬프트 — Phase 2: 시드 콘텐츠 등록 도구

당신은 운영 중인 `neo-alpha-research/etf-campus` 프로젝트의 백엔드 엔지니어입니다.

## 목적
커뮤니티 초기 개설 시 첫 방문자가 "빈 화면"을 보지 않도록, 운영자가 대량의 시드(Seed) 게시물(저자 완주 기록 30건, 공지, Q&A)을 미리 작성하고 발행할 수 있는 도구를 제공합니다. 실제 콘텐츠 작성은 운영자의 영역이므로 **도구 개발까지만** 담당하십시오.

## 런타임 제약
- 이 스크립트는 로컬 환경(운영자의 PC)에서 Node.js 로 실행할 일괄 등록 유틸리티입니다. `scripts/` 디렉토리에 위치해야 합니다.
- Supabase REST API(`functions/api/community/_lib/supabase.js`의 논리와 유사하게, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 사용해 직접 DB에 꽂아 넣거나 Admin API를 호출)를 사용하십시오.

## 작업 명세

### 시드 일괄 등록 스크립트 작성
`scripts/seed-community-posts.mjs` 를 생성하십시오.
- 마크다운 파일들의 묶음(특정 디렉토리, 예: `content/seeds/`)을 읽어 일괄 등록합니다.
- 마크다운 파일의 **Frontmatter(YAML)** 를 파싱하여 `title`, `category_slug`, `day_number`, `is_author_seed`, `is_pinned` 등의 값을 추출합니다.
- 마크다운 파일명(예: `day01-initial.md`)을 읽어 Day 번호나 순서를 판별할 수 있게 하십시오.
- DB에 직접 삽입하거나 관리자 RPC를 호출해 게시물을 생성합니다. (기수 식별자 `cohort_id` 등 필요한 필드는 CLI 인자나 .env에서 주입받도록 구성)
- 이미 등록된 시드를 멱등적으로 덮어쓰거나, 스킵하는 방어를 갖추십시오.

### 화면 연동
- Phase 1에서 구현한 `is_author_seed` 뱃지와, Phase 4에서 구현할 Day 기반 화면 등에서 이 글들이 정상적으로 렌더링될 수 있는 구조인지 확인만 하십시오. (추가 컴포넌트 수정 없음)

## 검증 절차 및 필수 테스트
- 스크립트를 로컬 더미 폴더에 대해 실행했을 때 정상적으로 Supabase API (또는 로컬 모킹 API) 호출 페이로드가 만들어지는지 확인(단위 테스트 혹은 Dry-run 옵션).
- 프론트매터 파싱 에러(필수값 누락) 시 명확한 에러 메시지 출력 여부.

## 산출물
- `scripts/seed-community-posts.mjs` 및 관련 마크다운 파싱 의존성(`gray-matter` 등 필요 시 최소 추가).
- 사용 가이드를 `README.md` (스크립트 상단 혹은 디렉토리 내부) 에 요약 기록.

## 작업 규칙 (금지 사항)
- 증분 편집 준수 (해당 스크립트 외 다른 파일 수정 시 기존 코드 파괴 금지).
- 임시 파일 남기지 않음.
- PowerShell 리터럴 문자열 생성 금지 (에디터/Node 파일 시스템 사용).
- 광범위 패턴(`git add .`) 사용 금지.
- **운영자가 넣을 콘텐츠 내용(ETF 종목, 수익률 등)을 스크립트의 기본 더미 텍스트로 임의 창작하지 마십시오. 오직 툴 자체만 제공합니다.**

## 운영자 결정 대기 항목
- 예약 발행 기능 유무: 1기 규모에서는 수동 발행이 무방하므로 현재 별도의 `publish_at` 자동화 스케줄러는 구축하지 않습니다 (Over-engineering 방지).
