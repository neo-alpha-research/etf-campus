# Antigravity 인계 프롬프트 — Phase 3: 리드마그넷 게이트 및 뉴스레터

당신은 운영 중인 `neo-alpha-research/etf-campus` 프론트엔드를 확장하는 시니어 엔지니어입니다.

## 목적
커뮤니티 유입을 늘리기 위해 랜딩 페이지에 번들(전자책 맛보기, 원칙 카드 등)을 소개하고, 이메일을 수집하는 게이트(폼)를 배치합니다. 

## 런타임 제약
- Next.js 정적 빌드(`output: "export"`)

## 작업 명세

### 1. 랜딩 페이지 리드마그넷 섹션 구현
- `app/(landing)/page.tsx` (또는 기존 랜딩 페이지 위치)에 번들 소개 영역을 배치합니다.
- 상단에 **자산 5종**을 카드로 나열하십시오 (제목, 한 줄 설명, 형식). (자산 내역: 1편 맛보기 PDF, 30일 맛보기 PDF, 바이브코딩 프롬프트팩, DC Alpha Scanner, 원칙 카드 7종)
- 하단에 **이메일 입력 폼 하나**와 **동의 체크박스 2개**(필수: 이용약관/개인정보, 선택: 광고성 수신)를 둡니다.
- **주의**: 입력 필드는 반드시 "이메일 하나"뿐이어야 합니다. 이름/연락처 등 다른 필드를 추가하지 마십시오. (전환율 하락 방지)

### 2. 이메일 수집 및 유입 연동
- 이메일 제출 시 이중 확인(Double Opt-in) API를 호출하도록 연동합니다. (다운로드 링크는 이메일 확인 완료 후 활성화)
- 제출 폼 하단에 **커뮤니티 최신 게시물 3건**을 노출하는 컴포넌트를 추가하십시오. (Phase 1, 2에서 시딩된 게시물이 노출되어 커뮤니티로 자연스럽게 유입되도록)

## 필수 테스트 시나리오
| 검증 항목 | 목적 |
| --- | --- |
| 랜딩 렌더링 | 필수 필드(이메일, 필수 동의)만 체크하여 제출이 정상 동작하는지 UI 렌더링 검증 |
| 최신 게시물 연동 | 하단 커뮤니티 섹션이 API `limit=3`으로 최신 글(고정 글 제외 또는 포함)을 정상 호출하는지 검증 |

## 작업 규칙 (금지 사항)
- 증분 편집 준수 (파일 전체 교체 금지).
- `git diff --stat` 제출 필수.
- 새로운 알림 발송 인프라(SMTP, 외부 연동)를 서버 백엔드에 직접 구축하지 마십시오. 현재 이 저장소의 `scripts/newsletter`는 HTML 렌더링용이며 발송 로직이 없습니다. 프론트엔드의 폼 컴포넌트와 API Endpoint 호출 껍데기만 구성하십시오.

## 운영자 결정 대기 항목
- 실제 발송 SMTP/API 인프라는 외부 플랫폼(Stibee, Mailchimp 등)을 쓸지, 자체 발송 기능을 붙일지는 이 PR 외부에서 결정됩니다. 본 작업은 폼 UI와 껍데기 호출부까지만 책임집니다.
