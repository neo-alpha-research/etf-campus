# Antigravity 인계 프롬프트 — Phase 5: 기록 게시판

당신은 운영 중인 `neo-alpha-research/etf-campus` 프론트엔드 및 백엔드를 확장하는 시니어 엔지니어입니다.

## 목적
30일 챌린지 인증(명칭: "기록")을 위한 특수 게시판 뷰와 작성 폼을 개발하고, 백엔드 RPC를 확장합니다.

## 작업 명세

### 1. RPC 및 스키마 확장 (Supabase 마이그레이션)
`challenge-30` 카테고리의 구조화된 게시물 저장을 위해 `create_community_post` RPC를 수정하고 테이블 구조를 확장해야 합니다. (별도 마이그레이션 파일 추가)
- 추가 필드: `day_number`(1~30 정수), `cohort_id`, `metric_key`(화이트리스트만 허용), `metric_value`(숫자), `visibility`("cohort" | "public", 기본값 "cohort").
- `created_at`은 클라이언트가 보낸 값을 버리고 무조건 **서버(DB) 시간**으로 기록해야 합니다.
- 금칙 표현 차단 로직(정규식 등)을 RPC나 트리거 레벨에 두어 백엔드 2차 검증을 수행하십시오. 
- 직전 기록과 `body_text`가 완전히 동일한 경우 반려하는 로직(어뷰징 차단)을 추가하십시오.

### 2. 작성 폼 (프론트엔드 `challenge-30` 특화)
핵심 원칙: **필수 입력 2개, 나머지 선택.** (백지 공포 제거)
- **Day**: 기수 시작일 기반 자동 계산 (수정 가능). 마감 기한이 지난 경우 경고 표시.
- **오늘의 과제 (읽기 전용)**: 숨기지 않고 항상 노출. (원문: `D:\Pension_ETF\Reports\30일_챌린지_인증과제_설계제안_20260806.md` 내용 사용, 절대 각색 금지)
- **본문 (필수, 30~1000자)**: Placeholder에 저자 시드 기록 링크를 포함. 절대금액 패턴(만원, 억) 입력 시 차단은 안 하되 경고 노출.
- **오늘의 숫자 (선택)**: Day별로 라벨 변경 (예: Day 3은 "원리금보장 비중(%)"). **절대금액 단위는 어느 Day에서도 제공 금지.**
- **공개 범위**: 기본값 '같은 기수'(`cohort`).
- 반복 작성 마찰 제거: 두 번째 작성부터 이전 공개 범위/옵션 기본값 복원, 진입 시 Day 자동 채움.

### 3. 목록 페이지 (뷰)
모바일 퍼스트(Threads 인앱 브라우저 고려).
- 상단 규칙 노출: "게시물의 수치는 작성자 본인이 입력한 값이며 서비스가 검증하지 않습니다." (인증 → 기록 용어 통일)
- **내 진행 카드**: 달성률 원형 차트, 마감 카운트다운, 마일스톤 진행 바 노출. 
- **30칸 상태 그리드**: 1~30 Day 달성 현황(달성/지각/미달성/예정) 노출.
- **필터 칩**: 전체, 내 기수, 오늘의 Day, 저자 기록, 내 글 (인기순/추천순 **절대 금지**).
- 반응 버튼은 "좋아요"가 아닌 **"응원"**으로 라벨링.
- 데스크톱 화면에서만 우측 사이드 히트맵 배치.

## 필수 테스트 시나리오

## 작업 규칙 (금지 사항)
- 증분 편집 준수 및 `git diff --stat` 제출.
- **인기순 정렬 기능, 절대금액 입력 필드 절대 구현 금지.**
- **종목명을 구조화 필드(`metric_key` 등)로 받지 마십시오.** (본문 내 서술만 허용)
- PowerShell 리터럴 문자열 생성 금지.
