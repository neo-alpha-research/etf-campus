# Antigravity 통합 인계 프롬프트 — 커뮤니티 개설 및 30일 챌린지 연속 구현 (Phase 0 ~ Phase 6)

당신은 자율적이고 강력한 문제 해결 능력을 갖춘 **Manus 1.6** 시니어 엔지니어입니다. 
현재 운영자는 자리를 비운 상태이며, 당신은 중단 없이 **Phase 0부터 Phase 6까지의 전체 범위를 한 번에 연속으로 구현**해야 합니다.

작업 중 의문점이나 운영자의 결정이 필요한 사항(예: 알림 발송용 외부 벤더 등)이 발생하면 작업을 멈추지 마십시오. 대신 **안전한 방향(예: UI 껍데기만 구현, 외부 API 호출부만 더미로 남김)으로 우회하여 구현을 계속 진행**하고, 발생한 모든 문제와 질문은 최종 완료 보고서의 **[운영자 질문 모음]** 섹션에 일괄 정리해 제출하십시오.

## 🏗️ 아키텍처 및 환경 제약 (절대 규칙)
1. **아키텍처 분리**: 커뮤니티 데이터는 **Supabase (Postgres)**, 기존 ETF 데이터/관리자 인증은 **Cloudflare D1 (SQLite)** 입니다. 두 시스템을 절대 결합하지 마십시오. 모더레이션 권한 역시 D1 세션이 아닌 Supabase의 `community_user_roles`(`admin`, `moderator`)를 활용하십시오.
2. **런타임 제약**: 
   - 프론트엔드(Next.js)는 `output: "export"`, `trailingSlash: true` 로 설정되어 있어 동적 라우팅이 불가능합니다. (쿼리 파라미터 사용)
   - 백엔드(Cloudflare Pages Functions)는 Node 런타임이 아닌 Workers 런타임입니다. (`Buffer`, `node:crypto`, `fs` 사용 불가)
3. **Supabase SDK 부재**: `@supabase/supabase-js`는 설치되어 있지 않습니다. `functions/api/community/_lib/supabase.js` 에 구현된 자체 REST 클라이언트를 그대로 사용하고, 부족한 메서드는 최소한으로 확장하십시오.

## 🚫 작업 금지 사항 (과거 회귀 사고 방지)
- **증분 편집만 수행**: 기존 파일을 통째로 다시 쓰지 마십시오. 정규식 일괄 치환(Sed 등)이나 파일 전체를 덮어쓰는 스크립팅 방식을 엄격히 금지합니다.
- **PowerShell 파일 IO 금지**: `> `, `>>`, `Set-Content` 등을 사용하면 UTF-16 인코딩 변환 문제로 파일이 깨집니다. 에디터 도구 및 Node.js 스크립트만 사용하십시오.
- **광범위 글로벌 매치 금지**: `git add .` 나 `git rm *.py` 등을 사용하지 말고 경로를 명확히 지정하십시오.
- **기존 타입 계약 절대 변경 금지**: 기존 클라이언트가 소비하는 응답 구조를 망가뜨리지 마십시오.
- **인기순 정렬 기능, 절대금액(만원/억 등) 입력 폼 설계 절대 금지.** (컴플라이언스 위반)

## 🚀 구현 명세 (연속 실행)

### [Phase 0] 기반 정리 (가장 먼저 실행)
1. **인코딩 손상 파일 복구**: `functions/api/community/` 하위 파일 중 에러 메시지(한글)가 깨진 6개 파일(`account.js`, `config.js`, `profile.js`, `posts/index.js`, `comments.js`, `[commentId].js`)을 찾아 과거 Git 이력(`git log -S`)에서 원본 리터럴을 추출해 교체하십시오. **로직은 건드리지 마십시오.**
2. **`error.code` 전환**: `community-post-detail.tsx` 의 not-found 판정을 깨진 한글 비교에서 `error.code === "NOT_FOUND"` 로 변경하십시오.
3. **잔재 제거**: 루트의 `temp.json` (약 1.8MB)을 `git rm` 으로 제거하십시오.
4. **UTF-8 검증 CI 추가**: 모든 파일이 UTF-8(BOM 없음)로 저장되도록, `U+FFFD` 포함 여부를 검사하는 `scripts/verify-utf8.mjs` 를 만들고 `package.json` 테스트에 연동하십시오.

### [Phase 1] 커뮤니티 기반 확장
1. **`notice` 카테고리 신설**: `moderator` 및 `admin` 권한만 작성 가능한 공지 카테고리 추가.
2. **고정 게시물(`is_pinned`)**: 게시글 속성에 고정 여부 추가 (카테고리당 최대 3건 허용). 목록 조회 시 고정 글을 상단에 정렬. **(Supabase DB 스키마/RPC 마이그레이션 필수)**
3. **페이지네이션**: 목록 API(`GET /api/community/posts`) 및 프론트엔드 피드에 **커서 기반 페이지네이션**과 "더보기" 기능 구현.
4. **저자 시드 뱃지**: `is_author_seed` 플래그 추가 (집계에서 제외됨), UI에 "저자 기록" 배지 노출.

### [Phase 2] 시드 콘텐츠 등록 도구
- **시드 등록 스크립트 작성**: `scripts/seed-community-posts.mjs` 를 개발. 마크다운 파일들의 폴더를 읽어 프론트매터(YAML)를 파싱하고 Supabase REST API를 통해 일괄 업로드(멱등성 보장)하는 Node.js 유틸리티 구현. (※ 자동 스케줄러 발행 기능은 구현 불필요)

### [Phase 3] 리드마그넷 게이트 및 뉴스레터 연동
- **랜딩 폼 구현**: `app/(landing)/page.tsx` 등에 번들 5종을 카드 형태로 노출하고, 하단에 **이메일(단일 필드)**과 필수/선택 동의 체크박스 2개를 갖춘 폼을 배치.
- 폼 제출 시 이중 확인(Double Opt-in) API 연동 껍데기를 구현하고, 하단에 최신 커뮤니티 글 3개를 함께 노출하십시오.

### [Phase 4] 기수와 참가자 관리
1. **스키마 추가 (마이그레이션)**: `community_cohorts` (기수 테이블) 및 `community_participants` (참가자 상태 관리 테이블) 추가. 성능을 위해 `participants` 테이블에 외래키 인덱스를 반드시 생성하십시오.
2. **참가 신청 폼 UI**: 프론트엔드에 퇴직연금 유형, 목표 한 문장, 기록 가능 여부 체크 등 **3개의 필수 항목**만 갖춘 신청 양식 뷰를 만드십시오. 하단에 미완성 도서 안내 문구 고정 노출.

### [Phase 5] 기록 게시판 (30일 챌린지 전용)
1. **RPC 확장 (마이그레이션)**: `create_community_post` 를 수정하여 `day_number`, `cohort_id`, `metric_key`, `metric_value` 등을 저장. `created_at` 은 반드시 DB 서버 시간으로 덮어씌움.
2. **어뷰징 필터**: 직전 기록과 동일한 텍스트일 경우 에러 반환.
3. **특화 작성 폼**: `challenge-30` 카테고리 작성 폼은 본문과 오늘의 숫자 2개만 노출. Day 자동 계산, 오늘의 과제(원문 그대로 노출), 이전 공개옵션 기본값 복원 처리. 절대금액 단위 노출 불가.
4. **상세/목록 UI**: 목록 좌측에 내 진행 카드(진행률, 30칸 상태 그리드), 필터 칩(인기순/추천순 제외) 노출. 좋아요 대신 "응원" 버튼.

### [Phase 6] 자동 판정 배치와 관리자 화면
1. **자동 판정 로직 (Cloudflare Workers Scheduled Event)**: 매일 12:05 KST에 기동. 클라이언트 제출 시간이 아닌 `마감 시각 KST`를 기준으로 달성/지각/미달성을 기계적으로 판정해 불변 로그로 기록. (※ 현재 `pg_cron` 사용 불가 상태이므로 Workers Cron Triggers 사용 권장)
2. **관리자 화면 확장**: 기존 D1 기반 관리자 콘솔을 재사용(새 인증 체계 구축 금지)하여, 기수별 참가자 통계 표와 '수동 소명 접수' 버튼만 추가.
3. **알림 연동 껍데기**: 미달성 통보 및 경고 발송을 위한 인터페이스 함수만 작성. 실제 메일 발송 로직은 연동하지 말고 TODO로 두십시오.
