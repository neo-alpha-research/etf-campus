# ITD 가격수익률 및 MAX 차트 백필 작업 보고서

**작성일:** 2026-08-15 (Asia/Seoul)  
**대상:** ETF Campus 국내 상장 ETF 데이터셋 1,160종목  
**수익률 정의:** 상장 후 최초 유효 거래일 종가 대비 최신 유효 종가의 **시장가격 기준 가격수익률(PR)**. 분배금은 포함하지 않는다.

## 1. 작업 완료 여부

코드 구조 개선, 전수 감사 파일 생성, 안전한 ITD 백필 도구와 단위 테스트 추가, MAX 기간·내부 D1 API의 장기 조회 제한 수정, 그리고 빌드 검증까지는 완료했다. 다만 이번 실행 환경에는 KRX Open API 및 금융위원회 공공데이터포털 접근 키가 없고 원격 D1 쓰기 인증도 없었다. 따라서 공식 일별 이력을 실제로 수집·적재하여 전 종목 `r_itd`를 채우는 단계는 의도적으로 보류했다. 검증되지 않은 기존 캐시 가격을 운영 ITD로 승격하거나 추정 가격을 생성하지 않았다.

| 구분 | 완료 상태 | 비고 |
| --- | --- | --- |
| ITD 전수 감사 파일 | 완료 | `data/quality/itd_coverage_audit.csv` 생성 |

| 일일 업데이트의 90일 제한 제거 | 완료 | 기존 앵커를 유지하고 최신 종가만으로 ITD 갱신 |

## 2. 수정 전 핵심 원인

기존 기간 모듈은 MAX/ITD에 `1970-01-01`을 사용했다. 상세 화면은 이 값을 가격 이력 API로 보냈고, API는 약 1,826일을 넘는 모든 요청을 `range_too_large`로 거절했다. 그 결과 상장 후 기간 차트가 빈 데이터처럼 보일 수 있었다.

일일 데이터 업데이트 또한 신규 상장 90일 이내에만 `itd_anchor_close`를 채우고 `r_itd`를 계산했다. 90일을 넘긴 종목은 기존 앵커가 있더라도 `r_itd`를 빈 문자열로 덮어썼다. 이 구조가 전체 ETF의 상장 후 수익률을 유지할 수 없게 한 직접 원인이었다.

## 4. 데이터 출처 및 신뢰도

KRX Open API의 공식 서비스 목록은 ETF 일별매매정보가 **2010-01-04부터** 제공된다고 명시한다.[1] 이 원천은 2010-01-04 이후 상장 ETF의 일별 시장가격(PR) 수집에 우선 사용하도록 설계했다.

금융위원회 공공데이터포털의 증권상품시세정보는 ETF 종목별 시가·종가·고가·저가·거래량·변동률을 제공하는 REST API이며, 페이지 기준 무료이고 이용허락범위는 제한 없음으로 표시된다.[2] 페이지에는 과거 제공 시작일이 제시되지 않으므로 2010년 이전 31종목은 종목별 호출로 최초 제공일을 기록해야 한다. 이 절차를 통과하지 못한 가격은 운영 데이터에 적재하지 않는다.

| 원천 | 사용 목적 | 확인된 제공 범위·조건 | 운영 처리 |
| --- | --- | --- | --- |
| KRX Open API ETF 일별매매정보 | 2010년 이후 일별 시장종가 및 MAX 이력 | 2010-01-04 이후 제공 명시 | 공식 API 키가 제공되면 날짜 단위로 수집·D1 upsert |
| 금융위원회 증권상품시세정보 | 2010년 이전 상장 종목의 보조 검증 | 무료, 이용허락범위 제한 없음. 과거 시작일은 종목별 확인 필요 | 종목별 최초 조회 가능일·재사용 상태 기록 후 사용 |

## 9. 자동 업데이트 방식 및 재실행 명령

기존 GitHub Actions의 일일 데이터 갱신은 KRX·금융위원회 키와 서명된 가격 적재 엔드포인트 비밀값을 사용하도록 설정되어 있다. 수정된 일일 업데이트는 새로 받은 공식 상장일 종가만 앵커로 저장하고, 이후에는 그 앵커를 바꾸지 않으며 최신 종가가 바뀔 때만 ITD를 재계산한다.

전체 일별 이력을 공식 원천에서 내보낸 후에는 다음 명령을 실행한다.

```bash
python scripts/backfill_itd.py \
  --history-csv data/price_history/official_etf_daily_history.csv
```

특정 종목은 `--ticker 363580`, 2010년 이전 상장 종목만 감사하려면 `--pre-2010-only`, 쓰기 없이 검증하려면 `--dry-run`을 사용한다. 제공하는 이력 CSV에는 `ticker,date,close`가 필수이며 `source,collected_at` 열을 함께 보존한다.

## 10. 미해결 종목과 정확한 사유

현재는 1,160종목 모두가 공식 일별 이력 연결 대기 상태다. 로컬 실행 환경의 `KRX_OPEN_API_KEY`, `DATA_GO_KR_SERVICE_KEY`, `PRICE_INGEST_HMAC_SECRET`, Cloudflare 원격 D1 인증이 설정되어 있지 않아 실제 호출·D1 적재를 수행할 수 없었다. 이러한 인증 부재는 가격을 추정하거나 캐시를 공식 데이터처럼 표시해서는 안 되는 차단 사유다.

운영 반영 전에는 다음을 확인해야 한다. GitHub Actions 비밀값이 유효한지, 2010년 이전 31종목에 대한 금융위원회 API의 최초 제공일이 실제로 상장 직후인지, D1의 `etf_prices`에 날짜·티커 유일성이 유지되는지, 그리고 권리변동 감지 종목의 가격 조정 기준이 앵커·최신 종가 간에 일치하는지를 확인해야 한다. 전체 린트는 이번 변경과 무관한 기존 오류 14건·경고 40건으로 실패했으며, 이번에 수정한 차트 파일에는 기존의 `any` 관련 규칙 위반이 남아 있으나 빌드·타입 검사·전체 테스트는 통과했다.
