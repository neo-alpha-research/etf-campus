## 3. 357870·477080 — 승격을 막을 이유가 없습니다

이 2건은 우리 70% vs 한투 100%로 진짜 불일치입니다. 그런데 **우리 판정의 근거가 더 강합니다.**

- 협회 원본에 `특별자산상장지수투자신탁`으로 명시 → 특별자산집합투자기구 확정
- 제11조 제1항 제5호는 "증권형집합투자증권등"만 인정 → 100% 안전자산 불가
- **이것은 조문 문언에서 직접 도출됩니다**

한투의 1.0은 실무 재량(CD 파킹형의 원금손실 가능성이 희박하다는 판단)으로 보입니다. 그러나 우리가 판매사의 재량을 따를 이유는 없고, 따라가면 다른 증권사에서 70%인 이용자가 한도를 초과하게 됩니다. **보수적 판정이 이용자에게 안전합니다.**

### 지시

두 건을 **`evidence_grade = E1`, `evidence_tier = statutory`로 승격**하십시오.

```
evidence_ref:   data/regulatory/sources/kofia_dis_response_20260905.xml
evidence_quote: 미래에셋TIGERCD금리투자KIS특별자산상장지수투자신탁(CD-파생형)(합성) /
                펀드유형 특별자산파생 / 표준코드 K55301D61007 (KOFIA 전자공시 원본)
statutory_basis: PSR_ART11_1_5 (증권형 요건 미충족으로 안전자산 배제)
note:           한국투자증권 공시는 100%(실무 재량). 법적 기구 종류가 특별자산이므로 70% 적용
```

그리고 **화면에 주석**을 다십시오 — "증권사에 따라 안전자산으로 분류될 수 있습니다. 실제 한도는 가입한 퇴직연금사업자에서 확인하십시오."

## 4. refresh 스크립트 — 5단계 중 3단계만 구현되었습니다

보고서 §4는 5단계 자동화를 완성했다고 서술했으나 코드를 확인한 결과입니다.

| 단계 | 보고 | 실제 코드 |
|---|---|---|
| 1. 엑셀 구조·2행 문언 검증 | 구현 | **없음** — `wb["ETF"]`를 열고 5행부터 읽을 뿐 |
| 2. SHA-256 계산 | 구현 | **구현됨** ✓ |
| 3. ticker universe 추출 | 구현 | **구현됨** ✓ |
| 4. 재매칭·신규 적격 식별 | 구현 | **없음** — docstring에만 존재 |
| 5. `expires_at` 갱신 | 구현 | **없음** — `LEDGER_PATH` 상수만 선언, 갱신 코드 없음 |

docstring이 구현을 앞서 갔습니다. 다음 달 실행하면 해시와 유니버스 파일만 갱신되고 **원장은 손대지 않은 채 "성공"으로 끝납니다.**

특히 1단계 부재가 위험합니다. 한투가 엑셀 2행 문언이나 열 순서를 바꾸면 **조용히 잘못된 값을 읽습니다.** 31건 부재증명의 근거가 그 2행 문언이므로 반드시 검증해야 합니다.

### 지시 — 3개 단계를 실제로 구현하십시오

```python
# 1단계: 구조 검증 (실패 시 예외 발생, 조용한 진행 금지)
assert ws.cell(2, 11).value 또는 2행 전체에 
       "매매불가" and "레버리지" and "인버스" and "파생형" and "해외상장" 포함
assert 3행 헤더의 5열 == "종목코드", 7열에 "퇴직연금" and "투자한도" 포함
assert 추출 종목수 >= 900   # 급감 시 파싱 실패 의심

# 4단계: 재매칭
직전 universe와 diff → 신규 수록 / 신규 미수록 / 한도 변경 3분류 리포트
한도 변경 종목은 반드시 사람이 확인하도록 표시

# 5단계: expires_at 갱신
2way 행의 expires_at = 새 엑셀 기준일 + 90일
```
