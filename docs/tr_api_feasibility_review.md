# ETF 총수익률(TR) API 도입 검토

- 검토일: 2026-08-13
- 범위: 국내 상장 ETF 1,160종목, 비교/상세 화면의 1일~3년 및 YTD 수익률
- 현재 기준일: 가격·PR CSV 2026-08-11, 별도 TR 산출물 2026-08-10

## 결론

TR 산출은 기술적으로 가능하다. 그러나 현재 무료 가격 API에 API 하나만 추가하는 방식으로 전 종목의 운영 가능한 TR을 바로 만들 수 있는 상태는 아니다. 전 종목 TR에는 다음 세 가지가 동시에 필요하다.

1. 일별 시장 종가와 분할·병합 등 기업행사 조정 정보
2. ETF별 현금 분배금의 금액과 권리락일(또는 기준일에서 확정적으로 변환할 수 있는 정보)
3. 공개 웹 서비스에서 가공값을 표시할 수 있는 상업 이용·제3자 제공 권한

권장안은 **라이선스가 확인된 조정가격/분배금 데이터 공급자 1곳을 주 데이터원으로 선정**하고, 현재 금융위원회 가격 API 및 운용사 공식 자료를 검증·장애 대응용으로 사용하는 것이다. 무료 데이터만 사용해야 한다면 금융위원회 가격 API와 운용사별 분배금 수집기를 결합할 수 있지만, 운용사별 어댑터 유지보수와 데이터 누락 검수가 필수다.

## 기존 점검 결과에서 수정할 사항

### 1. 비교 서비스에는 TR이 없지만, 저장소 전체의 TR 데이터가 0건인 것은 아니다

`lib/data/etf-repository.ts`는 `etf_returns_draft.csv`의 `r_1d`~`r_36m` 값을 그대로 읽는다. 이 파일의 1,160종목 수익률은 종가 비율로 계산한 PR이다. 따라서 **현재 비교/상세 서비스 계약에서 바로 쓸 수 있는 TR은 0종목**이라는 결론은 맞다.

반면 저장소에는 별도 리드마그넷 파이프라인으로 계산한 TR 산출물이 있다.

| 산출물 | 종목 수 | 기간 | 방식 |
| --- | ---: | --- | --- |
| `page1_performance_metrics.csv` | 3 | 6개월, YTD, 1·2·3년 | 운용사 공식 가격/분배금 재투자 |
| `page2_metrics.csv` | 6 | 6개월, YTD, 1년 | 네이버 조정 시계열이라고 가정한 가격 + 공식 분배금 원장 |
| `page3_performance_metrics.csv` | 5 | 6개월, YTD, 1년 | 운용사 공식 가격/분배금 재투자 |

중복이 없어 총 14종목이다. 다만 비교 서비스 스키마에 연결되어 있지 않고, page2의 네이버 시계열은 공식 API·라이선스·현금 분배 조정 범위를 별도로 검증해야 하므로 14종목을 곧바로 운영 TR로 승격해서는 안 된다.

### 2. 과거 가격 조회 로직과 일별 가격 저장소는 이미 있다

- `scripts/update_daily_data.py`에는 금융위원회 API의 종목별 과거 가격 조회 함수가 있다.
- `scripts/backfill_api.py`와 `scripts/d1_schema.sql`에는 일별 종가를 D1에 저장하는 파이프라인이 있다.
- KRX 직접 API는 날짜당 전체 ETF 스냅샷을 반환하므로, 3년 백필은 종목별 호출보다 거래일별 호출이 효율적이다.

따라서 새로 필요한 핵심은 가격 DB 자체가 아니라 **기업행사 조정, 전 종목 분배금 원장, 품질 상태와 수익률 기준을 담는 스키마**다.

### 3. 1주는 반드시 5거래일이어야 한다는 기존 제안은 수정한다

현재 코드는 기준일에서 7일 전 달력일을 구한 뒤 그 날 또는 직전 거래일 종가를 사용한다. 이는 일반적인 기간수익률 관행으로 사용할 수 있다. “1주=정확히 5개 관측치”로 바꿀 필요는 없다. 대신 모든 기간에 대해 실제 시작·종료 거래일을 결과에 저장하고 UI 툴팁에 표시해야 한다.

## 현재 코드에서 먼저 해결할 데이터 결함

### 영문자가 포함된 신규 종목 294개가 D1 가격 적재에서 제외된다

현재 마스터 1,160종목 중 숫자 6자리 종목은 866개, 영문자가 포함된 6자리 종목은 294개다. 그런데 다음 두 곳이 `숫자 6자리`만 허용한다.

- `scripts/backfill_api.py`: `ticker.isdigit()` 검사
- `functions/api/internal/ingest-prices.js`: `/^\d{6}$/` 검사

TR 작업 전에 허용 규칙을 KRX 단축코드 형식에 맞게 `영문 대문자와 숫자로 된 6자리`로 확장하고 테스트를 추가해야 한다. 그렇지 않으면 신규 ETF 약 25.3%가 가격 이력 단계에서 누락된다.

### 장기 수익률 정의가 일관되지 않다

일반 `r_24m`, `r_36m`은 시작·종료 종가의 누적수익률인데, `calculate_page1_total_return_metrics.py`는 2년·3년 값을 CAGR로 연환산한다. 같은 “2년/3년 수익률” 라벨 아래 서로 다른 값을 섞지 말고 아래 중 하나로 통일해야 한다.

- 권장: 1일~3년과 YTD는 모두 누적 TR
- 별도 지표: `cagr_2y`, `cagr_3y`를 명시적으로 추가

### PR과 TR을 같은 필드에 덮어쓰면 안 된다

기존 `returns[period]`를 TR로 조용히 교체하면 과거 스냅샷과 비교 결과가 단절된다. 다음처럼 기준을 데이터에 포함한다.

```text
return_basis: PR | TR_GROSS_MARKET_PRICE | TR_NET_MARKET_PRICE | TR_NAV
period: 1d | 1w | 2w | 1m | 2m | 3m | 6m | ytd | 12m | 24m | 36m | itd
value_pct
anchor_date
as_of_date
quality_status: verified | provisional | unavailable
source_version
```

## 권장 계산 기준

서비스 기본 TR은 다음과 같이 정의하는 것이 비교 가능성이 가장 높다.

- 기준: **원화 시장가격 세전 총수익률**(`TR_GROSS_MARKET_PRICE`)
- 분배금: 주당 세전 현금 분배금을 권리락일 종가에 전액 재투자
- 비용: ETF 보수와 내부 거래비용은 시장가격/NAV에 이미 반영된 것으로 보고 별도 차감하지 않음
- 세금·매매수수료: 투자자와 계좌별로 달라 기본 TR에서 제외
- 환율: 국내 상장 ETF의 원화 시장가격에 포함된 결과를 그대로 사용
- 장기 기간: 기본은 누적수익률, CAGR은 별도 필드

분할·병합이 없는 구간에서 기존 코드의 일별 인덱스 공식은 타당하다.

```text
TR_t = TR_(t-1) × (P_t + D_t) / P_(t-1)
```

다만 전 종목 운영에서는 분할·병합 이후 과거 분배금 단위까지 일치시켜야 하므로, 조정계수 또는 보유좌수 원장을 적용해야 한다. 가장 안전한 방법은 공급자가 제공하는 현금분배 포함 조정종가를 사용해 `AdjClose_end / AdjClose_start - 1`로 계산하고, 분배금 원장으로 표본 검증하는 것이다.

## 구현안

### A안 — 상용 조정종가/기업행사 API 사용(권장)

1. 공급자에게 KRX ETF 1,160종목 및 영문 포함 단축코드 지원 여부 확인
2. 현금 분배 포함 조정종가인지, 분할만 반영한 수정주가인지 서면 확인
3. 최소 3년 이력, 일별 갱신 시각, 정정 데이터 제공 방식, 서비스 화면 표시·재배포 권한 확인
4. 20~30종목 표본을 기존 14종목 공식 산출물과 비교
5. 오차 기준을 통과하면 전 종목 백필 및 PR/TR 병행 제공

이 안은 개발량과 장애 포인트가 가장 적고, 데이터 권리 문제도 계약으로 정리할 수 있다.

### B안 — 무료 공식자료 조합

1. 가격: 금융위원회 ETF 시세 API로 날짜별 전체 종목 스냅샷 적재
2. 분배금: KODEX·TIGER·ACE·RISE·SOL·PLUS 등 운용사별 공식 어댑터 구축
3. 기업행사: KIS 수정주가 또는 별도 권리정보로 분할·병합 검증
4. 원천 응답 해시, 수집시각, 정정 이력, 누락 상태 저장
5. 운용사별 계약/이용약관 및 공개 서비스 표시 가능 여부 확인

이 안도 가능하지만 운용사 추가·브랜드 변경·페이지 개편 때마다 수집기가 깨질 수 있다. “분배 없음”과 “수집 실패”를 반드시 구분해야 한다.

## 검증 기준

- 표본: 대형, 월분배, 분기분배, 무분배, 신규 영문코드, 분할/병합 이력, 상장폐지 종목 포함
- 비교: 기존 공식 산출 14종목 및 운용사 공시 기간수익률과 대조
- 허용오차: 기간수익률 0.05%p 이내를 목표로 하되 원천 반올림 상품은 별도 기준 기록
- 완전성: 활성 종목 가격 99.5% 이상, 분배 이벤트는 공식 표본 대비 100%
- 신선도: 장 종료 후 익영업일 공개 전 갱신, 원천 정정 시 재계산
- 실패 처리: 누락 시 PR로 자동 대체하지 말고 TR을 `unavailable`로 표시
- 회귀검증: 분배금이 0인 구간은 TR과 기업행사 조정 PR이 같아야 함

## 출시 순서

1. 즉시: UI의 기존 수익률을 `가격수익률(PR) · 분배금 미포함`으로 명시
2. 1차: D1의 영문 포함 종목코드 지원, 가격/분배금/기업행사/수익률 테이블 분리
3. 2차: 20~30종목 POC, 기존 14종목 공식 산출물과 교차검증
4. 3차: 1년 TR부터 전 종목 확대 후 3개월·6개월·YTD·2년·3년 순으로 백필
5. 4차: 95% 이상 검증 커버리지 확보 전까지 비교표 기본값은 PR 유지
6. 최종: 전 종목 검증 완료 후 TR을 기본값으로 전환하고 PR/TR 토글 및 기준일·실제 앵커일 제공

## 최종 판단

- **산출 가능 여부:** 가능
- **현 무료 API만으로 즉시 전 종목 운영 가능 여부:** 불가
- **가장 현실적인 방법:** 상업 표시 권한이 포함된 현금분배 조정가격/기업행사 API 계약
- **무료 대안:** 금융위원회 가격 API + 운용사별 공식 분배금 수집 + 기업행사 보정
- **현재 비교 서비스에 바로 표시 가능한 검증 TR:** 0종목
- **저장소에 별도 산출되어 POC 검증 기준으로 쓸 수 있는 TR:** 14종목
