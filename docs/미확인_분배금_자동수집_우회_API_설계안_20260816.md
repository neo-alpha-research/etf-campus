# 미확인 분배금 자동 수집 우회·API 연동 설계안

작성일: 2026-08-16  
대상: FOCUS 0073X0·0176P0, 파워 192720, DAISHIN343 0189Z0  
목표: 운용사 공식 원문을 우선 수집하되, 공식 페이지가 동적이거나 공지 URL이 불안정한 경우에도 **자동 발견·원문 보존·교차검증·게시 보류**가 끊기지 않는 구조를 구축한다.

## 1. 설계 원칙

이번 설계에서 말하는 우회는 원천의 신뢰도를 낮추는 우회가 아니다. 우회는 **공식 사이트 안에서 다른 문서 경로와 공개 조회 기능을 찾는 것**을 의미한다. 운용사 상품 페이지, 운용보고서, 투자설명서, KIND 공시, DART 펀드공시, 금융투자협회 Fund One-Click을 서로 다른 등급의 원천으로 저장하고, 원문에서 직접 확인되지 않은 값은 웹페이지에 확정값으로 표시하지 않는다.

> 외부 사이트에서 보이는 배당금 숫자나 검색엔진 요약문은 발견용 단서로만 사용한다. 최종 데이터는 운용사 원문 또는 KRX KIND 원문에서 직접 확인된 값만 사용한다.

특히 `ex_date`, `record_date`, `pay_date`는 서로 다른 날짜다. 하나가 없다고 다른 날짜에서 역산하지 않는다. 원문에 날짜가 없으면 빈 값으로 저장하고, TR 계산이나 확정 배지에 사용하지 않는다.

**권장안은 첫 번째와 두 번째를 병행하고, 세 번째를 실패 안전장치로 두는 방식**이다. 단순히 외부 사이트 숫자를 긁어 게시하는 방식은 채택하지 않는다.

## 4. 공통 어댑터 인터페이스

각 운용사 어댑터는 `scripts/distribution_adapters/` 아래에 두고 같은 결과 형식을 반환한다. 외부 패키지는 사용하지 않고 `urllib.request`, `http.cookiejar`, `html.parser`, `json`, `hashlib`, `re`, `datetime`, `pathlib`만 사용한다.

```python
from dataclasses import dataclass
from typing import Optional

@dataclass
class SourceArtifact:
    source_id: str
    url: str
    fetched_at: str
    http_status: int
    content_type: str
    raw_path: str
    sha256: str
    parser_name: str
    access_status: str

@dataclass
class DistributionObservation:
    ticker: str
    name: str
    amount: Optional[str]
    ex_date: Optional[str]
    record_date: Optional[str]
    pay_date: Optional[str]
    source_id: str
    source_url: str
    source_sha256: str
    evidence_locator: str
    confidence: str
    publication_status: str
```

`SourceArtifact`는 원문을 받았다는 사실만 기록한다. `DistributionObservation`은 원문에서 직접 읽은 값만 기록하며, 날짜가 빠진 경우 `None`으로 둔다. 파서는 추정이나 날짜 역산을 하지 않는다.

### 5.2 세션·CSRF 처리

첫 번째 요청에서 `Set-Cookie`와 HTML의 CSRF 메타 태그를 저장한다. 두 번째 요청에서 같은 쿠키와 CSRF 헤더를 보내 운용보고서 HTML을 받는다. 이것은 로그인 우회나 CAPTCHA 우회가 아니라, 공식 페이지가 브라우저에 요구하는 정상적인 세션 흐름을 표준 라이브러리로 재현하는 것이다.

```python
import http.cookiejar
import re
import urllib.parse
import urllib.request

class VIClient:
    def __init__(self):
        self.cookies = http.cookiejar.CookieJar()
        self.opener = urllib.request.build_opener(
            urllib.request.HTTPCookieProcessor(self.cookies)
        )

    def get_detail(self, detail_url: str) -> tuple[str, str]:
        request = urllib.request.Request(
            detail_url,
            headers={"User-Agent": "ETF-Campus-Official-Archive/1.0"},
        )
        with self.opener.open(request, timeout=30) as response:
            html = response.read().decode("utf-8", "replace")
        token = re.search(
            r'<meta[^>]+name=["\']_csrf["\'][^>]+content=["\']([^"\']+)',
            html,
            re.I,
        )
        header = re.search(
            r'<meta[^>]+name=["\']_csrf_header["\'][^>]+content=["\']([^"\']+)',
            html,
            re.I,
        )
        return html, (token.group(1) if token else "") + "\t" + (header.group(1) if header else "")

    def list_reports(self, detail_url: str, bidx: int) -> tuple[int, bytes, str]:
        html, csrf = self.get_detail(detail_url)
        token, header = csrf.split("\t", 1)
        payload = urllib.parse.urlencode({
            "bidx": str(bidx), "pageIndex": "1", "pageUnit": "10"
        }).encode()
        request = urllib.request.Request(
            detail_url.rsplit("/", 1)[0] + "/listAjax",
            data=payload,
            method="POST",
            headers={
                "User-Agent": "ETF-Campus-Official-Archive/1.0",
                "Content-Type": "application/x-www-form-urlencoded; charset=UTF-8",
                header or "X-CSRF-TOKEN": token,
                "Referer": detail_url,
                "X-Requested-With": "XMLHttpRequest",
            },
        )
        try:
            with self.opener.open(request, timeout=30) as response:
                return response.status, response.read(), response.headers.get("Content-Type", "")
        except urllib.error.HTTPError as exc:
            return exc.code, exc.read(), exc.headers.get("Content-Type", "")
```

실제 구현에서는 `urllib.error`를 함께 import하고, 403·429·5xx 응답은 재시도하지 않고 상태별로 분류한다. 403이 계속되면 `csrf_or_access_blocked`로 기록한다. JavaScript 실행기나 CAPTCHA 우회 도구를 도입하지 않는다.

### 5.3 FOCUS 운용보고서 파서

운용보고서 목록에서 PDF 또는 HTML 다운로드 링크를 찾고, 파일 자체를 원본으로 저장한다. PDF에 표가 포함되어도 외부 PDF 파서는 추가하지 않는다. 표준 라이브러리만 사용하는 현재 제약에서는 우선 운용보고서의 HTML 응답과 파일명·문서 제목을 보존하고, PDF 본문에서 텍스트를 안정적으로 추출하기 어렵다면 `manual_review_required`로 보낸다.

FOCUS의 공식 상품 상세 페이지는 월배당 여부만 제공하므로, **월배당이라는 상품 설명을 실제 지급 이벤트로 변환하지 않는다.** 운용보고서에서 금액과 지급 일정이 직접 확인된 경우에만 후보를 생성한다.

## 6. 파워 전용 우회 수집기

### 6.1 공식 검색 경로

교보악사 공식 페이지는 다음 두 경로를 사용한다.

```text
상품 목록: https://www.kyoboaxa-im.co.kr/prdtInfo/powerETFList.do
운용보고서: https://www.kyoboaxa-im.co.kr/cletCetr/mrReport.do
```

운용보고서 페이지는 기준일과 펀드명을 입력하는 검색형 화면이다. 따라서 `192720`, `파워 고배당저변동성`, 가능한 펀드코드 후보를 순서대로 넣어 검색하고, 응답 HTML에서 문서 다운로드 링크를 수집한다.

### 6.2 검색 전략

검색어는 다음 순서로 제한한다.

| 순서 | 입력값 | 목적 |
|---:|---|---|
| 1 | `파워 고배당저변동성` | 펀드명 완전 일치 확인 |
| 2 | `192720` | 상품코드 검색 지원 여부 확인 |
| 3 | 레지스트리의 운용사 펀드코드 | 펀드명 변경·공백 차이 보완 |
| 4 | 기준일을 최근 24개월의 월말로 순회 | 월별·분기별 운용보고서 발견 |

검색 결과가 없으면 실패가 아니라 `no_report_found_for_query`로 기록한다. 검색 결과가 존재하지만 파일 링크가 비어 있으면 `report_metadata_without_file`로 기록한다.

### 6.3 HTML·PDF 수집

운용보고서 검색 화면의 검색 요청은 먼저 브라우저에서 확인한 공식 form action과 필드명을 레지스트리에 기록한다. 이후 표준 라이브러리로 같은 GET 또는 POST를 호출한다. 링크가 상대경로이면 공식 도메인 기준으로 결합하고, 파일 응답의 Content-Type과 SHA-256을 기록한다.

파워 운용보고서에 분배금 표가 있다면 다음 라벨을 보수적으로 인식한다.

```text
분배금, 좌당 분배금, 주당 분배금, 분배락일,
기준일, 지급기준일, 지급일, 지급예정일
```

`분배금 지급 예정` 문구만 있고 금액이 없다면 금액을 비워 둔다. `월분배형`, `분배 가능` 같은 정책 문구는 이벤트로 저장하지 않는다.

## 7. DAISHIN343 전용 우회 수집기

### 7.1 공식 공시 허브 병행

대신자산운용 공식 홈페이지에서 0189Z0 전용 문서 URL이 불안정한 경우, 다음 순서로 공식 제출문서를 발견한다.

| 단계 | 원천 | 용도 | 게시 권한 |
|---:|---|---|---|
| 1 | 대신자산운용 공식 홈페이지 | 운용사 상품·공지·투자설명서 탐색 | 원문 확인 시 후보 생성 |
| 2 | KIND ETF 공시 | 분배금 금액·기준일·지급예정일 후보와 운용사 제출 공시 확인 | 운용사 후보와 매칭 시 교차검증 |
| 3 | DART 펀드공시 | 투자설명서·일괄신고서·정기보고서 검색 | 문서 발견·보조 교차검증 |
| 4 | 금융투자협회 Fund One-Click | 펀드명·펀드코드·운용보고서 연결 확인 | 운용사 문서 링크 탐색 |

KIND 공시만으로는 `verified_official_issuer`를 부여하지 않는다. 다만 KIND 원문 자체가 공식 제출문서이므로, 원천 등급을 `official_exchange_notice`로 구분하여 별도 표시할 수 있다.

### 7.2 KIND 수집기

KIND에는 ETF 공시 검색 화면과 개별 원문 뷰어가 있다. 현재 저장된 KIND 원문 구조를 기준으로 다음 어댑터를 추가한다.

```python
class KindNoticeAdapter:
    def discover(self, ticker: str, since: str, until: str) -> list[SourceArtifact]:
        """ETF 분배금 관련 공시 목록을 발견하고 원문 URL·접수번호를 저장한다."""

    def fetch_notice(self, artifact: SourceArtifact) -> bytes:
        """개별 공시 뷰어 HTML을 원본 그대로 저장한다."""

    def parse_distribution_rows(self, html: bytes) -> list[DistributionObservation]:
        """종목코드·금액·기준일·지급예정일을 직접 읽고 ex_date는 별도 필드로 둔다."""
```

검색 대상 제목은 `이익금분배`, `ETF 분배금`, `분배금`, `분배락`을 사용하되, 제목이 바뀌어도 종목코드 `0189Z0`가 원문 표에 직접 존재하는지 확인한다. 원문에서 `0189Z0`이 없으면 후보를 생성하지 않는다.

### 7.3 DART·KOFIA API의 역할

DART Open API는 일반 기업 공시 API와 펀드공시 검색을 분리해 확인해야 한다. ETF 분배금 전용 API라고 가정하지 않는다. API 키가 있으면 공시 검색·문서 목록을 발견하는 보조 어댑터로 사용하고, 실제 분배금 표는 원문 HTML 또는 첨부 파일에서 직접 확인한다.

금융투자협회 Fund One-Click은 펀드 관련 정보 연결 서비스로 사용하고, 공개된 안정적 API 계약이 확인되지 않으면 HTML 검색 화면을 자동 수집의 최종 계약으로 간주하지 않는다. KOFIA 또는 DART에서 찾은 문서는 원문 URL과 문서 해시를 저장하되, 운용사 공식 문서인지 제출기관 문서인지 `source_tier`로 구분한다.

## 8. 원천 등급과 게시 게이트

```text
third_party_observation  제3자 사이트 관측값
```

게시 상태는 원천 등급과 필드 충족 여부를 함께 평가한다.

| 조건 | 상태 | UI 표시 | TR 사용 |
|---|---|---|---|
| 운용사 원문에서 금액·기준일·지급일 직접 확인 | `issuer_candidate` | 분배금 카드 후보 | 사용하지 않음 |
| 운용사 후보와 KIND 행의 금액·종목코드 일치 | `cross_checked_candidate` | 검증 대기 | 사용하지 않음 |
| 운용사 원문과 KIND 원문에서 필요한 일정이 모두 확인 | `verified_distribution` | 확정 분배금 | 현재 PR 정책상 사용하지 않음 |
| KIND 또는 DART 단독 확인 | `official_secondary_only` | 출처 확인 필요 | 사용하지 않음 |
| 제3자만 확인 | `third_party_only` | 게시하지 않음 | 사용하지 않음 |

현재 ETF Campus의 차트는 모든 ETF가 PR 전용이므로, 이 설계가 성공해도 TR 차트는 자동 활성화하지 않는다. 분배금 카드는 `verified_distribution` 또는 프로젝트가 별도로 허용한 `cross_checked_candidate`만 노출한다.

## 9. 원본 보존과 감사 로그

각 요청마다 다음 파일을 저장한다.

```text
data/distributions/raw/<source_family>/<yyyy>/<mm>/<source_id>.html
 data/distributions/raw/<source_family>/<yyyy>/<mm>/<source_id>.pdf
 data/distributions/manifests/<run_id>.jsonl
 data/distributions/reports/<run_id>.json
```

`manifest` 한 줄에는 `source_id`, `url`, `fetched_at`, `http_status`, `content_type`, `sha256`, `parser_name`, `parser_version`, `access_status`, `ticker_hints`, `document_title`을 기록한다. 서버가 403·429·5xx를 반환하면 응답 본문도 저장하되, 그것을 분배금 원문으로 파싱하지 않는다.

중복 방지는 URL이 아니라 `source_id + sha256` 기준으로 한다. 같은 URL이 수정된 경우 새 해시로 별도 원문을 보존한다. 원문을 덮어쓰지 않는다.

## 11. 일일 GitHub Actions 실행 순서

기존 가격·분배금 업데이트가 시작되는 시점에 다음 순서로 실행한다.

1. 레지스트리와 대상 티커를 읽는다.
2. 운용사 공식 상세·목록·보고서 검색 페이지를 수집한다.
3. FOCUS는 세션·CSRF가 성공한 경우에만 운용보고서 AJAX를 호출한다.
4. 파워는 운용보고서 검색 결과와 첨부 문서를 순회한다.
5. DAISHIN343은 공식 홈페이지와 KIND·DART·KOFIA 발견 계층을 병행한다.
6. 모든 원문을 해시와 함께 보존한다.
7. 후보 파서는 금액·날짜가 원문에 직접 있을 때만 행을 생성한다.
8. 후보와 KIND 행을 종목코드·금액·일정으로 대조한다.
9. 게시 게이트를 통과하지 못한 데이터는 `pending_krx_verification`, `official_secondary_only`, `manual_review_required` 중 하나로 보류한다.
10. 요약 JSON은 게시 가능한 상태만 반영한다. 원문 발견 건수와 보류 건수는 별도 실행 보고서에 기록한다.

GitHub Actions에서는 운용사별 실패가 전체 작업을 중단시키지 않도록 각 어댑터를 독립 단계로 실행한다. 단, 후보 검증 단계와 요약 생성 단계는 앞선 수집 단계가 모두 끝난 뒤 한 번만 실행한다.

## 12. 실패·재시도 정책

| 응답 | 처리 |
|---|---|
| 200 + 정상 HTML/PDF | 원문 보존 후 파싱 |
| 403 + CSRF/세션 실패 | 1회 세션 재수립 후 재시도. 다시 실패하면 검토 큐 |
| 404 | URL 변경 후보로 기록. 자동으로 다른 경로를 추측하지 않음 |
| 429 | 해당 운용사 수집 중단, 다음 일일 실행으로 연기 |
| 5xx·timeout | 짧은 재시도 1회 후 실패 로그 |
| HTML 구조 변경 | 후보 0건으로 조용히 성공 처리하지 말고 `parser_schema_changed` 경고 |
| PDF만 존재하고 표 추출 불가 | PDF 원본 보존, `manual_review_required` |

## 13. 권장 구현 순서

가장 먼저 FOCUS 어댑터를 구현한다. 이미 공식 상세 URL, `bidx=5/7`, AJAX 경로, CSRF 요구사항을 확인했기 때문에 자동화 가능성이 가장 높다. 다만 CSRF 처리 후에도 403이 지속되면 이 경로는 자동 수집이 아니라 공식 보고서 링크 발견용으로 격하한다.

두 번째로 파워 운용보고서 검색 어댑터를 구현한다. 검색 폼의 실제 파라미터와 다운로드 URL을 한 번 브라우저에서 확인하고 레지스트리에 고정한다. 검색 결과가 192720의 운용보고서로 연결되면 해당 문서를 원본으로 저장한다.

세 번째로 DAISHIN343은 KIND·DART·KOFIA 발견 어댑터를 먼저 연결한다. 0189Z0에 대한 운용사 제출문서가 발견되면 공식 원문 링크를 레지스트리에 추가한다. KIND 단독 결과만 존재할 때는 UI에 확정 분배금으로 게시하지 않고 `official_secondary_only`로 남긴다.

## 14. 최종 권고

**무료·표준 라이브러리·감사 가능성**이라는 현재 제약에서는 “운용사 전용 어댑터 + KIND/DART/KOFIA 발견 계층 + 수동 검토 큐” 조합이 가장 현실적이다. 외부 유료 API나 비공식 제3자 배당 API를 추가하는 것은 빠르게 숫자를 얻을 수 있지만, 한국 ETF 분배금의 기준일·지급일·분배락일을 동일한 이벤트로 보장하기 어렵고 원문 감사성이 약해진다.

따라서 자동화의 성공 기준은 4개 ETF가 즉시 모두 확정되는 것이 아니라, 매일 새 원문을 놓치지 않고 발견하며 **확인된 값만 게시하고 미확인 값은 안전하게 보류하는 것**으로 정의한다. 이 구조라면 현재 PR 차트 정책을 유지하면서도 향후 운용사 공지가 확보되는 즉시 분배금 카드에 누적 반영할 수 있다.
