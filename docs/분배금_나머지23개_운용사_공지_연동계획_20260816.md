## 1. 범위와 결론

기존 `distribution_source_registry.json`의 5개 운용사·52개 티커를 제외한 감사 목록의 차집합을 계산한 결과, 추가 대상은 정확히 **23개 ETF**입니다. 이번 계획은 분배금 포함 수익률이나 TR 산출을 위한 것이 아니라, ETF 상세 페이지에 공식 원문으로 확인 가능한 주당 분배금·분배락일·지급기준일·지급일을 게시하기 위한 것입니다.

따라서 외부 ETF 정보 사이트의 값을 직접 게시하지 않고, 운용사 공식 공지·상품별 공식 지급 이력·KIND 보조 대조 순서로 수집합니다. 공식 원천 URL이 확인되지 않은 경우에는 레지스트리에 `discovery_required`로 정의하되 자동 게시 대상에는 포함하지 않습니다.

## 3. 공식 원천 정의

### 3.1 즉시 등록 가능한 17개

1Q·HANARO·KoAct·RISE·TIGER는 공식 공지 목록 또는 상품별 공식 분배금 현황 페이지가 확인되어 자동 연동 후보로 정의했습니다. 1Q 공지는 1좌당 분배금과 지급일을 본문에 제공하고 정정 공지 가능성도 명시합니다.[1] HANARO는 공식 고객지원 공지 목록에서 월말 분배금 공지를 반복 제공하며,[2] KoAct는 삼성액티브자산운용의 분배금 전용 공지 목록을 운영합니다.[3] RISE는 분배금 검색 결과와 지급기준일·지급예정일이 포함된 공지 구조를 사용합니다.[4] TIGER는 연간 분배 내역과 전체 분배금 공지 목록을 별도 제공하여 지급 이력과 최신 공지를 분리 수집할 수 있습니다.[5]

### 3.2 공식 URL 추가 확인이 필요한 6개

TIME·FOCUS·DAISHIN343·파워는 현재 상품명·제3자 검색 결과·KIND 단서만으로는 자동 게시 원천을 확정하지 않습니다. 이 6개는 레지스트리에 별도 등록하되 `discovery_required` 상태로 두고, 공식 운용사 도메인의 공지 목록·상품 페이지·운용보고서 중 하나가 확인될 때까지 자동 게시를 차단합니다.

|---|---|---:|---|---|
| `timefolio_notice_pending` | TIME | 2 | discovery_required | TIMEFOLIO 공식 ETF 공지·분배금 게시판 |
| `focus_notice_pending` | FOCUS | 2 | discovery_required | HI Asset Management 공식 ETF 상품·공지 페이지 |
| `daishin343_notice_pending` | DAISHIN343 | 1 | discovery_required | 대신자산운용 공식 ETF 공지·분배금 페이지 |
| `power_notice_pending` | 파워 | 1 | discovery_required | 파워 ETF 운용사 공식 공지·상품 페이지 |

KIND 일괄공시는 DAISHIN343와 FOCUS의 후보 발견 및 일정 교차확인에 사용할 수 있지만, 운용사 공식 원문을 확보하기 전에는 웹페이지 게시용 1차 원천으로 단독 사용하지 않습니다. KIND 문서에는 정정 요구 또는 최종문서 여부를 확인해야 하는 경우가 있으므로, 정정 공시 확인 후에만 보조 증거로 연결합니다.[6]

## 4. 단계별 연동 순서

### 1단계: 16개 즉시 등록 대상

레지스트리 초안의 `confirmed_official` 5개 소스를 기존 공통 수집기에 추가합니다. 공지 목록 또는 상품별 현황 페이지를 수집한 뒤 같은 호스트의 분배금 상세 링크만 증분 발견합니다. 티커·주당 분배금·지급기준일 또는 분배락일·지급일이 확인된 행만 상세 페이지 요약 JSON으로 승격합니다.

### 2단계: 7개 공식 URL 확정 대상

TIME·FOCUS·DAISHIN343·파워의 공식 도메인과 공지 상세 URL 패턴을 직접 확인합니다. URL이 확정되기 전에는 임의의 주소를 레지스트리에 넣지 않고 `manual_official_notice_pending` 상태를 유지합니다. URL 확정 후에는 각 운용사의 표·첨부 이미지·동적 페이지 형식에 맞춰 파서 유형을 지정합니다.

### 3단계: 원문·증거·게시 게이트

모든 신규 원문은 수집 시각·최종 URL·HTTP 상태·SHA-256·파서 버전과 함께 불변 저장합니다. 상품코드는 ETF 마스터의 6자리 티커와 일치해야 하며, 상품명만 일치하는 행은 자동 게시하지 않습니다. 공지에 분배락일이 없으면 지급기준일을 그대로 표시하고 분배락일을 역산하지 않습니다. 지급예정일은 실제 지급 완료일과 구분해 화면에 표시합니다.

## 5. 레지스트리 초안 파일

추가 소스 정의는 다음 파일에 작성했습니다.

`data/distributions/distribution_source_registry_remaining_23.json`

이 파일은 기존 52개 레지스트리와 병합할 수 있도록 동일한 `source_key`, `issuer`, `source_type`, `url`, `parser_name`, `fields`, `tickers`, `status` 구조를 사용합니다. `confirmed_official`만 자동 수집 대상으로 활성화하고, `discovery_required`는 검토 큐에만 남기는 것을 권장합니다.

## 6. 게시 가능 기준

| 조건 | 게시 처리 |
|---|---|
| 공식 원문·티커·주당 분배금 확인 | 지급 이력 후보 생성 |
| 공식 원문에 분배락일 확인 | 분배락일 표시 |
| 분배락일 없이 지급기준일 확인 | 지급기준일 표시, 분배락일은 `확인되지 않음` |
| 지급일이 공지됨 | 지급일 또는 지급예정일을 원문 표현대로 표시 |
| 정정 공지 존재 | 최신 정정 원문 우선, 이전 원문도 보존 |
| KIND만 존재하고 운용사 원문 없음 | 웹페이지 자동 게시 보류 |
| 공식 원문·티커 매칭 실패 | 게시 보류 및 검토 큐 등록 |
