# 배당형 ETF 상세 UX 및 분배금 업데이트 자동화 권고안

**대상:** ETF Campus ETF 상세 페이지  
**기준일:** 2026-08-15  
**목표:** 배당형 ETF에서 사용자가 필요한 분배금 정보를 즉시 이해하게 하되, 수익률의 데이터 품질을 과장하지 않고 공식 원천 기반 업데이트를 운영한다.

## 1. 현 카드에 대한 진단

현재 `투자 전 체크 지표` 카드는 순자산, 1일 거래대금, 실질 부담 비용, 기본 수익률 기준을 한 카드에서 제공한다. 모바일 화면에서는 카드의 하단 여백이 크고, `기본 수익률 기준 · 분배금 미포함`이 분배형 ETF 사용자에게는 가장 궁금한 ‘최근 얼마가 언제 지급되는가’를 답하지 못한다.

`분배금 미포함`은 정보로는 정확하지만 행동을 돕는 표현은 아니다. 배당형 ETF의 사용자는 금액, 분배락일, 지급일, 최근 분배의 연속성, 그리고 이 수익률에 분배금이 반영됐는지를 순서대로 확인한다. 따라서 수익률 설명을 유지하되, 분배금 자체를 별도의 핵심 행으로 승격해야 한다.

## 2. 권장 카드 구조

배당형 플래그가 있는 ETF에서만 현재 카드에 `분배금` 블록을 추가한다. 비배당형 ETF에는 기존 네 항목을 그대로 유지한다. 실제 값이 없거나 검증 중이면 수치를 추정하지 않고 상태와 다음 확인 시점을 표시한다.

| 영역 | 표시 항목 | 사용자 문구 예시 | 공개 조건 |
|---|---|---|---|
| 최근 분배금 | 최근 공식 공지의 주당 분배금 | `최근 분배금 37원` | 운용사 공식 공지 또는 KRX 일괄공시 |
| 일정 | 분배락일, 지급일 또는 지급예정일 | `분배락 7.30 · 지급예정 8.4` | 해당 날짜가 원문에 있는 경우 |
| 주기 | 최근 6회 관측 기반의 사실 요약 | `최근 6회 기준 월분배` | 동일 ETF의 일정 관측 횟수가 충분한 경우 |
| 커버리지 | 확인된 월 수와 최신 원천일 | `공식 공지 5회 확인 · 7월 업데이트` | 원장 집계값 |
| 수익률 기준 | PR, 분배금 반영 수익률(추정), 검증 TR의 품질 구분 | `현재 표는 시장가격 수익률(PR)` | 항상 표시 |

데스크톱에서는 분배금 블록을 투자 전 체크 카드의 비용·수익률 기준 아래에 가로 전체 폭으로 배치한다. 모바일에서는 순자산·거래대금과 비용·수익률 기준의 2열 그리드 아래에 분배금 블록을 한 행 전체 폭으로 두어 금액과 날짜가 줄바꿈 없이 읽히도록 한다.

```text
분배금                                                   공식 공지 확인
최근 분배금                                      37원
분배락 2026.07.30 · 지급예정 2026.08.04
최근 6회 기준 월분배 · 공식 공지 5회 확인

수익률 기준
시장가격 수익률(PR) · 분배금 미포함
[분배금 반영 수익률(추정) 보기]   [검증 TR은 원천 검증 중]
```

`최근 12개월 분배금`이나 `연환산 분배율`은 값의 유혹이 크지만, 커버리지가 완결되기 전에는 첫 화면의 핵심 지표로 쓰지 않는다. 대신 `최근 12개월 중 8개월 확인`처럼 범위를 먼저 표시하고, 충분한 월이 쌓였을 때만 상세 탭에서 합계와 연환산을 제공한다. 지급일이 미확정이면 ‘지급예정’이 아니라 ‘지급일 확인 중’으로 표시한다.

## 3. PR·추정 수익률·검증 TR의 위치

수익률 품질은 오른쪽 카드에서 설명하고, 실제 전환은 차트 바로 위에서 한다. 카드 안에서 PR·D2·D3를 세 개의 동등한 버튼으로 보이면 사용자가 추정 수익률을 검증 TR로 오해할 수 있다.

| 상태 | 카드의 설명 | 차트 동작 |
|---|---|---|
| PR | `시장가격 수익률(PR) · 분배금 미포함` | 기본 선택, 모든 ETF 제공 |
| D2 | `분배금 반영 수익률(추정) · 운용사 공지 기반` | 해당 기간만 선택 가능, 커버리지 배지 표시 |
| D3 | `검증 TR · KIND 대조 완료` | 검증된 기간만 선택 가능 |
| 보류 | `분배금 정보 수집 중` 또는 `출처 대조 필요` | PR만 제공, 비활성 버튼 대신 이유 노출 |

정보 아이콘은 데스크톱의 hover만으로 구현하지 않는다. 모바일에서는 탭하면 닫을 수 있는 짧은 바텀시트 또는 팝오버로 `세전 기준`, `재투자 가정`, `수집 범위`를 설명해야 한다.

## 4. 자동화 대상과 안전한 상태 전이

자동화는 판단이 필요한 업무가 아니라, 반복적인 공식 원천 수집·해시·파싱·대조·상태 생성으로 나눈다. 새 데이터는 곧바로 사용자 화면에 노출하지 않고 다음 단계를 통과한다.

```text
공식 URL 탐색/수집
  → 원문 불변 저장 및 SHA-256
  → 운용사별 표 파싱
  → 후보·증거·월별 커버리지 생성
  → 금액·일정 대조
  → D1 분배금 정보 또는 D2 추정 수익률 생성
  → 검증 TR 대조 대기
  → 정적 파일 게시
```

자동 실행은 `정상`, `검토 필요`, `차단`의 세 갈래로 종료한다. 정상은 기존 파서가 읽고 날짜·금액이 유효하며 기존 후보와 충돌하지 않는 경우다. 검토 필요는 새 표 구조, 새 ETF, 날짜 누락, 외부 대조 불일치가 있는 경우이며, 이때는 원문 링크와 행 위치가 포함된 검토 큐를 만든다. 차단은 원문 해시 오류, 금액 충돌, 파서 구조 오류이며 사용자가 보는 분배금·수익률을 변경하지 않는다.

## 5. 업데이트 주기와 운영 화면

운용사 공지는 분배락일 전후에 집중되므로, 평일 오전과 장 마감 후에 공식 공지 목록을 확인하는 두 번의 배치가 실용적이다. 매일 무조건 모든 ETF를 다시 처리하는 대신 122개 배당형 워치리스트와 최근 45일의 공지 대상만 우선 탐색한다. 월말에는 KODEX·RISE·TIGER의 일괄공시를 우선 수집하고, 분배락일 전후에는 개별 KIND 공시를 추가 대조한다.

운영자는 작은 상태 화면에서 `새 원문`, `파싱 성공`, `검토 필요`, `차단`, `게시 대기`만 보면 충분하다. 새 분배금 자체를 사람이 매번 입력하는 구조는 피하고, 예외 데이터만 원문 링크를 열어 확인하도록 한다.

## 6. 자동화 구현 선택지

| 선택지 | 동작 방식 | 장점 | 고려 사항 |
|---|---|---|---|
| 저장소 기반 예약 실행 | 현재 Python 표준 라이브러리 스크립트를 정해진 시각에 실행하고, 변경된 CSV·JSON을 검토용 변경 요청으로 생성 | 현재 정적 배포·원문 원장 구조를 거의 그대로 사용, 비용과 구현 난도가 낮음 | 원문 수집이 실패하거나 충돌하면 게시 전 검토가 필요 |
| Cloudflare 기반 예약 작업 | 수집·대조 로직을 TypeScript로 이식해 예약 작업이 D1에 후보·증거를 쓰고, 승인된 상태만 정적 데이터로 내보냄 | 앱 데이터·운영 상태를 한곳에서 관리, 향후 알림·관리 화면 확장이 쉬움 | 기존 Python 파서 이식과 D1 스키마·운영 화면 작업이 필요 |
| 혼합 운영 | Python이 원문·증거를 수집하고, 승인된 D1·D2·D3 상태만 Cloudflare 데이터 계층으로 게시 | 감사 가능한 원문 파이프라인과 빠른 서비스 반영을 함께 확보 | 두 계층의 배포 규칙과 실패 복구 절차를 명확히 정해야 함 |

현재 ETF Campus의 정적 CSV/JSON, Python 표준 라이브러리, 외부 DB 미사용 원칙에는 첫 번째 선택지가 가장 가볍다. 데이터 범위가 122개에서 더 커지고 운영자가 상태를 화면에서 직접 관리해야 할 때 두 번째 또는 세 번째 선택지를 검토한다.

## 7. 단계적 도입 순서

첫 단계에서는 상세 카드에 D1 분배금 블록과 품질 배지를 연결한다. 두 번째 단계에서는 공식 분배락일과 가격 이력이 있는 ETF만 D2를 활성화한다. 세 번째 단계에서 KIND 대조가 완료된 이벤트가 누적되면 검증 TR을 추가한다. 마지막으로 수집·파싱·대조를 예약 실행으로 옮기되, 처음에는 자동 게시가 아니라 검토용 변경 목록을 만들고, 일정 기간 오류율을 확인한 뒤 정상 건만 자동 게시한다.
