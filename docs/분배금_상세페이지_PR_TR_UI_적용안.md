# 배당형 ETF 상세 페이지: 분배금·PR·총수익률 적용안

작성일: 2026-08-16 (KST)  
작성자: Manus AI

## 1. 결론

첨부 화면의 구조는 유지하되, 배당형 ETF에는 **차트 오른쪽의 수익률 기준 전환**, **차트와 동일 기준으로 동기화되는 2행 기간 수익률 표**, **최근 분배금 정보를 보여 주는 요약 카드**를 하나의 경험으로 연결하는 방식을 권장한다.

기본값은 모든 ETF에서 현재와 같은 **가격 수익률(PR, 분배금 미포함)**이어야 한다. 사용자가 전환한 경우에만 분배금 반영 수익률을 표시하며, 이때 검증 수준에 따라 명칭을 엄격하게 구분해야 한다. 운용사 공식 공지 기반이지만 KIND 전체 대조 전이면 **`분배금 반영(추정)`**, 전체 검증 게이트를 통과한 경우에만 **`분배금 포함(TR)`**을 사용한다. 두 값을 같은 `TR`로 부르면 사용자가 검증 수준을 오해할 수 있다.

> **핵심 원칙:** 차트·헤드라인 수익률·하단 기간 수익률 표는 언제나 동일한 기준(PR / 분배금 반영 추정 / 검증 TR)과 동일한 시작·종료일을 사용한다. 하나만 바뀌거나, 분배금 데이터가 없는 기간을 0%로 표시해서는 안 된다.

| 사용 상황 | 화면상 명칭 | 제공 조건 | 표시 방식 |
|---|---|---|---|
| 기본 | 가격 수익률(PR) | 모든 ETF | 기본 선택, 기존 차트·기간 표 유지 |
| 공식 공지 기반 | 분배금 반영(추정) | 운용사 공식 분배금·분배락일 및 선택 기간의 가격 이력 확보 | 파란 `추정` 배지, 세전·분배락일 재투자 가정 명시 |
| 전체 검증 | 분배금 포함(TR) | KIND 대조·무분배 월·기업행동·가격 이력 검증 완료 | 초록 `검증 완료` 배지, 세전 재투자 가정 명시 |
| 미제공 | 분배금 데이터 준비 중 | 기간 커버리지 또는 원천 검증 미완료 | 값 대신 `—`, 짧은 제공 불가 사유 |

현재 데이터 기준으로 D2 추정 수익률은 **458730(TIGER 미국배당다우존스)**에만 일부 커버리지로 활성화되어 있으며, D3 검증 TR은 전 기간 게이트가 충족된 종목에만 향후 노출해야 한다. 따라서 UI는 지금부터 완성하되, 사용할 수 없는 기간은 의도적으로 비워 두는 설계가 필요하다.

## 2. 경쟁 서비스에서 가져올 원칙

justETF는 ETF 프로필에서 분배 정책·분배 빈도·최근 12개월 분배금·현재 분배율을 함께 제공하고, 성과 수치의 기본 기준이 분배금을 포함한 total performance임을 명시한다.[1] Morningstar는 상단 요약에 배당수익률·규모·보수를 배치하고, 차트에서 배당 관련 도구를 제공하며, 성과 표에서 ETF·동종·벤치마크를 여러 기간에 걸쳐 비교하게 한다.[2] K-ETF는 분배율을 별도 랭킹 기준으로 제공한다.[3]

ETF Campus는 이들보다 보수적으로, **PR을 기본값으로 유지하고 사용자가 전환했을 때만 분배금 반영 수익률을 보이는 방향**이 적합하다. 국내 배당형 ETF는 분배금 수준·주기·기준일이 상품마다 크게 다르고, 커버드콜 ETF의 높은 분배율은 가격 수익률과 별개로 해석해야 하기 때문이다.

| 벤치마크 관행 | ETF Campus의 채택안 | 이유 |
|---|---|---|
| 분배 정책·빈도·최근 분배금의 동시 제시 | 최근 주당 분배금·분배락일·지급일을 카드 최상단에 제공 | 투자자가 다음 일정과 현금흐름을 빠르게 확인 |
| 총수익률 정의의 명시 | 토글 옆에 `세전 · 분배락일 재투자 가정` 고정 고지 | PR·추정·TR 혼동 방지 |
| 기간별 성과 표 | 기존 PR 행 아래 분배금 반영 행을 추가 | 차트 전환 효과를 숫자로 즉시 비교 |
| 배당수익률의 별도 제공 | 최근 12개월 완전 데이터가 있는 경우에만 `최근 12개월 분배금`과 `최근 12개월 분배율` 제공 | 일부 월 데이터만으로 연환산 수익률을 과대 표시하는 문제 방지 |

## 3. 상세 화면의 권장 레이아웃

### 3.1 데스크톱

현재 화면의 좌측 차트와 우측 `투자 체크 지표`의 2열 구조를 유지한다. 다만 배당형 ETF에서는 우측 패널의 하단에 **`분배금 한눈에`** 블록을 추가한다. 이 블록은 수익률 토글과 별개의 정보가 아니라, 사용자가 왜 분배금 반영 수익률을 선택할 수 있는지를 설명하는 신뢰 근거다.

```text
┌──────────────────────────────────────┬───────────────────────────────┐
│ 기간 선택 / 차트 저장                 │ 투자 체크 지표                │
│ 2025.08.14 ~ 2026.08.14              │ 순자산 · 거래대금 · 비용      │
│ [가격 수익률(PR) | 분배금 반영(추정)] │ ───────────────────────────── │
│ 수익률 +00.00%   [추정]               │ 분배금 한눈에                 │
│                                      │ 최근 주당 분배금  103원      │
│                차트                  │ 분배락 2026.07.30            │
│                                      │ 지급 2026.08.04              │
│                                      │ [운용사 공지 기반] [이력 >]  │
└──────────────────────────────────────┴───────────────────────────────┘

가격 수익률(PR)     +3.06%   +9.63%   +1.02% …
분배금 반영(추정)      —        —      +1.25% …
```

### 3.2 모바일

모바일에서는 우측 패널을 차트 **바로 아래, 기간 수익률 표 바로 위**로 이동한다. 사용자가 토글을 누른 직후 분배금 근거를 확인할 수 있고, 가로 스크롤 표를 보기 전에 최근 분배금 맥락을 이해할 수 있다.

모바일 카드의 정보 우선순위는 다음과 같다.

| 우선순위 | 노출 항목 | 표기 예시 |
|---:|---|---|
| 1 | 최근 주당 분배금 | `최근 주당 분배금 103원` |
| 2 | 분배락일·지급일 | `분배락 2026.07.30 · 지급 2026.08.04` |
| 3 | 검증 상태 | `운용사 공지 기반` 또는 `검증 완료` |
| 4 | 보조 정보 | `최근 12개월 분배금`, `분배 주기`, `분배금 이력 12건` |

지급일이 원문에 없으면 `지급일 확인 중`, 기준일이 없으면 해당 항목을 숨긴다. 빈 값을 `0원`, `미지급`, 또는 추정 날짜로 바꾸면 안 된다.

## 4. 차트 수익률 기준 전환 설계

### 4.1 단일 스위치 대신 2개 선택지

현재의 토글은 간결하지만, `분배금 포함(TR)`이라는 문구가 D2 추정 수익률에도 쓰일 수 있어 검증 수준을 가린다. 차트 헤드라인 옆에 아래와 같은 **2분할 세그먼트 버튼**을 권장한다.

| 상태 | 버튼 구성 | 기본 선택 | 전환 후 헤드라인 |
|---|---|---|---|
| 비배당형 ETF | 노출하지 않음 | PR | `가격 수익률` |
| 배당형·D2 없음 | `가격 수익률(PR)` + 잠금 `분배금 반영` | PR | `가격 수익률` |
| 배당형·D2 가능 | `가격 수익률(PR)` / `분배금 반영(추정)` | PR | `분배금 반영 수익률` + 파란 `추정` 배지 |
| 배당형·D3 가능 | `가격 수익률(PR)` / `분배금 포함(TR)` | PR | `분배금 포함 수익률` + 초록 `검증 완료` 배지 |

선택지 아래에는 한 줄짜리 정의를 고정 표시한다.

> `분배금 반영(추정): 운용사 공식 공지 기준, 세전 분배금을 분배락일 종가에 재투자한 가정`

> `분배금 포함(TR): KIND 공시 대조와 전체 기간 검증 완료, 세전 분배금을 분배락일 종가에 재투자한 가정`

이 문구는 차트 이미지 저장 시에도 포함되어야 한다. 사용자가 공유한 이미지에서 수익률 기준을 잃지 않게 하기 위해서다.

### 4.2 전환 동작

1. 사용자가 `분배금 반영(추정)` 또는 `분배금 포함(TR)`을 선택한다.
2. 차트 라인, 헤드라인 수익률, 툴팁, 하단 기간 수익률 표의 기준을 동시에 변경한다.
3. 같은 기간이 전체 커버리지 안에 있으면 **기간 선택을 유지**한다.
4. 선택 기간이 커버리지 밖이면 수익률을 임의로 연장하지 않는다. 차트는 제공 가능한 최대 완전 기간으로 전환하고, `1년 기준은 아직 제공되지 않아 1개월 기준으로 표시합니다`라는 짧은 안내를 노출한다.
5. 하단 표에서는 커버리지 밖 기간을 `—`로 표시하며, 길게 누르거나 정보 아이콘을 누르면 `분배금 원천·가격 이력 커버리지 확인 중`을 보여 준다.

현재 구현처럼 D2 전환 시 무조건 `1M`으로 바꾸는 방식은 최소 수정으로는 가능하지만, 선택 기간이 바뀌었다는 사실을 사용자가 알아차리기 어렵다. 자동 변경이 필요하면 반드시 기간 버튼과 날짜 범위가 함께 바뀐다는 안내를 표시한다.

### 4.3 차트·툴팁 표기

| 위치 | PR | D2 추정 | D3 검증 TR |
|---|---|---|---|
| 헤드라인 | `가격 수익률` | `분배금 반영 수익률` + `추정` | `분배금 포함 수익률` + `검증 완료` |
| 차트 범례·이미지 저장 | `분배금 미포함(PR)` | `분배금 반영(추정)` | `분배금 포함(TR)` |
| 툴팁 금액 | 종가 | `분배금 반영 지수`와 해당일 분배금 | `총수익 지수`와 해당일 분배금 |
| 하단 보조 문구 | `분배금 미포함` | `운용사 공식 공지 기반 · N개월 완전 커버리지` | `KIND 검증 완료 · N개월 완전 커버리지` |

## 5. 하단 기간 수익률 표: 추가할 한 줄

첨부 화면의 가로 기간 표에 **기존 행을 보존하고 두 번째 행을 추가**한다. 기준 전환 상태가 바뀌면 행의 강조 위치만 바꾸며, 두 행을 동시에 지우거나 같은 값으로 복제하지 않는다.

```text
                 1D      1W      2W      1M      3M      6M      1Y      3Y      YTD
가격 수익률(PR)  +3.06%  +9.63%  +1.02%  -2.86%  -14.59% +40.06% +223.42% +283.57% +98.45%
분배금 반영(추정)  —       —       —      +0.18%    —       —       —       —       —
```

### 5.1 행 이름과 강조 규칙

| 현재 선택 기준 | 1행 | 2행 | 강조 방법 |
|---|---|---|---|
| PR | `가격 수익률(PR)` | `분배금 반영(추정)` 또는 `분배금 포함(TR)` | PR 행 이름·값을 진하게, 다른 행은 중간 명도 |
| D2 추정 | `가격 수익률(PR)` | `분배금 반영(추정)` | D2 행 이름 옆 파란 `추정` 배지와 진한 값 |
| D3 검증 | `가격 수익률(PR)` | `분배금 포함(TR)` | TR 행 이름 옆 초록 `검증 완료` 배지와 진한 값 |

`1D`, `1W`, `2W`처럼 해당 기간에 분배 이벤트가 없더라도, 완전한 분배금 이력과 가격 이력이 있으면 D2/D3 값은 PR과 같을 수 있다. 반대로 커버리지가 시작되기 전이거나 중간에 결손이 있으면 값이 같아 보여도 **`—` 처리**한다. 이는 ‘분배금이 0원’과 ‘검증되지 않음’을 구분하기 위해서다.

### 5.2 산출식과 동일 기준 보장

각 기간·각 기준의 수익률은 차트와 같은 시작일·종료일·시계열에서 계산한다.

```text
PR 수익률 = (종료일 종가 / 시작일 종가 - 1) × 100

D2 수익률 = (종료일 추정 분배금 반영 지수 / 시작일 추정 분배금 반영 지수 - 1) × 100

D3 TR 수익률 = (종료일 검증 TR 지수 / 시작일 검증 TR 지수 - 1) × 100
```

D2·D3의 분배금 반영 지수는 세전 현금분배금을 **검증된 분배락일의 시장가격 기준으로 재투자**한다고 가정한다. 투자자 개인의 세금, 거래 수수료, 실제 체결 시점은 반영하지 않는다.

### 5.3 표의 데이터 계약

기존 PR 수익률 CSV를 재사용해 D2/D3 숫자를 억지로 섞지 말고, 기준별 결과를 하나의 조회 모델로 정규화한다.

```ts
type ReturnBasis = "pr" | "estimated" | "tr";

type PeriodReturnCell = {
  period: "1d" | "1w" | "2w" | "1m" | "2m" | "3m" | "6m" | "12m" | "24m" | "36m" | "ytd" | "itd";
  value: number | null;
  available: boolean;
  reason?: string;
};

type ReturnMatrix = {
  ticker: string;
  asOfDate: string;
  rows: Array<{
    basis: ReturnBasis;
    label: string;
    quality: "pr" | "estimated" | "verified" | "unavailable";
    coverageStart?: string;
    coverageEnd?: string;
    cells: PeriodReturnCell[];
  }>;
};
```

PR 행은 모든 ETF에서 제공한다. D2·D3 행의 각 셀은 `etf_return_display_status.json`의 상태와 시작·종료일 커버리지를 먼저 판정한 뒤, 해당 시계열에서 계산한다. **선택된 차트의 API 응답과 하단 표가 서로 다른 기준일을 사용하지 않도록**, 동일한 `start`, `end`, `basis` 계산 함수를 공유해야 한다.

## 6. 최근 분배금 카드의 데이터 모델

현재 원장은 주당 분배금, 분배락일, 기준일, 지급일, 분배 유형, 원천 ID와 검증 상태를 이미 보유한다. 이를 상세 페이지가 매번 CSV에서 직접 찾지 않도록 빌드 단계에서 정적 요약 JSON을 만들 것을 권장한다.

```ts
type DistributionSummary = {
  ticker: string;
  isIncomeEtf: boolean;
  latest?: {
    amountKrw: number;
    exDate?: string;
    recordDate?: string;
    payDate?: string;
    type: "ordinary_cash" | string;
    status: "verified" | "partial" | "announced" | "conflict";
  };
  trailing12m?: {
    amountKrw: number;
    yieldPct?: number;
    complete: boolean;
  };
  frequency?: "monthly" | "quarterly" | "irregular" | "unknown";
  sourceLabel: "검증 완료" | "운용사 공식 공지 기반" | "공식 공지 확인 중" | "검증 보류";
  sourceUrl?: string;
  updatedAt: string;
};
```

| 원장 상태 | 카드 배지 | 차트 토글 | 기간 표의 2행 |
|---|---|---|---|
| `verified` + D3 가능 | 초록 `검증 완료` | TR 활성 | `분배금 포함(TR)` 값 표시 |
| `partial` + D2 가능 | 파란 `운용사 공지 기반` | D2 활성 | `분배금 반영(추정)` 값 표시 |
| `partial` + D2 불가 | 회색 `공식 공지 확인 중` | 비활성, 이유 표시 | 모두 `—` |
| `conflict` | 주황 `검증 보류` | 비활성 | 모두 `—`, 충돌 안내 |
| 이벤트 없음 | `최근 분배금 확인 중` | 비활성 | 행 자체를 숨기거나 한 개의 준비 중 셀만 표시 |

## 7. 구현 순서

| 우선순위 | 작업 | 완료 기준 |
|---:|---|---|
| 1 | `build_distribution_summary.py` 추가 | 종목별 최근 분배금·12개월 합계·상태가 정적 JSON으로 생성 |
| 2 | 상세 페이지 데이터 어댑터 추가 | 티커별 `DistributionSummary`와 `EtfReturnDisplayStatus`를 서버에서 주입 |
| 3 | `DistributionSummaryCard` 컴포넌트 구현 | 데스크톱 우측·모바일 차트 하단에 상태별 카드 노출 |
| 4 | 차트 토글을 세그먼트 버튼으로 정비 | D2를 TR로 부르지 않고, 선택 기간·커버리지 변화를 명확히 고지 |
| 5 | `ReturnMatrix` 생성 및 기간 표 2행 적용 | 차트·헤드라인·표가 같은 날짜·기준·수익률을 표시 |
| 6 | 테스트 보강 | PR 기본값, D2/D3 전환, 미커버리지 `—`, 충돌 차단, 모바일 가로 스크롤 검증 |

## 8. 수용 기준

1. 비배당형 ETF에는 분배금 토글·분배금 카드를 보이지 않는다.
2. 배당형 ETF는 PR을 기본값으로 표시한다.
3. D2가 활성화된 ETF는 `분배금 반영(추정)`으로만 노출하며 `TR`로 부르지 않는다.
4. D3 검증이 완료된 ETF만 `분배금 포함(TR)`으로 노출한다.
5. 토글을 전환하면 차트·헤드라인·툴팁·하단 기간 표가 동시에 같은 기준으로 바뀐다.
6. 기간 커버리지 밖의 D2/D3 값은 0%가 아니라 `—`와 사유로 표시한다.
7. 최근 분배금 카드에서 지급일·기준일이 비어 있으면 추정 값을 만들지 않고 `확인 중`으로 표기한다.
8. 모바일 360~430px에서 기간 표는 열 폭을 훼손하지 않고 가로 스크롤되며, 두 행의 라벨은 고정되거나 첫 열에서 식별 가능해야 한다.

## 9. 기준·한계 고지

- **기준:** PR은 시장가격 수익률, D2는 운용사 공식 공지 기반의 세전 분배금 재투자 추정 수익률, D3는 KIND 공시 대조 및 전체 검증을 통과한 세전 TR이다.
- **시점:** 현재 데이터 원장 기준일과 가격 스냅샷 기준일이 같은 일일 배치에서 갱신되는 구조를 전제로 한다.
- **가정:** 분배금은 검증된 분배락일의 시장가격으로 즉시 재투자한다고 가정하며, 개인별 세금·수수료·체결 오차는 반영하지 않는다.
- **원천 및 신뢰도:** 주당 분배금은 운용사 공식 공지, 분배락일은 KRX KIND 공시를 우선 원천으로 한다. D2는 추정값이고, D3만 검증 TR로 표시한다.

투자 참고용 정보이며, 개인 맞춤형 투자 조언이 아닙니다.
