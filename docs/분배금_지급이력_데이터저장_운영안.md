# 분배금 지급 이력: 데이터 저장·게시 운영안

작성일: 2026-08-16 (KST)  
상태: **상세 페이지 지급 이력 우선 방식 적용**

## 1. 현재 적용 구조

ETF Campus 상세 페이지의 차트와 기간 수익률은 모든 ETF에서 가격 수익률(PR)만 제공한다. 분배금은 총수익률을 계산하지 않고, 운용사 공식 공지에서 확인된 **주당 분배금·분배락일·지급일**을 보여 주는 지급 이력으로 제공한다.

| 계층 | 파일·테이블 | 역할 | 갱신 방식 |
|---|---|---|---|
| 원문 보관 | `data/distributions/raw/**` | 운용사 공지·KIND 공시 원문과 해시 | 원문 불변 추가 |
| 감사 원장 | `etf_distribution_event_candidates.csv` | 수집된 이벤트 후보와 원천·추출 상태 | 일일 수집·대조 |
| 정규 이벤트 | `etf_distribution_events.csv` | KIND 대조 등 정규화 이벤트 | 검증 단계에서 갱신 |
| 상세 페이지용 읽기 모델 | `etf_distribution_summaries.json` | 티커별 최신 1건·최근 3건·전체 12건 이력 | 원장에서 자동 재생성 |
| 가격 이력 D1 | `etf_prices` | PR 차트의 종가 이력 | 기존 일일 가격 적재 유지 |

## 2. 이번에 추가한 갱신 항목

`scripts/build_distribution_summaries.py`는 운용사 공식 공지 기반 후보 중 다음 조건을 동시에 갖춘 행만 티커별 JSON으로 변환한다.

- 6자리 티커
- 양수의 주당 현금 분배금
- 운용사 공지에 기록된 분배락일

지급일과 기준일은 있으면 표시하고, 없으면 `확인 중`으로만 표현한다. 값이 없는 날짜를 추정·보정하지 않는다. 이 요약은 티커별 최대 12건을 보존하며, 상세 페이지에서는 최신 3건을 먼저 보여 준다.

`run_daily_distribution_update.py`에는 `distribution_detail_summaries` 단계가 추가됐다. 따라서 일일 가격 스냅샷이 새로 확인된 실행에서는 분배금 원천 수집·후보 정리·KIND 대조 뒤에 지급 이력 JSON도 자동 갱신된다.

## 3. D1 데이터베이스 변경 필요 여부

### 3.1 현재: D1 변경 불필요

현재 사이트는 `output: "export"` 기반의 정적 배포이며, 상세 페이지는 빌드 시 생성된다. 지급 이력은 티커별 정적 JSON이 가장 단순하고 안전하다. 기존 D1의 `etf_prices`는 PR 차트만 담당하므로, **지급 이력 카드를 출시하기 위해 D1 테이블이나 내부 적재 API를 변경할 필요가 없다.**

| 이유 | 정적 JSON 방식의 효과 |
|---|---|
| 조회량 | 상세 페이지가 빌드 시 직접 데이터를 포함하므로 별도 API 요청이 없음 |
| 신뢰성 | 수집 원장과 게시 데이터가 같은 Git 커밋으로 추적됨 |
| 비용·복잡도 | D1 마이그레이션·서명 적재 API·인덱스 운영이 불필요 |
| 캐시 | 정적 배포 캐시와 일관되게 동작 |

### 3.2 향후: D1 확장이 필요한 경우

아래 기능이 필요해질 때만 D1에 분배금 이벤트 테이블을 추가한다.

- 전체 분배 이력의 서버 측 검색·정렬·필터링
- 여러 ETF의 지급일 캘린더와 대량 조회
- 정적 배포 뒤에도 즉시 공시 정정을 반영해야 하는 경우
- 이벤트별 원문 링크·감사 이력의 API 조회

그 시점에는 가격 테이블을 변경하지 않고 별도 테이블을 추가한다.

```sql
CREATE TABLE IF NOT EXISTS etf_distribution_events (
  event_id TEXT PRIMARY KEY,
  ticker TEXT NOT NULL,
  ex_date TEXT NOT NULL,
  record_date TEXT,
  pay_date TEXT,
  amount_krw INTEGER NOT NULL CHECK (amount_krw > 0),
  currency TEXT NOT NULL DEFAULT 'KRW',
  distribution_type TEXT NOT NULL,
  verification_status TEXT NOT NULL,
  source_owner TEXT NOT NULL,
  source_id TEXT NOT NULL,
  source_hash TEXT,
  announced_at TEXT,
  updated_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_distribution_ticker_ex_date
  ON etf_distribution_events (ticker, ex_date DESC);
CREATE INDEX IF NOT EXISTS idx_distribution_pay_date
  ON etf_distribution_events (pay_date, ticker);
```

D1 확장 시에는 가격 적재용 `ingest-prices`를 재사용하거나 범용화하지 않는다. 분배금 전용의 서명 검증 엔드포인트와 요청 재생 방지 테이블을 별도로 두고, 이벤트 키는 `ticker + ex_date + distribution_type + source_id`를 기준으로 관리한다. 정정·취소 공시는 기존 행을 삭제하지 않고 상태·원천 이력을 추가해야 한다.

## 4. 일일 게시 흐름

```text
공식 가격 스냅샷 갱신
  → 분배금 원천 수집
  → 후보·증거·KIND 대조
  → 지급 이력 요약 JSON 생성
  → 원장 검증·프론트엔드 테스트
  → data/distributions 변경분을 GitHub에 커밋
  → 정적 배포 갱신
```

현재 GitHub Actions 워크플로는 `data/distributions` 전체를 데이터 커밋 범위에 포함한다. 따라서 `etf_distribution_summaries.json`과 신규 원문 증거는 같은 일일 데이터 커밋에 함께 반영된다.

## 5. 사용자 화면 노출 규칙

- 지급 이력 카드는 정적 요약 JSON에 이벤트가 있는 ETF만 노출한다.
- 카드에는 `운용사 공식 공지 기반` 상태를 명시한다.
- 지급일이 없는 이벤트는 `지급일 확인 중`으로 표시한다.
- 주당 분배금, 분배락일, 지급일을 보여 주되, 예상 분배율·재투자 수익률·TR은 표시하지 않는다.
- KIND 대조가 완료된 이후에도 기본 화면의 문구는 원천 상태에 맞게 갱신할 수 있으나, TR 기능은 별도 검증 기준을 충족한 뒤 다시 검토한다.

## 6. 운영 확인 항목

| 주기 | 확인 항목 | 통과 기준 |
|---|---|---|
| 매일 자동 | 원문 수집·요약 JSON 생성 | 신규 가격 스냅샷이 있는 실행에서 성공 |
| 매일 자동 | 원장·후보 검증 | 충돌·파싱 오류 시 게시 중단 |
| 배포 전 자동 | 상세 페이지 린트·회귀 테스트 | PR 차트와 지급 이력 카드 테스트 통과 |
| 수시 수동 | 공휴일·운용사 공지 형식 변경 | 원천 수집 규칙과 표시 상태 점검 |

**기준:** 화면 수익률은 PR이며, 지급 이력은 주당 세전 현금분배금의 원천 공지 정보다. **원천:** 운용사 공식 공지와 KRX KIND 공시를 우선 사용한다. **한계:** KIND 대조와 지급일 확보 수준은 이벤트별로 다를 수 있다. 투자 참고용 정보이며, 개인 맞춤형 투자 조언이 아니다.
