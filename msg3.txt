이전 작업 결과를 전제로, 아래 작업을 **한 번에 순서대로** 수행하십시오. 목표는 `community/phase-3-preview-rc` Preview 환경에서 공개 Turnstile 설정 API가 비로그인 상태에서도 정상 동작하도록 최소 수정하고, 최신 커밋이 배포된 Preview만 검증하는 것입니다.

현재 401은 공개 Turnstile 설정 API가 커뮤니티 공통 인증 미들웨어에 의해 차단되는 문제로 강하게 추정됩니다. 이 추정의 근거는 다음과 같습니다.

- `/api/community/auth/config` 엔드포인트 자체는 공개 site key 및 `required` 상태를 제공해야 로그인 이전의 Turnstile 위젯이 렌더링될 수 있습니다.

- 실제 응답의 `AUTH_REQUIRED` 코드는 `functions/api/community/_middleware.js`의 인증 경계에서 생성됩니다.

- 설정 엔드포인트 구현 자체는 정상 구성 시 JSON 성공 응답 또는 구성 오류(503)를 반환하는 경로이므로, 현재 401은 설정 핸들러 이전의 미들웨어 차단으로 봐야 합니다.

## 2. 최소 보안 수정

`functions/api/community/_middleware.js`만 수정하여 **정확히 다음 경로의 ****`GET`**** 요청만** 세션 인증 없이 `config.js` 핸들러까지 통과하도록 하십시오.

```
/api/community/auth/config
```

구현 요구사항은 다음과 같습니다.

1. 메서드가 `GET`이고 pathname이 정확히 `/api/community/auth/config`인 경우에만 공개 접근을 허용합니다.

1. POST, PUT, PATCH, DELETE 요청에는 이 예외를 적용하지 않습니다.

1. `/api/community/auth/request-otp` 및 `/api/community/auth/verify-otp`의 기존 보안 처리, Origin/CSRF 처리, rate limit, CAPTCHA 검증을 변경하지 않습니다.

1. 게시물·댓글·수정·삭제·신고·탈퇴 API의 인증 요구를 변경하지 않습니다.

1. 공개 설정 응답에는 `required`와 공개 `siteKey` 외 Secret·SMTP 정보·내부 사용자 식별자·이메일·Auth UUID가 포함되지 않도록 유지합니다.

1. `COMMUNITY_ENVIRONMENT === "preview"` 환경에서 Turnstile 구성 불일치가 있으면 기존처럼 fail-closed(구성 오류)로 처리합니다.

경로 예외를 넓게 만들지 마십시오. 예를 들어 `/api/community/auth/*` 전체를 익명 허용하는 변경은 금지입니다.

## 3. 테스트 우선 보완

기존 Pages Functions 또는 커뮤니티 API 테스트 구조를 찾아 다음 보안 회귀 테스트를 추가하거나 기존 테스트를 보완하십시오.

1. **비로그인 GET `/api/community/auth/config`**은 미들웨어에서 `AUTH_REQUIRED` 401로 차단되지 않고 설정 핸들러에 도달합니다.

1. 올바른 Preview 환경 변수가 주어진 경우 응답은 HTTP 200이며, `required: true`와 공개 `siteKey`만 포함합니다.

1. 응답 JSON 문자열에 `TURNSTILE_SECRET_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, SMTP 관련 필드, 이메일, Auth UUID가 포함되지 않습니다.

1. 비로그인 사용자의 보호된 쓰기 API는 계속 401 또는 기존의 적절한 인증 오류를 반환합니다.

1. POST `/api/community/auth/config`은 공개 예외로 통과하지 않습니다.

테스트는 실제 Secret을 사용하지 말고 더미 환경값 또는 mock을 사용하십시오. 기존 테스트 파일의 스타일·도구를 재사용하십시오.

## 7. Preview 공개 API 재검증

```
curl.exe -sS -L -o NUL -w 'community final=%{url_effective} status=%{http_code}`n' 'https://community-phase-3-preview-rc.etf-campus.pages.dev/community'
curl.exe -sS -L -o NUL -w 'posts final=%{url_effective} status=%{http_code}`n' 'https://community-phase-3-preview-rc.etf-campus.pages.dev/api/community/posts'

```

성공 기준은 다음과 같습니다.

| 대상 | 성공 기준 |
| --- | --- |
| `/community` | 최종 HTTP 200 |
| `/api/community/posts` | 최종 HTTP 200 |
| `/api/community/auth/config` | 최종 HTTP 200, `AUTH_REQUIRED` 없음, 공개 site key 및 required 상태만 응답 |
| 응답 보안 | 응답 본문·헤더에 Secret, 이메일, Auth UUID, SMTP 정보, 내부 토큰 미노출 |
